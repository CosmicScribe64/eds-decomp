# Matching tricks catalog

The shared reference for techniques recorded across the EDS wiki. Recipes are grouped by the discrepancy they address; links preserve the original function, context, evidence and unsuccessful variants. This page consolidates knowledge rather than replacing the detailed unit pages.

**Verified** means the technique has a matching-source example. **Hint** means a documented compiler-only adjustment, including `FAKEMATCH` forms. **Partial** means it reproduces part of an instruction stream but the function remains nonmatching. **Behavior checked** means a finite experiment agreed on its stated fixtures. **Failed/Rejected** records unsuccessful or invalid attempts. **Historical/Hypothesis** identifies obsolete advice or an unproved interpretation. A technique that worked in one function can worsen another.

The 2026-09-30 audit covered all 110 unit pages, relevant named helpers, compiler/tool pages and sound notes. Matching examples, initialized compiler hints and failed variants are retained together; a verified technique does not mean every function mentioned in that entry is complete. Current enabled source and complete-unit bytes take precedence over stale status notes.

## Start with the discrepancy

| Observed difference | First things to inspect |
|---|---|
| `ldr` versus `ldrh`/`ldrb`, or `ldsh` versus `ldrh` | Field width, access expression, bitfield container, overlay size and signedness |
| Correct instructions, wrong registers | Separate initialized locals, declaration/assignment order, live ranges and guard scope; compute global-alloc priorities and trace reload rotation ([below](#register-allocation-priority-and-reload-rotation)) |
| A literal or temporary lands one register off | Reload round-robin (`last_spill_reg`): an extra or missing reload earlier in the function, a hidden live argument, integer-constant versus symbol tables |
| Correct sum, reversed `add` operands | Explicit derived offset and entry pointer; staged additions |
| Table/base loaded outside the loop | Constant pointer versus extern symbol, narrow inline helper, repeated access versus cached local |
| `bhi/bcc` versus `bgt/blt` | Promoted operand type, bitfield container, signed local or comparison cast |
| Wrong switch tree or jump-table length | Signed selector, real case labels, source order, explicit final case or empty case |
| Wrong shared tail or branch target | Per-case returns/increments, early-return direction, case order and repeated memory tests |
| Extra saved high register or stack spill | Lifetime of bases/indices, pointer scope, address escape, declaration order |
| DMA code differs | Exact volatile width and read/write order, stack fill-source width, initialized pointer lifetimes |
| Isolated score looks implausibly good | Check target address, function extraction, ABI, saved registers, literal pools and whole-unit bytes |

Prefer an ordinary C form first. Use initialized hints only when a documented compiler discrepancy remains. Accept a conversion after an exact whole-unit comparison, then verify the combined ROM at a held checkpoint. See [[decomp-workflow]], [[decomp-permuter]] and [[agent-tooling]].

## Use the catalog to speed up a batch

At the 2026-09-30 held checkpoint, 291 fallbacks remained: 261 had parked C and 30 lacked parked C drafts. (After workflow waves 1-2 on 2026-10-01: 1769/1976 functions in C, 66.91% of code bytes; see [[overview]].) They occupy 0x358D8 code bytes; 51 functions of at least 0x400 bytes account for 0x1C318 of those bytes. These are source-progress counts, not proof that the parked drafts are correct. Newly parked large reconstructions improve the reference inventory only. [[overview]], [[agent-tooling]]

1. Regenerate `build/decomp-queue/queue.json` while writers are held. Claim a source unit, then inspect its current compiled mismatch and the linked unit/sibling pages. The queue identifies matched-source siblings and batches up to eight functions per unit.
2. Reuse a matched sibling before retranslating an existing draft. Apply the relevant width, ABI, expression or scope recipe to related functions together; retain function-specific differences.
3. Compile a small variant grid in one Docker invocation. Record the candidate/source/compiler context and the exact remaining discrepancy. A syntax failure or malformed extraction is not matching evidence.
4. Time-box allocation searches. Start with a two- or three-minute focused permuter run; extend only if the candidate improves or new evidence changes the search. Keep at most two jobs, each with at most two workers, within the documented shared-host budget. Do not rerun an unchanged failed grid blindly. [[decomp-permuter]]
5. Review behavior/ABI and accept each source change only after a complete-unit byte match. Keep nonmatching drafts parked. Hold all source writers for combined ROM/report checkpoints; full builds need not run for each private candidate.
6. Update this catalog and the unit page when a new trick succeeds or a bounded family fails. Advance both metrics with sibling wins and larger-function streams: 85.27% of functions are in source, while the source counter covers 57.76% of code bytes (validated objdiff: 57.72%).

The existing Docker image supplies the compiler, disassembler, decompiler and search dependencies. Reuse prepared function contexts and run candidate loops inside Docker; avoid host installs and repeated container setup per variant. A C draft is a starting point; translation alone does not advance matching coverage. [[toolchain]], [[m2c]]

## Compiler, prologue, padding and pools

| Region | Verified configuration | Discriminating evidence / limit |
|---|---|---|
| Game Thumb | `old_agbcc -O2 -mthumb-interwork -fhex-asm` | 35-function survey; nine sampled functions only match old_agbcc. |
| Sound Thumb | `agbcc -O2 -mthumb-interwork -fhex-asm -fprologue-bugfix` | 12-function survey; six sampled functions discriminate newer agbcc, including `sub_0807E6E8`, which also needs the bugfix. Current driver has 28 exact C bodies with these flags. |
| AgbSram | `-O1 -mthumb-interwork`; either binary in the sampled routines | Six exact functions. Most fail at O2. |
| libgcc / libc | Existing agbcc archives, pinned member order | Byte-identical library members; do not recreate them with a different compiler. |
| ARM mixer | Preserve its assembly | Handwritten provenance remains a hypothesis; its unusual register interface is concrete. |

Sources: [[compiler-flags]], [[agbcc]], [[toolchain]], [[sound-driver]], [[sound-mixer]]. The flags survey's **51 functions** is a historical compiler experiment, not the current project function count.

**Verified discriminator:** for nonvolatile constant RMW or bit tests, old_agbcc tends to materialize the constant before loading memory, while newer agbcc loads first. Example forms are `x |= 4` and `if (p->f & 0x80)`. Volatile MMIO reads are load-first with both compilers and cannot discriminate them. Both binaries print `gcc 2.9-arm-000512`; the banner cannot discriminate them either. Old_agbcc rejects `-fprologue-bugfix`. Sources: [[compiler-flags]], [[agbcc]].

**Verified prologue discriminator:** plain newer agbcc can emit `push {lr}` in a branchy leaf, followed by a pop/bx return, where EDS has a bare `bx lr`. The sound driver's `sub_0807E6E8` only matches with `-fprologue-bugfix`. `-mthumb-interwork` is required for register-saving functions: void returns use `pop {r0}; bx r0`, value returns use `pop {r1}; bx r1`, and leaves use `bx lr`. High-register save/restore moves through low registers are ordinary compiler output. Do not change signatures to manufacture these forms. Sources: [[compiler-flags]], [[agbcc]].

**Resolved history:** early defaults selected newer agbcc for game code from a nondiscriminating leaf. Nine discriminating game examples (`sub_08000854`, `sub_080042D8`, `sub_0802C890`, `sub_0803A7F4`, `sub_0805FCF4`, `sub_08077A44`, `sub_08077A74`, `sub_0807B114`, `sub_0807D0A0`) resolved the default to old_agbcc. The current [[decomp-workflow]] records this resolution. The exact historical compiler boundary at `0x0807D3D0` was initially a hypothesis: the survey's last old-only routine was `0x0807D0A0` and first new-only routine `0x0807E3B0`. Using the current unit configuration is verified for the enabled sound C; the source-provenance boundary is a separate claim. Sources: [[compiler-flags]], [[agbcc]], [[decomp-workflow]].

**Failed / limited alternatives:** O1 changes game/sound strength reduction, loop reversal, and allocation; O2 is the verified configuration. O3 happened to agree with O2 in the sample, so that agreement does not establish O3 as the original setting. Flag toggles such as `-fcaller-saves`, `-fno-gcse`, `-fno-strength-reduce`, and `-fno-regmove` did not improve `sub_0807B114`. Normal calls are plain `bl`, with no evidence for `-mlong-calls`. Other middleware compiler islands remain a hypothesis and do not justify broad flag changes. Source: [[compiler-flags]].

**Verified padding:** append the compiler assembly's `.text` / `.align 2, 0` convention before assembly. Function starts and pools are four-byte aligned, with zero padding; the assembler's default Thumb filler can otherwise be `mov r8,r8` (`0x46C0`). `-fhex-asm` only changes printed numbers, not bytes. Sources: [[compiler-flags]], [[agbcc]].

**Verified normal codegen to recognize, not hand-emit:**

| Target pattern | Source / interpretation | Example / source |
|---|---|---|
| `add rD,rS,#0` | Normal low-register copy | [[compiler-flags]], [[decomp-workflow]] |
| `mov` plus `lsl` | Constant expressible as shifted eight-bit value | `0x04000000`: `0x80 << 19`; same sources |
| `mov` plus `neg` | Small negative int constant | `~0x10` as int/s32; a u16 `0xFFEF` instead uses a pool; same sources |
| Base literal + offset literal + add | Ordinary large struct field access | `sub_08077A44`, `sub_08026CC8`, `sub_0807D0A0`; [[compiler-flags]] |
| `mov #0xC4; lsl #1; add` | Small offset +0x188 | Plain struct field access; [[compiler-flags]] |
| Pool after unconditional branch inside body | Normal literal-pool placement | `sub_0807E9C8`, `sub_08001BC8`; [[compiler-flags]] |
| `bl` to internal label in a huge function | Compiler far branch | Keep ordinary C; [[decomp-workflow]] |
| `lsl #2; ldr table; add; ldr; mov pc` | Dense switch jump table | [[compiler-flags]], [[decomp-workflow]], [[m2c]] |

**Verified bitfield container effects:** the ARM compiler's `STRUCTURE_SIZE_BOUNDARY` is 32. A struct exactly four bytes can cause whole-word bitfield loads, while larger structs use byte/halfword loads plus shifts. Mixed u8/u16 containers also change widths. `sub_0802C890` and `sub_0803A7F4` are matched examples. The grid command's timer needs a **u32 container** for the ROM's signed comparisons; an apparently equivalent smaller container changes codegen. Sources: [[compiler-flags]], [[code-080150dc]].

**Verified narrowed values with wider locals:** `int fp = (u8)from;` rather than a u8 local fixed allocation in `sub_08017B04`. Location packing `(u8)player | ((u8)zone << 8)` gives the required byte narrowing and u16 argument form; when the callee takes u32, an enclosing u16 cast preserves the intended packed value. Plain `(zone << 8) | player` differed in the tested context. Source: [[code-08017314]].

**Verified arithmetic examples:**

- A signed-16 compare of register-held values can shift both left 16 and use a signed branch without an arithmetic shift back (`sub_0807B114`). Do not infer unsignedness only from the absence of `asr`.
- `% 64` on a provably nonnegative int is `asr #6; lsl #6; sub`, without sign correction (`sub_08026CC8`). A derived `(i * stride) >> 2` used as a u32-pointer index can generate `asr #2; lsl #2`.
- `s64 r = (s64)a * (s64)b; return r >> 8;` matches `sub_0807B4E0`; omitting the named 64-bit temporary changes registers.
- `--x == 0` for u16 yields decrement, halfword store, left shift 16, compare 0 (`sub_0807B0D0`). Introducing an extra u16 temporary can move narrowing relative to the store.

Source: [[compiler-flags]]. These patterns preserve the original arithmetic domains; they are not permission to change signed overflow behavior.

**Recorded local-width lever:** a u16 running counter can make the compiler reload constants from the pool at each use rather than preserve them as a loop invariant. This is a local-counter experiment from [[decomp-workflow]], not a rule that all counters should be narrowed; confirm that wrap/truncation and original loop bounds remain faithful.

**Verified SDK-specific pool side effect:** at O1, expressions using function-address differences such as `(u32)ReadSram - (u32)ReadSram_Core` can emit otherwise dead rodata pool entries. Their existence and placement are part of the AgbSram match. This is a documented SDK layout effect, not permission to introduce arbitrary new C data into game units. Source: [[compiler-flags]]; supporting destinations [[agb-sram]] and [[toolchain]].

## Access widths, signedness and layouts

- **Verified: whole-word card reads.** A card-word pointer cast or `*(u32 *)` followed by `<< 20 >> 20` preserves the ROM's word load. Direct array-member `.id` can become a halfword load. For an 11-bit table index multiplied by two, combine uses `<< 21 >> 20`. Examples: `sub_080193D4`, placement/list helpers and the command-card views. [[code-08007994]], [[code-0800fb10]], [[code-080184d8]]
- **Verified: byte flags alongside word views.** Use a larger byte-view struct for `+6`/`+0x91` mask tests and a separate four-byte card-word view for the same object. This gives `ldr` for IDs and `ldrb [base,#6]` for flags while retaining a shared address. [[code-0800ab08]], [[code-08011be0]], [[code-08007994]]
- **Verified: byte-mask versus bitfield access.** A plain `u8` mask produces `mov/and`; a bitfield can produce a shift/sign test. Choose the representation demonstrated by the ROM. The draw-card player flag needs a whole-byte `|= 1`, whereas some link flags need individual bitfield assignments. [[code-0800eaa8]], [[code-0801f454]], [[code-08021cc8]]
- **Verified: padded byte bitfield views.** A byte bitfield struct of exactly four bytes can be read with `ldr`. Padding it beyond four bytes permits the required `ldrb`. [[code-08009a68]]
- **Verified: bitfield container controls comparisons.** `u32 timer:7` produces signed `bgt/ble` in the command-banner families; the corresponding `u16` container produces unsigned branches. Other selectors deliberately require `u16 rows:4` or `u16 timer:7` to avoid a hoisted coordinate or to compare masked bits directly. [[code-08012c4c]], [[code-08013cdc]], [[code-080150dc]], [[code-080162c4]], [[code-0801ce68]]
- **Verified: mixed bitfield containers.** One byte can combine `u32 active:1` with `u8 timer:2` and `u8 frame:5`; the declared types affect extraction and decrement tests. [[code-08025108]]
- **Verified: straddling fields.** Preserve the actual declaration across bytes/words. The removed-zone mask spans `+0x0B/+0x0C`; selection state spans bits 26–33 using a `u16` container. Their assignments reproduce the original multi-byte surgery. [[code-08008a1c]], [[code-08020af4]]
- **Verified: container width can separate reused masks.** A `u16`/`u32` field at `gMain+0x4870` prevents a constant-one mask from being CSE'd with a later link flag; a `u8` field changes allocation. [[code-08020af4]]
- **Verified: signed loads versus signed comparisons.** Keep reel storage `u16` and cast at the comparison when the ROM loads unsigned; declaring storage `s16` instead produces `ldsh`. For a signed speed, `speed *= -1` retains `ldrsh; neg`, whereas `speed = -speed` drops the extension. [[code-08026124]]
- **Verified: narrow locals with wider promotions.** `int fp = (u8)from`, `u16 id`, or `u16 flags = x != 0` can preserve copies, masks and argument allocation that `u8`/`int` replacements lose. A signed `int end` supplies `bge/blt` even with a narrow counter. [[code-08017314]], [[code-08008a1c]], [[code-08009a68]], [[code-08021cc8]]
- **Verified: ARM struct rounding.** Agbcc rounds ordinary structs to four-byte boundaries (`STRUCTURE_SIZE_BOUNDARY` 32), in size **and alignment**. Flatten a genuine 0x12-byte message record rather than nesting a rounded sub-struct. A union containing a byte bitfield struct can also become four bytes and move subsequent fields. Use a separate view, or an explicitly checked packed/aligned representation where required. An array of 20-byte cell structs declared at `pad0[0x1726]` silently compiled at +0x1728; `sub_0806704C` matched with the array at the 4-aligned +0x1724 and the two flag bytes at cell offset +2/+3. [[shared-headers]], [[code-08021cc8]], [[code-08019554]], [[code-08041f9c]], [[code-0806704c]]
- **Verified: shared headers with local exceptions.** Map fields by compiled offset/bit position, keep canonical headers stable during a migration wave, and retain small documented local views when the ROM requires another access width. Compile size/offset assertions and field probes; recheck every including unit after a shared-header change. [[shared-headers]]

- **Verified.** Match the actual access width with a local view when canonical fields differ. Byte-bitfield overlays preserve shifted flag tests (`sub_0802D47C`, `sub_0802DBA8`); a byte view preserves the `ldrb` at `+0x1ACD` rather than a word-bitfield read (`sub_08033DAC`). Keep such views local and retain the same symbol with `asm("symbol")`. A tail view must account for actual offsets and trailing padding: replacing a misplaced padded view with the canonical `linkSkip` field recovered `sub_0803732C`. [[code-0802cae8]], [[code-0802db30]], [[code-08033dac]], [[code-0803732c]], [[code-08031bc8]]
- **Verified.** A four-byte packed entry struct is loaded as a word; use a whole `u32` read where the ROM does `ldr` followed by shifts. A card-word bitfield view with `.flag12` yields `lsl #19; lsr #31` (`sub_0803435C`). Separate bitfield stores for request byte `+0x491` reproduce its individual mask/OR writes (`sub_08042AB0`); a clear gives `mov #0x41; neg`. [[code-08029750]], [[code-08033dac]], [[code-08041f9c]]
- **Verified.** Bitfields and raw masks are not interchangeable for code generation. Viewer `active = 0` produces `mov #2; neg; and`, while raw `&= ~1` gives `#0xFE`; the large-struct single-bit store in `sub_08029750` also retains the ROM's negated mask. Zone flag/mark bitfields avoid folding `+6` into a literal and reproduce the temporary-mark clear in `sub_0803A9C8`. [[code-0802aac0]], [[code-08029750]], [[code-0803a654]]
- **Verified.** For the `+0x91` single-bit zone flags, bitfields can form a separate `zone + 0x91` and load once (`sub_08041DC4`). For `sub_0802D0E0`, write the raw byte access twice to preserve separate `&4` / `&8` tests. These are different target access patterns. Raw shifts on an `extern u8` produce `ldrb`; a bitfield struct can instead produce `ldr` (`sub_0803B924`'s position extraction). [[code-08040ebc]], [[code-0802cae8]], [[code-0803b670]]
- **Partial.** One RAM object with fields can reproduce address differences derived from a shared base: `sub_08030620`'s decoded scratch views explain `base-8`, `base-4`, and `base-0x164`, with bitfields crossing word boundaries producing u32/u16/u8 RMW accesses. This structure inference improves the draft but does not make that function match. Packed, two-byte-aligned unions and assertions are necessary for the new `sub_0804244C` / `sub_08042BE0` halfword views; otherwise this compiler rounds union size to four. Those state-machine bodies remain unverified drafts. [[code-0802fb64]], [[code-08041f9c]]

- **Verified.** Keep byte/halfword values in the type that reproduces the ROM's copies and masks. `u16 id = CARD_ID(word)` often preserves a register copy, avoids redundant parameter narrowing and keeps/hoists `0x7FF` (`sub_0802D30C`, `sub_0802D97C`, `sub_08033E44`, `sub_0803AA80`). Conversely, the selectors `sub_0803DFE4` / `sub_0803E8F8` need a `u32` extracted id followed by `CARD_TYPE((u16)id)` to put pointer/id in r1/r2 and retain the non-destructive mask form. [[code-0802cae8]], [[code-08033dac]], [[code-0803a654]], [[code-0803dd7c]]
- **Hint.** A redundant initialized `u16 copy = id`, used for a later number/type lookup while the original id is tested, reproduces an extra register move (`sub_0802B48C`, `sub_0802BA68`, `sub_0802BDF0`, `sub_0802BF38`, `sub_0802C334`). Mark the otherwise redundant copy FAKEMATCH. An assigned comparison temporary similarly changes loop base/mask allocation in `sub_0802F958`; it is assigned in the condition before use. Reusing a dead zone variable in `ret = zone = 1` keeps the result in r3 (`sub_0802BB40`, also documented in [[decomp-permuter]]). [[code-0802aac0]], [[code-0802bad0]], [[code-0802eb58]]
- **Verified.** `int player = (u8)pos; int zone = pos >> 8` preserves byte extraction while giving signed zone comparisons; `u8` locals give unsigned branches, and `pos & 0xFF` can introduce a pooled mask. `int tp = (u8)target` avoids saved-register copies caused by `u8 tp` (`sub_08031DA8`, `sub_080353A4`, `sub_0803C060`, `sub_0803C368`, `sub_0803C5A0`). If a byte local is needed for allocation, copy it to an `int` immediately before a signed comparison (`sub_08031C14`). [[code-0802aac0]], [[code-08031bc8]], [[code-08035198]], [[code-0803b670]]
- **Verified / Partial.** `int k` plus `k > hi || k < lo`, or `switch ((int)bitfield)`, preserves separate signed bounds. Unsigned conjunctions often become `sub; cmp; bhi`. The 21/22 type pair uses `cmp #22; bgt; cmp #21; blt` in `sub_0802CD28` and `sub_08041DC4`. For zone 5–10, `(u32)(zone-5) <= 5` deliberately selects the unsigned range form. Nested signed switches can reproduce 1–4 / 5–6 compare chains in the still-parked `sub_08034768`. [[code-0802db30]], [[code-0802cae8]], [[code-0802bad0]], [[code-08035198]], [[code-08040ebc]], [[code-08041f9c]], [[code-08033dac]]
- **Verified.** Raw signed bit tests such as `(s32)((u32)byte << 26) < 0` reproduce `lsl; cmp; bge` without hoisting an AND mask. The shift amount depends on the bit: flag bit 5 uses 26, bit 3 uses 28, card-word bit 12 uses 19. Do not infer signed semantics from a bit's informal name. [[code-08032cb0]], [[code-0802db30]], [[code-0802eb58]], [[code-0803b670]]
- **Verified.** Use unsigned shifts when the ROM zero-extends: `(u32)x << 20 >> 20` for a 12-bit id from a halfword (`sub_08036510`), versus pooled `&0xFFF`; signed `int` can select `asr`. `(u8)w << 8` produces `lsl #24; lsr #16`, while `&0xFF` can pool a mask. Byte-swapping with a `u16 ch` matches `sub_08029FC8`; `u32 ch` does not. [[code-080361d0]], [[code-0802fb64]], [[code-08029750]]
- **Verified.** A `u8` random bit has a separate QImode AND constant; `int` shares it with later player tests (`sub_08038C38`, `sub_0803B104`). A `u32 zero = (u8)(flags & 4)` removes an extra copy that a `u8` local introduces. A byte `skip` known to be zero after its guard can supply later zero stores (`sub_08037CD4`). [[code-080383f0]], [[code-0803a654]], [[code-08032cb0]], [[code-0803732c]]
- **Verified.** Narrow Boolean locals can select `neg; orr; lsr #31` instead of branches (`sub_0802FD90`). Explicit initialization and conditional reassignment (`flag=1; if(c){flag=0; if(x)flag=1;}`) also select this setcc form. Direct `return x > 0` can avoid the saved register introduced by a named result (`sub_0802F068`, `sub_0802F088`). An inline `TypeIs` helper with initialized result and conditional assignment retains a particular result copy in `sub_08032F20`. [[code-0802fb64]], [[code-08032cb0]], [[code-0802eb58]]
- **Verified.** `1 & ~flags` / `1 & ~(flags >> 1)` select `bic`; `!((byte >> 6)&1)` gives the shared-one BIC form in `sub_08033DAC`. For bit 5, a temporary before the call or `!((byte>>5)&1)` preserves the form in `sub_080327F4`. A scalar `int id > 0` gives `ble` where `u16 id` gives `beq` (`sub_080300D8`). [[code-0802bad0]], [[code-08033dac]], [[code-08031bc8]], [[code-0802fb64]]
- **Verified.** For helpers whose callers narrow results, preserve the original declared return width: `sub_0802D058` and `sub_0803DDAC` are `u16`. An `int` call result tested as `(u16)r == 0` produces `lsl; cmp` without `lsr` (`sub_0803D0B8`); the final `(u16)` return in `sub_08041F9C` retains `lsl/lsr #16`. An apparently unused `if (u16_call()!=0) return 1; return 1` preserves its result shift. Prototype width also determines argument narrowing (`sub_08038320`). These are disassembly-backed ABI recovery observations, not permission to change an existing ABI to improve a score. [[code-0802cae8]], [[code-0803c838]], [[code-0803dd7c]], [[code-0803732c]], [[code-08041f9c]]
- **Verified.** Preserve evidenced call arity even when an argument looks dead: `sub_0803CC18` and `sub_0800CCCC` take four arguments; the latter's fourth is spilled/reloaded across the previous call. Existing unprototyped `sub_08018DC8()` declarations permit the ROM's three- and four-argument call sites. Conversely, an incidental live r3 in generated `sub_0804244C` formatting output was not an extra argument; ROM inspection showed only buffer/format/name. [[code-0803c838]], [[code-0803b670]], [[code-0803732c]], [[code-080383f0]], [[code-08041f9c]]

- **Verified C: narrow at the original point of use.** An ARM register argument occupies a word even when only its low half is used. A word parameter followed by explicit `(u16)` narrowing can preserve behavior while changing prologue scheduling. `sub_080608BC`: `((b << 16) + 0x40000) >> 16` means `(b + 4) & 0xFFFF`, not `b + 0x40`; `sub_08060E2C`: word coordinates narrowed during index formation; `sub_08064984`: word column/tile inputs narrowed on entry, column retained at word width within the inner loop, then narrowed at the outer tail. **Compiler hints** remain in sub_080608BC and sub_08064984. [[code-0805f96c]], [[code-080609c4]], [[code-08063a28]].
- **Verified C: explicit order of narrow locals.** Word parameters followed by `u16 b = b0; u16 a = a0;` narrow the second before the first in `sub_08068E44`, `sub_08068EFC`, `sub_08069014`. Declaring both parameters `u16` narrows them in parameter order. [[code-08068180]].

## Register allocation priority and reload rotation

Workflow waves 1-2 (2026-10-01) matched about sixty functions whose last differences were register numbers. Most were resolved by reading agbcc's RTL dumps instead of guessing. `tools/wf.py dump` (see [[agent-tooling]]) or `old_agbcc -O2 -dl -dg -dL -dc` on a cut-down file produces them; the per-function `dump.sh` / `prio.py` / `reloads.py` scripts under `build/wf/<func>/` are worked examples.

**Global allocation (`global.c`).** Pseudos that live across basic blocks are allocated in priority order `floor_log2(refs) * refs / live_length`. The `.greg` dump lists "Registers to be allocated in sorted order"; the `.lreg` dump prints "Register N used X times across Y insns". Facts established by the matches:

- refs and live_length come from the **flow pass, before combine**. Insns that combine later deletes (zero/sign extensions of narrow locals) still count, and notes and labels do not. A pseudo set twice counts each loop insn twice (`sub_0803C254`: i at 4*20/216 = 0.3704 beat ref at 3*15/122 = 0.3689 until `u8` locals added combinable insns). [[code-0803b670]]
- Equal priorities (after integer truncation) go to the **lower pseudo number**, i.e. the earlier-created value: `u16 angle, scale; scale = sa >> 16; angle = sa;` put angle in r8 in `sub_08076714`; its twin needed `u32 scale` because `attr2 << 1` broke the tie. [[code-08076144]]
- A pseudo with a `REG_EQUAL`/`REG_EQUIV` constant has its live length **doubled** by `update_equiv_regs` (`sub_080516D8`). [[code-08050a70]]
- A pseudo born at function entry has the longest live range and the lowest priority. It gets no register, and reload rematerializes its constant at each use. `u16 *tab = gUnk_08622AB4;` as the first local reproduced the per-iteration table reload of `sub_0800CD68` / `sub_0800CC18`; a block-local `int mask = 0xFF` did the same for `sub_080657F8`, and a `sel` pointer for `sub_080536D4`. [[code-0800c894]], [[code-08064af0]], [[code-08052b78]]
- Levers that change refs: one fewer use (`goto end;` to a single `return flags;`, `sub_080044E4`); one more use with no code (`asm("" : : "r"(color))`, FAKEMATCH, `sub_08005860`); a no-op self-store `count += 0` (FAKEMATCH, `sub_080516D8`). Levers that change live length: a separate early return instead of an `&&` term (`sub_0802BBDC`); `s16 f = (s8)PLAYER_RAW(ctx)` adding deletable sign extensions (`sub_08033AEC`); OR operand order in packed arguments (`(u8)w828 | ((u8)w82C << 8)` in `sub_08051DF4`, player first in `sub_08035E0C`). [[code-080044e4]], [[code-08005500]], [[code-0802bad0]], [[code-08032cb0]], [[code-08051a9c]], [[code-08035198]]

**Local allocation (`local-alloc.c`).** Quantities that live inside one block are allocated there. A value used in two blocks becomes a global pseudo instead, which can free the local registers: one function-scope `u16 *c` (`sub_0803DEB8`) or `u8 *pp` (`sub_08070F18`, `sub_0806F934`) shared by two arms. With exactly three local quantities, agbcc's sort compares quantity numbers rather than `qty_order` entries, which can give a pointer r0 (`sub_08070F18`). Block-local temporaries per subtraction let local-alloc tie the shift, the result and the difference to one register (`sub_0807B9D4`). [[code-0803dd7c]], [[code-0807093c]], [[code-0806ed44]], [[code-0807b6b8]]

**Reload rotation (`reload1.c`).** Reload registers (spilled pseudos, constants folded into `(plus reg const)`, `(subreg (mem:QI))` operands of an AND) come from the function's spill-register set, handed out **round-robin** from `last_spill_reg` and skipping registers that hold a live pseudo at that insn. One extra or missing reload anywhere shifts every later choice. Evidence and fixes:

- An extra reload on purpose: a constant in a variable whose store needs a reload (`h = 0x20`, `sub_080280D0`); an HImode-shortened mask (`(u16)CARD_STATS(id) & 0x1FF`, `sub_0805664C`); a hoisted-then-spilled table base (`names` in `sub_0802A09C`, `oy`/`ox` in `sub_08053770`, the count pointer in `sub_080649D8`). [[code-08027580]], [[code-08055eb0]], [[code-08029750]], [[code-08052b78]], [[code-08063a28]]
- Integer-constant tables keep a `const_int` inside the add, so reload loads them; extern arrays give a SYMBOL_REF pseudo placed by the allocators (`sub_0807D1F4`, `sub_0805DF34`). [[code-0807c7c8]], [[code-0805d58c]]
- A hidden live value occupies a spill register: `sub_0803EE6C`'s real second parameter, live in r1 and passed on to a callee, moved every later reload. A missing parameter is a candidate whenever a reload temporary is one register off. [[code-0803edc4]]
- The spill set itself can differ: a constant-1 pseudo live in r2 forced r3 into `sub_08017FF4`'s set until the zone pointer was computed from `player & 1` afresh, which made CSE create one long-lived, spilled constant pseudo. [[code-08017314]]
- When the target skips a free register, keep that register busy with an empty pair `asm("" : "=r"(busy)); ... asm("" : : "r"(busy));` around the insn, with `busy` bound to the register (FAKEMATCH; `sub_0806DBB0`, `sub_08070F18`, `sub_0806F934`). [[code-0806d51c]], [[code-0807093c]], [[code-0806ed44]]
- **Reload inheritance** can reuse a register that still holds a spilled constant; an empty clobber placed before the earlier block breaks it (`asm volatile("" ::: "r7")` in `sub_08032D10`). [[code-08032cb0]]
- To confirm a rotation theory cheaply, insert a probe such as `asm("" :: "l"(0x55))` in one branch and watch which later reload moves (`sub_0802A09C`).

### Exact DMA initializer: retain the original base after its iterator dies

`sub_0807D3D0`, **0x148**, had three hoisted pointer registers swapped (nine differing bytes). Reordering declarations, pins, and pointer forms had failed. The successful form initializes voice/state/buffer, walks a separate iterator, then consumes the **original voice base** after the loop:

```c
voice = gUnk_030053AC;
state = &gUnk_0300540C;
buffer = gUnk_03005414;
{
    struct SoundPcmVoice *iter = voice;
    i = 6;
    do {
        iter->flags = 0;
        iter->sampleId = 0;
        iter++;
    } while (--i != 0);
}
/* Keep initialized voice base live; emits no instructions. */
asm volatile ("" : : "r"(voice));
*(u32 *)state = 0;
*(u32 *)&state->previousPosition = 0;
```

The input creates no writes or instructions, but extends that base's lifetime through the reset loop and reproduces all three original pointer registers. Source: [[sound-driver]].

### Exact SE allocator: preserve distinct first and second requests

`sub_0807E3D8`, **0x17C**, retains separate signed `request` and later `id`, a cursor locally bound to r3, a separate shifted slot-mask value, and five documented empty constraints:

```c
register struct SoundTrack *track asm("r3");
request = p->pendingSe;
if (request < 0) return;
effect = &gUnk_08087FD0[request & 0xFFF];
metadata = *(const s32 *)&effect->priority;
asm volatile ("" : : "r"(effect), "r"(request));
/* ... derive priority/slots, variant, map ... */
track = &p->seTracks[5];
asm volatile ("" : "+r"(variant));
/* ... priority scan ... */
id = p->pendingSe;
asm volatile ("" : : "r"(id));
id &= 0xFFF;
/* ... reverse six-slot allocation ... */
map--;
asm volatile ("" : : "r"(id));
track--;
/* ... overlap loop, flags update ... */
p->flags = (p->flags & 0xFFFB) | 0x40;

```

The placements keep the first request through metadata loading, variant through cursor setup, and the second signed request before masking, during allocation, and through final flag writes. ## Sound decoder layout repairs and validation


The SE and BGM track views are **0x18 bytes**; their channel-output view is eight bytes. Source-local static assertions verify sizes and field offsets. For SE +0x0A, use a two-byte union exposing both a packed u16 and the flag/volume bytes. The packed inner byte struct plus packed, aligned(2) outer union avoids the old compiler rounding this union to four bytes. Commands 0xA0–0xEF operate on the full halfword: the earlier byte-only draft dropped the high volume byte. This is a substantive behavior correction, not a register trick. Source: [[sound-driver]].

For BGM, preserve halfword resets of instrument/volume at +2/+3 and vibrato phase/depth at +0x0E/+0x0F; signed `(s8)operand << 5` for note offsets; and a wide extended-duration temporary. The raw m2c u8 duration truncated high bits. A PCM note change writes only the low halfword of `stepAndFraction`, retaining the mixer fraction; PCM start writes the full word. Command 0xF0 on PCM tracks writes output +0x0B/+0x0C, reaching the next output's volume/dirty bytes. For track 9 these aliases reach the saved song-pointer high byte and last-track-pointer low byte. The typed draft uses a real frame view with byte aliases across these members. A bounds-safe ten-element-array rewrite would change the original behavior. Source: [[sound-driver]] and directly reviewed disabled local draft.

Raw m2c `pointer += 0x18` needs scrutiny: once typed as a 0x18-byte track pointer, the faithful advance is `pointer++`. Similar scaling fixes apply to eight-byte output pointers. Width/layout repair must precede register permutation. Source: [[sound-driver]], [[m2c]].
