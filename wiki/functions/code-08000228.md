# code_08000228: dialogue scene module

Unit `code_08000228` (`0x08000228`–`0x08001363`, Thumb, `old_agbcc -O2`). It holds the dialogue ("Bustup") scene code: character-name lookup, the Mode-4 scene loaders, the text-box state, the per-frame `$`-code text processor and the cursor sparkle. Source: `src/code_08000228.c`.

## Text control codes (from `0x08000C54`, verified from disassembly)

Tab and newline (`\t`, `\n`) are skipped. `$$` is not an escape and leaves the pointer on the second `$`. The codes are:

| Code | Effect |
|---|---|
| `$Q nn` | insert the full duelist name `nn` (2 digits via `sub_08079F10`), colour 4 |
| `$q nn` | insert the short duelist name, colour 5 |
| `$i nnnn` | insert the card name: id → `0x08623DF4[id & 0x7FF]` (id ≥ 2000: `[id-2000]+1`), then the 0x40-byte name table at `0x0822C720`. Colour 3. `0xFFFF` gives entry 0. |
| `$b nn` | set the speaker (`sub_08079ED4`, max 39), `gMain+0x4859 += 4` |
| `$c` | wait (state -1), unless auto-advance |
| `$h` / `$k` | clear / set flag `+0x9A6` |
| `$n` | newline |
| `$p` | flip the page, reset the cursor, and redraw the box |
| `$rX` | colour X (`0`-`9`, `a`-`f`) |

Characters are 1 byte, or 2 bytes when `gSaveData+4` bit 7 (Shift-JIS) is set. They're drawn by `sub_08079E50(glyph, x, y, vram, colour, 14, 12, 240, 8)`. A line wraps when `sub_08079F40(str, col, 30)` returns 0. A leading space or `.` at the start of a line is dropped.

## Shared headers

This unit uses `include/main.h` for the gMain (`0x03000040`) layout instead of a local `struct Main`, which
was removed. The canonical field at `+0x40E` is `vblankFlags` (it was `unk40E` in the local view). The other
fields the unit touches (`seqIndex1` `+0x4859`, `flag4884_3`/`speaker` `+0x4884`, `dialogueIndex` `+0x4886`)
already had the canonical names and types. The duplicate local `extern` was removed, and the `gMain` alias is
kept (`#define gMain gUnk_03000040`). No local views are needed, because no field's declared type or bitfield
split differs from the canonical header and the unit references no duel structures (`duel.h` and `duel_ui.h`
are not needed). `struct Duelist` here is the unrelated duelist-name table entry, not `struct DuelCard`.

## Matching notes

- `sub_08000994`: `if ((timer = tbl[idx++]) == 0)`. Only the assignment-as-condition form reproduces the target, which zero-extends the stored value with an AND against the 0xFFFF constant already held in a register.
- `sub_080011F0`: `gUnk_02013DE0.flag136E = gMain.bit3` schedules wrong. Writing `u8 *flag = &...flag136E; *flag = gMain.bit3;` matches, because the destination address is computed first.
- Historical `sub_08000AC8` (matched in wave 2, see below): the target's `mov r3,#0; orr r3,byte` and `mov r1,#3; mul` only appear with a zero-valued local ORed into the y argument and a local `gap = 3` multiplier. Those locals are probably real source variables, but that's a hypothesis. What's left is an r7/r8 swap and a no-op `add r4,#0`.
- `sub_08000C54` (not matching): the layout only comes out as `switch (state) { default: if (*p == 0) goto finished; break; case 2: … case 3: … }`, with the end-of-text block last. Both glyph buffers have to be function-scope locals, name buffer first. In case 2, `u8 i = *idx;` must come before `name = tb->name`. `$i` needs the name pointer taken before the call.

## Text processor match (2026-10-01)

`sub_08000C54` matches all 0x59C bytes and the full unit. The match uses fixed ROM views for the reverse-ID and name tables. The decoded name index stays full-width until it is explicitly narrowed for the 64-byte name offset, and the control-code byte and plain-glyph pointer stay in r1. The glyph pointer is assigned separately in both branches. In the two-byte path, the first source byte is staged in a local before the terminator value is set to zero, which preserves all byte reads and writes and removes the extra pointer copy.

The `$h` case needs one empty read/write constraint on its initialized script base and 0x9A6 offset, with the offset bound to r2. The base needs no binding, and the `$k` case needs no hints. The final source has three initialized bindings (code byte, glyph pointer, flag offset), one empty constraint, and no uninitialized scaffolds or dead branches. Removing any remaining binding changes the code, and changing the constraint to input-only or to one output fails the match. The glyph pointer is assigned on both paths before use, and the staged byte and terminator have real data uses. Existing helper signatures are unchanged.

Evidence: `build/bigguns-lead2/dialogue_*.py`, `sub_08000C54/solo-clean/`, and the full-ROM run in `build/lead-pass16/` (checkpoint 26). Earlier text-processor near-miss notes are superseded.

Historical (the cursor function matched in wave 2; the final source calls the unprototyped `sub_0807B6B8` with exactly the 12 and 8 arguments the ROM prepares, and the callee's 13th stack read is still unexplained): the unmatched cursor function needs further ABI review. Its ROM calls to `sub_0807B6B8` explicitly prepare 12 arguments on the history path and 8 on the fallback path, while the callee reads 13 (the list pointer at entry-SP+0x20). `sub_0807A320` dereferences that list pointer even for layer 0. Do not invent missing arguments or assume they are unused. The original stack and caller contract is still unknown.

### `sub_08000AC8` (0x18C, start score 72; ordinary C)

- The parked draft was stale against the now unprototyped `sub_0807B6B8()`: `s8 x, y` added sign extensions and a `u16 d` added an `lsl/lsr #16` pair. What matched: `int x, y` assigned through `(u8)(...)` casts, and `s32 d = (i + 1) * gap - 30;` as its own statement (inlined, fold reassociates it to `head + 30 - ...`).
- `int off = 0` and `u8 gap = 3` stay variables. The history call passes `hist.y + off`, which combine turns into the target's `mov r3,#0; orr`. The fallback does `y += off;`; that plus has no in-block LOG_LINKS, so it survives as the no-op `add r4,#0` once reload substitutes the REG_EQUIV constant 0 (with a `u8 y` the zero_extend let combine make it an ior).
- r7/r8 swap (script base vs `&sparkleHead` at `0x02013DE0+0x9E8`): both had 13 refs and the head pointer won r7 on its shorter live length (288 vs 292). Passing the list argument as the member `gUnk_02013DE0.unkAA8` instead of the separate symbol `gUnk_02014888` (same address) lets CSE relate the constant to the base register, which gives the base a 14th ref and r7.
- Failed: a goto loop without loop notes (score 179, nothing hoisted), `do { } while (0)` around x/y (143, loop.c hoists the table instead), `register ... asm("r7")` on the base (r7 is the Thumb frame pointer and is eliminated to sp).
