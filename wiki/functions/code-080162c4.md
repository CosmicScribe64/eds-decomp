# Unit code_080162C4

`0x080162C4`–`0x08017313`, Thumb, `old_agbcc -O2`. Source: `src/code_080162C4.c`.
Duel "script command" handlers, dispatched like those in [[code-08012c4c]] and [[code-08010bdc]]. Each reads its operands from the command block `gDuelCmd`, runs a small state machine on `step` (+0x80A) and `timer` (+0x80C bits 5–11), and clears `running` when it finishes.

Unit status: `unit bytes MATCH`, 17/17 functions in C (verified with `tools/check.py code_080162C4`).

## Shared headers

This unit uses the shared headers instead of local definitions:

- `main.h`: `struct Main` / `gMain` (still aliased as `gMain` by a local `#define`).
- `duel.h`: `struct DuelPlayer` / `gDuelPlayers[2]` and `struct DuelState` / `gDuel`.
- `duel_ui.h`: `struct DuelCmd` / `gDuelCmd` and `struct DuelScreen` / `gDuelScreen`.

Five local struct definitions (`Main`, `DuelCmd`, `DuelPlayer`, `Duel`, `DuelScreen`) were removed. Field accesses were remapped to the canonical names by offset: `lp` to `lifePoints`, `count3` to `deckCount`, `count5` to `fusionCount`, `list7C4` to `deck`, `listA44` to `fusionDeck`, `unk1B12_0/1/2` to `flag1B12_0`/`linkSkip`/`phase1B12`, `unk0_2` to `flag0_2`, `unk4` to `scroll`, `unk80C` to `cursorX`, `unk810` to `cursorY`, and `unk85C` to `cb85C` (with a function-pointer cast; the `#if 0` drafts were updated too). `DUEL_FROM_PLAYERS` now casts to `struct DuelState *`.

Local views kept:

- `struct DuelStateUnk1ACCView` / `gUnk_020192E0_lo asm("gDuel")`: used only by `DuelCmd_SetFieldBackground`. It writes `+0x1ACC` as a `u8:4` bitfield (`unk1ACC_0`); `duel.h` declares that word as `u32 unk1ACC_0:15`, which makes agbcc emit `ldrh`/`strh` instead of the ROM's `ldrb`/`strb`. Everything else in the unit uses the canonical `u32`-container bitfields (`step`, `busy`, `timer`) and matches directly.

## Data

- `gDuelCmd` command block: `step` (+0x80A, `u8:7`), `timer` (+0x80C bits 5–11, **`u32` bitfield container**), `running` (+0x80C bit 13), `savedCount3[2]` (+0x818), `savedCount5[2]` (+0x81C), `savedList7C4[2][80]` (+0x820), `savedListA44[2][80]` (+0xAA0).
- `gDuelPlayers[2]` per-player state (0xD64): +0x0 LP, +0x3 `count3`, +0x5 `count5`, +0x7C4 `list7C4[80]`, +0xA44 `listA44[80]`.
- `gDuel` +0x1B12: bit 0, bit 1, bits 2–4 (`unk1B12_2`).
- `gDuelScreen` duel screen state: bit 0 `fast`, bit 2, +0x4, +0x808 bit 3 `busy`, +0x80C/+0x810 cursor position (hypothesis), +0x85C.

## Matching tricks

- **Same symbol for related constants (`DuelCmd_ResetDuelState`).** The ROM computes the `unk1B12` byte address as `0x02019AA8 + 0x134A`, reusing the `list7C4` base register. That only happens if every access goes through the `gDuelPlayers` symbol. Using `gDuel.players[...]` or `gDuel.unk1B12_2` loads a second, unrelated literal. The C uses `DUEL_FROM_PLAYERS` (= `(struct Duel *)((u8 *)gDuelPlayers - 4)`) for the flag write.
- The `timer` bitfield must stay in a `u32` container: signed compares (`bgt`/`ble`) depend on it. See [[code-08012c4c]].
- `DuelCmd_EnterPhase` (asm): only register allocation differs. The `0x80C` offset constant goes to r2/r0 in cases 0 and 1, where the ROM uses r3.

## Banner-fade follow-up (2026-09-30)

The `DuelCmd_EnterPhase` draft reproduces exactly **0x1D0 bytes**, with six differing operand bytes. The case-zero timer offset uses r2 and its loaded packed halfword uses r3; ROM uses r3 and r2 respectively. The case-one initial timer offset uses r0 where ROM uses r3. All later bytes match.

Private grids tested 26 lossless step/blend type variants, 13 timer-pointer views with initialized offsets, 33 conventional inline timer-reader/writer boundaries, 25 initialized packed-word clear variants, and five valid halfword/word bitfield-container views. None improved the original six bytes; no variant was installed. A two-minute, single-worker strict-branch-target permuter reached 11,198 iterations with 465 compilation failures and no better output. Failures are not matching evidence. Every semantic candidate preserved the original ABI, field width, blend MMIO writes, fast-forward increments and state transitions.

Evidence: `build/codex-continue/banner-fade-{types,timer-view,access-helpers,packed-word,container-view}/results.json`, `banner-fade-types/best.diff`, and `banner-fade-permuter.log`. This records a bounded unsuccessful attempt, with **zero coverage change**; the original assembly remains enabled and this unit stays **16/17 C**.

## Completed banner fade and unit (2026-10-01)

`DuelCmd_EnterPhase` now matches all 0x1D0 bytes; the whole unit is **17/17 C**, 0x1050 bytes. This supersedes the prior six-byte near miss. The case-zero timer clear uses a +0x80C bitfield view, an initialized offset bound to r3, and an initialized RMW pointer bound to r1. One empty read/write constraint retains the offset; initialize the pointer from the command base, then add the offset in a separate assignment. That staging selects the original ADD operand order and also resolves case one's allocation without changing that case. The halfword clear preserves every non-timer bit.

The second pointer constraint was unnecessary and removed. Tests removing either binding or the remaining offset constraint fail the match. No base binding, value clobber, uninitialized scaffold or changed ABI is present. Evidence: `build/bigguns-lead2/banner_{hints,pointer,finish,minimize}.py`, `DuelCmd_EnterPhase/solo-clean/`; the full-ROM check in `build/lead-pass17/` is exact.
