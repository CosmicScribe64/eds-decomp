# Unit code_08019554

`0x08019554`–`0x0801A7B3`, Thumb, `old_agbcc -O2`. Source: `src/code_08019554.c`.
Searches of a player's graveyard / deck / hand / fusion deck by card number, many one-line wrappers that queue a
duel event through `sub_0801EC58` (`DuelCmd_Push`, [[code-0801e260]]; bit 15 of the event id = player 1), LP-change
helpers, the card-draw routine, and small OBJ drawing helpers. Related: [[code-08017314]], [[code-08007994]] (deck
lists), [[code-08008a1c]].

Unit status: `unit bytes MATCH`, 24/25 functions in C; only `sub_0801A32C` remains `INCLUDE_ASM`. Verified with `tools/check.py code_08019554`.

This unit uses the shared headers: `main.h` (`struct Main`, `gUnk_03000040`), `duel.h` (`struct DuelCard`,
`DuelPlayer`, `DuelState`; `gUnk_020192E0`, `gUnk_020192E4`) and `duel_ui.h` (`gUnk_0201CFB0` /
`struct DuelScreen`). Local views are kept where the canonical field differs:

- `struct DuelCard17`: canonical `DuelCard` puts the drawn-card flag at bit 20, but this unit's ROM tests
  bit 17 (`sub_080199E0`).
- `struct DuelFlagBytes`: canonical `DuelState` exposes `+0x1B12` as the `phase1B12:3` bitfield, but the
  ROM tests that byte as a raw `0x1C` mask.

## Matching tricks

- **Card-number switch with a range case**: `if (no == 1910) … else if (no >= 1910 && no <= 1912)` folds into an unsigned range test; the ROM's `cmp; blt; cmp; bgt` comes from `switch (no) { case 1910: …; case 1911: case 1912: … }` (`0x0801A238`). The helper there is a `static inline`; `switch ((int)CARD_TYPE(id))` gives the signed `blt/ble` tree.
- **Constant kept in a register for a table index**: `u16 no = 1434; sub_080086CC(p, no); … ((const u16 *)0x08623DF4)[no]` (`0x08019980`). When the constant is loaded *after* the other argument, write `sub_08008524(1 - player, no = 1045)` (`0x08019894`).
- Location packing `(u8)(loc & 0xF) | (u8)((loc >> 8) & 0xF) << 4` (the `u8` casts decide which `0xF` constant register is used).
- OR chains get reassociated: `A | C | (t << 31) | id` compiles with `C | (t << 31)` first; splitting into statements (`u32 ev = A | C; ev |= t << 31; ev | id`) keeps the ROM order (`0x080199E0`). `((player & 1) << 31) | 0x38600000 | (id & 0xFFFF)` matched `0x08019CF0` (explicit `& 0xFFFF` survives because it is in a different basic block from the bitfield extract).
- `y *= scale; y /= 16;` (two statements) for the ROM's signed-divide register use (`0x0801A1B8`).
- A union containing a `u8` bitfield struct is 4-byte aligned (bitfield structs round up to 4), which shifted a field from +0x1B12 to +0x1B14. Use a separate byte-view struct and cast instead.
- Byte-mask tests of fields far into a struct should be written as struct members (the ROM adds the symbol and offset from two literals); `((u8 *)&sym)[0x1B12]` folds into one literal.
- `0x0801A32C`'s row loop looks like a `goto` loop in the ROM (no loop-invariant hoisting; hypothesis, the goto form got closer but not to a match); `sub_0801A1B8` takes a third, unused argument (callers pass -1).
- Remaining decoded list-search near misses (drafts parked in `#if 0` above `INCLUDE_ASM`):
  - Historical `0x0801A130` blocker, now resolved: the `0xD64*(player&1)` product landed in r0 instead of the ROM's r1, because the hand pointer was one variable assigned twice and so conflicted with `offset`. A fresh hand pseudo born as `offset + base` fixes it; see [Hand search match](#hand-search-match-2026-10-01).
  - Historical `0x0801A010` blocker, now resolved: the original direct-field draft CSE'd the loop-tail `deckCount` test with the pre-loop load and kept the player base in r9. The ordinary-C inline reader below reproduces the ROM's reloads.
  - Historical `0x08019E0C` blocker, now resolved: the direct-field draft hoisted the loop-invariant `CardNumberToId(no)` table address. Narrow inline card readers in both loops retain the ROM's complete in-loop lookups; the earlier non-inline/ternary helper attempts remained unsuccessful.

## Hand search match (2026-10-01)

`sub_0801A130` matches all `0x68` bytes in ordinary C. The ROM computes `muls r1, r0`, so the product goes into
the register that held `0xD64` and `offset` lives in r1. The hand pointer then reuses r1 and the base temporary
takes r0. The hand pointer has to be a fresh pseudo, born as `offset + base`, with the base in its own temporary:

    u8 *hands = players + 0x684;
    u32 *hand = (u32 *)(offset + (u32)hands);

`offset` dies at that add, so it no longer conflicts with `hand`. Writing `offset + base` in that order prints the
add as `adds r1, r1, r0`. The earlier draft assigned one `hand` variable twice (`players + 0x684`, then
`+= offset`). That made one pseudo that was live alongside `offset`, so global allocation gave `hand` r1 and pushed
`offset` to r0. Failed variants (permuter and by hand): a plain `for` over `PLAYER(player).hand[i]` (score 34), an
inline address expression (51), `register u32 offset asm("r1")` (50), `offset = 0xD64; offset *= (player & 1)`
(73), and a named `stride` local (22).

The C was byte-identical for a while before it could be applied. `check.py --diff` printed
`size: built 0x66 vs target 0x68 (-2 bytes)`: the target size in `config/functions.tsv` runs to the next function
and so includes the `.align 2, 0` pad after the final `bx r1`, while agbcc's `.size` stops at the code. `wf.py`
added 4 × |delta| to the score, so the score stayed at 8 and `apply` refused. The matched `sub_0801A09C` showed the
same line. `check.py` now ignores a shortfall that is only zero alignment padding up to a 4-byte boundary (target
and built bytes both zero). After that fix, `wf.py apply` installed the function and the unit reports
`25/25 functions match; unit bytes MATCH (built 0x1260 vs target 0x1260)`. Enabled C is 24/25. Notes:
`build/wf/sub_0801A130/NOTES.md`.
