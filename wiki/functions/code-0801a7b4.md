# Unit code_0801A7B4

The unit covers `0x0801A7B4`–`0x0801BCFB` (Thumb, `old_agbcc -O2`), and its source is `src/code_0801A7B4.c`.
It holds empty debug stubs (including the compiled-out debug printf), the step sequences that enter and leave a duel from
the campaign, trunk helpers, and the start-of-day **calendar event** dispatcher with the opponent's pre-duel dialogue.
Related: [[code-08019554]], [[program-flow]], [[ram-map]] (`gMain` at `0x03000040`, save mirror at `0x02011C20`).

Unit status: `unit bytes MATCH`, **24/24** functions in C (verified with `tools/check.py code_0801A7B4`).

## Shared headers

The unit includes `include/main.h` (struct `Main`, `gUnk_03000040`) and `include/duel.h`
(struct `DuelPlayer`, `DuelState`; `gUnk_020192E0`, `gUnk_020192E4`). Its own definitions of
`struct Main`, `struct DuelPlayerHead` and `struct DuelFlagBytes` were removed and the globals
are the canonical externs; field accesses were renamed to the canonical names (`unk40E` is now
`vblankFlags`, `unk414` is `vblankCallback`, `calendarEvent` is `opponent`, `eventFlags` is
`events`, `step` is `step488A`, `unk4889` is `score`, `unk4888_4` is `counter4888`, and
`unk1B12_5` is `linkError`).

Local views kept (no header change):

- `struct MainFlags0801A7B4` + `extern … gMainFlags asm("gUnk_03000040")`, used only by
  `sub_0801AE2C` and `sub_0801B75C`. main.h declares `+0x4888` as `unk4888_0:4`, but the unit
  reads and writes bits 1 and 2–3 as separate bitfields (`unk4888_1:1`, `unk4888_2:2`), and that
  different bitfield split generates different code. All other fields there use canonical names.
- `struct DuelFlagByte` / `DUEL_FLAGS_1B12`: duel.h splits `+0x1B12` into 1/1/3/1/2-bit
  fields, but the unit masks the raw byte (`& 0x20`), so it needs a byte view.

## Data layout

- `gMain` (`0x03000040`): +0x40E u16, +0x414 u32, +0x4857 `seqIndexCampaign`, +0x4858 `seqState0`, +0x4859 `seqIndex1`, +0x485A/+0x485B, +0x485E frame counter, +0x4870 bit 0 and bits 1–5 = **opponent / calendar event** index, +0x487C u32 event flag being handled, +0x4888 bitfields (bit 1, bits 2–3, bits 4–5), +0x4889, +0x488A u16 bitfields: bits 0–3 duel variant, bits 4–11 sub-step.
- Save mirror (`0x02011C20`): +0x08 trunk `{count:10, …}` per card ID (4 bytes), +0x20D0 `records[32]` `{wins:11, losses:11, draws:10}` per opponent, +0x2150 u16 day counter (hypothesis), +0x2158 u16 last opponent (hypothesis), +0x215E/+0x2160 u16 reset on Dec 31, +0x2164 bit 0.
- `0x02017FB0` dialogue state: u32 bitfield at +0x304.
- `0x08081A6C` holds 60 card numbers, and `0x08623DF4` is the card number to ID table (numbers ≥ 2000 give ID + 1).

## Matching tricks

- **Returns**: `if (fade()) { …; return 1; } return 0;` versus `if (!fade()) return 0;` swaps the block order. For big dispatchers, put `return 0;` in each branch (the ROM cross-jumps the identical tails) and keep a single `return 1` at the very end (`0x0801AE2C`, `0x0801B75C`).
- **Prototype disagreements**: `sub_08001AE4` is `u32` here; the one call site that narrows the result uses `(u16)sub_08001AE4()`. `sub_08076F9C` (Random) is `int` (signed `% 5` compiles to `__modsi3`); unsigned sites write `(u32)Random() % 60` or `% 5u`.
- In `do { u32 r = Random() % 60; id = f(tbl[r]); } while (…)`, the named temporary stops the table address from being hoisted out of the loop (`0x0801B6D4`).
- Single-bit tests: u8 bitfields give `mov #mask; and`, u32 bitfields give `lsl #n; bge/blt` (`0x02017FB0` +0x304 is a u32 bitfield word).
- `if (d.month == 12 && d.day == 31)` on the date bitfields folds into the ROM's single masked compare `(w & 0x1FF000) == 0x1FC000`.
- `wins + losses + draws == 0` gives the `cmn` compare; read the fields straight from `gSave.records[opp]` (a pointer local merges the loads into one `ldr`).
- A `(u8)` byte view struct is needed next to the bitfield view for the `+0x1B12` flag byte (mask test vs bitfield clear), see [[code-08019554]].
- **Constant-0 store scheduling** (`sub_0801A7B4`): writing a plain `= 0` lets the scheduler hoist the `movs r0,#0` above the preceding `strb`; writing `player & ~player` (always 0) keeps it after, matching the ROM.
