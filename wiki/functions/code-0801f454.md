# Unit code_0801F454

`0x0801F454`–`0x08020AF3`, Thumb, `old_agbcc -O2`. Source: `src/code_0801F454.c`.
Duel driver helpers: the duel command queue runner, the link-side command runner, the duel setup that clears every duel work area, the handler of duel phase 1 (entry 1 of the phase table `0x08198F80`, see [[program-flow]]), and the 20-byte "action" entry lists in `0x02017A40`. Related: [[code-08021cc8]] (link messages), [[code-0801e260]] (`DuelCmd_Push` = `DuelCmd_Push`, the command dispatcher `DuelCmd_Dispatch`), [[code-08013cdc]] (command block).

Unit status: **13/15 functions in C**, `unit bytes MATCH` (verified with `tools/dr python3 tools/check.py code_0801F454`, 0x16A0 bytes).

> [!warning] Contradiction: the unit is now 15/15
> The count above (13/15) predates later matches. `src/code_0801F454.c` has no `INCLUDE_ASM` left (checked 2026-10-02), so all
> 15 functions are in matching C. The decompilation reached 100% at commit `d77fcef` ([[overview]]). Resolved in favour of
> the source. Text below that calls a function nonmatching, parked or `INCLUDE_ASM` is history. Some of the later matches
> are recorded only in git (`git log`) and not yet written up here.

The unit now uses the shared canonical headers `include/main.h`, `include/duel.h` and `include/duel_ui.h`
(the latter includes `duel.h`) instead of its own definitions: `struct Main`, `struct DuelState`,
`struct DuelZone`, `struct DuelCmd` and `struct DuelScreen` (plus the `gMain`, `gDuel`,
`gDuelZones`, `gDuelCmd`, `gDuelScreen` externs) were deleted. Two unit-local views had to stay
(see [[#Local views]]).

## Data

- `0x020185C0` command block ([[code-08013cdc]], canonical `struct DuelCmd` in `duel_ui.h`): `+0x008` `struct DuelCmdEntry queue[256]` (8 bytes each), `+0x808` queue count, `+0x80A` step (bits 0–6), `+0x80C` timer (bits 5–11), `+0x80D` bit 5 running.
- `0x02017FB0` link state: `+0x200`, `+0x202` ack wait timer; `+0x307` bit 0 remote command running, bit 1 ack received, bit 3; `+0x484` received command (8 bytes), `+0x48C` step.
- `0x020192E0`: `+0x1B12` bit 1 link-skip (this GBA mirrors the partner), bit 5 link error, bits 6–7 set at setup; `+0x1B20` phase-1 step; `+0x1B40` queue step.
- `0x02017A40`: two lists of 20-byte action entries. `+0x00` u16 card, `+0x02` u16 bitfields (bit 0 flag, bits 1–3 kind, 4–9, 10–15), `+0x04` bits 0–4 flags, `+0x06`/`+0x08` u16 (low byte = player, hypothesis). > [!warning] Contradiction: [[code-08011be0]] describes entries from `+0x258` with the count at `+0x3C0`; here list B starts at `+0x280` (count `+0x3C0`) and list A at `+0x000` (count `+0x3C4`). Both address forms appear in matched code, so the 0x258 view is probably `listB[count - 2]` or a different list (open).
- `gMain+0x488A` bits 0–3: campaign parameter used by `SetupStartFieldCard` (hypothesis: duel/stage number).

## Local views

- **`struct DuelStateUnit`** (`extern struct DuelStateUnit gUnk_020192E0u asm("gDuel")`): `duel.h`'s
  `struct DuelState` is only documented up to `+0x1B20`, but this unit also reads/writes `cmdStep` at
  `+0x1B40`. The view embeds the canonical `struct DuelState` and adds that tail byte. It must be the only
  symbol referenced by `DuelCmdQueue_Run`: referring to both `gDuel` and the `asm`-aliased name makes
  agbcc emit two literal-pool entries and the function grows by 4 bytes. Other functions (`Duel_Setup`,
  `DuelPhase_Opening`, `Chain_Add`) use the canonical `gDuel` directly.
- **`struct DuelZoneUnit`**: `duel.h`'s `struct DuelZone.card` is a `struct DuelCard`; reading its 12-bit
  `id` makes agbcc emit a halfword load, whereas the ROM loads the whole `u32` card word and masks it
  (`card << 20 >> 20`). Kept unit-local (raw `u32 card`, bit 1 named `faceUp`) for `Chain_GetResponseCommands` only.

## Matching tricks

- **`0x020192E0+0x1B12` as `u8` bitfields.** A `|= 0x20` on a plain byte loads the base into `r0`. The bitfield `linkError = 1` matches. Bits 6–7 are one 2-bit field set to 3. Casting the address to a bitfield struct folds the offset into one literal. A union with a bitfield struct pads the union to 4 bytes (ARM struct rounding) and shifts every later field.
- **Constant-address tables:** `CardNumberToId` in `0x0801F81C` (this copy has no `& 0x7FF` for numbers < 2000) and `CARD_NUMBER` in `0x0801FA48`/`0x0801FD68` must use `((const u16 *)0x0862xxxx)` for the ROM's register order.
- **`0x0801FD68`:** `player &= 1;` as a statement before computing `gDuelZones + (zone * 0x94 + player * 0xD64)`. The case bodies are in source order 11, 5, 0.
- **`0x0801FA90`:** extract the fields of the packed word with explicit masks (`(a & 0x1E00000) >> 21`), not a bitfield union. Flip bit 31 with `if (a & 0x80000000) a &= 0x7FFFFFFF; else a |= 0x80000000;` so that the `0x80000000` constant is built before the test.
- **`0x0801F97C`:** each case ends in `x++; return 0;`, and the second ternary is written `!(flag) ? 0x8061 : 0x61`.
- **`0x0801FCA8`:** subtype cases 2, 3 and 4 in a switch emit the ROM's signed `cmp #4; bgt; cmp #2; bge` checks. A combined range condition becomes a subtraction and unsigned comparison; separate `if` statements instead compare with 1. An explicitly commented empty memory barrier after the subtype switch preserves the ROM's `e->card` reload before the card-number switch. The barrier emits no instructions or memory writes. The complete 0xC0-byte function and complete unit match.
- **Resolved `0x0801FE54`:** form a step-field pointer before its load, keep separate `u32 step` / `u32 copy`, then put one empty initialized `+r` constraint on `step` after `copy = step`. Switch on `copy` and store `*p = step + 1` in the shared tail. This FAKEMATCH emits no instructions; it prevents case-value folding while keeping the original loaded byte live in r1. The step-0 negative guard breaks before the shared update; timer `<= 59` increments and breaks, otherwise jumps to it. All register bindings, base constraints and copy inputs were removed. The 0x4C function and complete 0x16A0 unit match; check log is `build/codex-continue/step-unit-check.log`.

> The former draft folded the step into constants or reloaded it. The separate pointer/copy and single initialized value constraint resolve that diagnosis. The two larger routines remain assembly-backed; the check's 15/15 byte matches include those fallbacks.
