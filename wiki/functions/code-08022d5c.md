## Data and matching

- `0x02017FB0`: received halfwords at +0/+2/+4/+6/+8; converted command and arguments at +0x484/+0x486/+0x488/+0x48A.
- Command arguments can hold a packed card word across two halfwords. Its bit 12 is the player/owner bit; conversion uses `1 - player`.
- Commands 0x30/0x31 exchange the first two arguments; 0x31 also swaps bytes of the third argument. Commands 0x82–0x84 invert the low byte of both first arguments; 0x85/0x86 invert the second and conditionally the first.
- Command 4 converts results 0/1 and sets link +0x306 bit 5.
- Use a `u32` bitfield container for link flags at +0x304, and explicitly truncate the low byte before shifting for the byte swap. Together these recover the original register allocation.
- Two separate stack card-word temporaries produce the original 8-byte frame. Explicit pointers to them recover the address scheduling before the bitfield updates.

## Receive dispatcher

Reads `SIOCNT`, seeds the receive buffer with 0xF000, and calls `sub_080722B0`.
A nonzero `0x030049D0+0x522` takes the error path. No received packet returns 0;
valid packets return 1. Receiving 0xEE00 stops or fades the BGM (`sub_08077BCC`),
sets duel +0x1B12 bit 5, and returns 0. An unknown packet or the SIO error flag
also sends 0xEE00 first.

List headers encode count in the low byte and sender's player in the high byte.
The receiver uses `1 - player`, inverts each card's bit 12, and updates counts
at `0x020192E4 + player*0xD64 + 2/3/4/5` for the first four lists. Graveyard,
fusion and banished reception also call `sub_080611AC`. Each sends the corresponding
0xF031–0xF035 acknowledgement. Hand/deck/grave completion sets +0x305 bits 5/6/7;
fusion and banished **both set +0x306 bit 0**. The banished handler **does not write
the banished count** in the original ROM.

Action records are 0x14 bytes: player at +2 bit 0, kind at +3 bits 2–7,
references at +6/+8. The packet 0xF051 converts low reference bytes for kinds
5–8, 16–17, 20–21, 25–27, 29–30; kind 15 inverts the entire second reference;
13/14 swap its bytes. Kind 19 reads and stores the same values (no effective
change). Packet 0xF059 omits kinds 20/21 and exchanges references for kind 19.

The initial draft differed in stack spills, pointer/constant hoisting and shared
store/return branches. Typed field views, common-base aliases, source-pointer
declaration order and the FAKEMATCH constraints below resolved these differences.

## Receive-dispatcher matching work

- The survey's `adds #152` versus `#120` and `subs #26` versus `adds #194`
  decode nested-switch table words as instructions. They are shifted handler
  addresses, not evidence of incorrect RAM offsets. The audited link/action/duel
  field offsets agree with the target.
- Corrected operation order from the parked draft: F006 clears link bit 6 before
  `sub_080617F4`; F092 sets link +0x308 bit 3 before clearing +0x306 bit 6;
  F051 converts reference +0x4C2 before +0x4C4. F003 reads a payload byte.
- F051 kind 19 really loads two halfwords and writes both unchanged. An empty
  `asm` constraint, marked FAKEMATCH, preserves these otherwise-eliminated accesses.
- Replaced raw action masks and reference casts with typed field views. Also
  expressed overlapping action/link addresses through their common base, allowing
  the compiler to recover the target's relative address calculations.
- List locals must be `int`, not `s16`, because `s16` adds truncations absent from
  the ROM. Extract player and count before computing `1 - player`.
- Explicit per-case success returns and a shared surrender-selection label recover
  shared tails. A direct no-packet `return 0` fixes the graveyard-loop initial
  comparison. Duplicating the initial error-handler body, marked FAKEMATCH, fixes
  the deck-loop comparison; the compiler merges the duplicate error tail.
- The decisive list-loop change is declaring `const struct CardWord *src` before
  the destination pointer, with destinations expressed through `ReceivePlayer`.
  This naturally puts the counter in r8, preserves the twin r4/r5 pointer
  increments and recovers the 4-byte frame. Hard-binding the counter, raw byte
  destination arithmetic, and alternate loop forms regressed those results.
- Additional marked FAKEMATCHes retain the seed constant/address scheduling,
  F051 kind-19 reload/store registers, F059 player register, F0B1 packed argument
  registers, and F057 destination-before-zero scheduling. All asm bodies are empty;
  no handwritten instructions are used.
- Two bounded permuter searches were started and stopped after manual improvements
  superseded them; no permuter output was applied. Scalar type/declaration-order
  sweeps and comparison barriers did not solve the final comparison; duplicated
  error handling did. Final acceptance used whole-unit byte equality, with both
  functions active in C and no behavioral fixture suite.
