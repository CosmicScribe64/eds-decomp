# Unit code_0802408C

`0x0802408C`–`0x08025107`, Thumb, `old_agbcc -O2`. Source: `src/code_0802408C.c`.

Unit status: `unit bytes MATCH`, 27/27 functions in C (verified with `tools/check.py code_0802408C`).

The unit has two halves:
- `0x0802408C`–`0x080243CC` and `0x08024440`: the duel screen object at `0x0201CFB0`. They cover the field scroll, the field cursor, VRAM tile uploads, and the request/dispatch of the five card animations. `DuelAnim_MoveCard(id, &from, &to)` is the card-move animation used by the duel command handlers in [[code-0800fb10]] and elsewhere.
- `0x080246A8`–`0x08025054`: a self-contained screen built on the overlay work area `0x02015280`. It throws up to 8 tokens, which bounce and land with a result face, then waits `0x140` frames. Hypothesis: the coin toss / dice roll screen (per-token results come from bits of `0x02017A30+6`).

## Data

### Duel screen `0x0201CFB0` (`struct DuelScreen` in the C)
- `+0x000` byte: bit 0 `fast`, bit 1 `cursorOn`, bit 2 `active` (per-frame update enabled).
- `+0x004` `scroll`, `+0x005` `scrollFrom`, `+0x006` `scrollTo`, `+0x007` bits 0–3 `scrollSteps` (counts down from 4 to 0).
- `+0x008` 0x800-byte tile buffer, uploaded to `0x060091C0` when `+0x808` bit 0 is set.
- `+0x808` u16: bit 0 tiles dirty, bit 1 call `TextCellsResetMap` after the upload, bit 2 cursor move finished (then `DuelScreen_DrawCursorInfo`), bit 3 cursor visible, bit 4 corresponds to OBJ attr1 `0x40`, bit 5 to attr2 `0x30`, bits 6–9 `cursorSteps`.
- `+0x80C/+0x810` cursor x/y (s32), `+0x814/+0x818` from, `+0x81C/+0x820` to.
- `+0x824/+0x828/+0x82C` cursor selection (player, zone, index).
- `+0x830` bit 0 `animActive`, bits 1–7 `animKind`. `+0x834` `animArg` (card id), `+0x838` step, `+0x839` timer, `+0x83A/+0x83C` extra args, `+0x840` `from` and `+0x844` `to` ([[#CardLoc]]), `+0x848` (= `0x0201D7F8`) sub-object for `sub_080769xx`.
- `gDuelScreenLerpWeights` u16 interpolation weights (8.8) indexed by the steps left. `gDuelZonePositions[player][16]` 8-byte zone entries (`+4` = cursor y). `gDuelZoneScrollTargets[player][16]` u16 scroll target per zone.

### CardLoc
4 bytes, passed by pointer and copied as one word: u16 bits 0 `player`, 1–4 `area`, 5–13 `index`, 14, 15, then a u16 (see [[code-0800fb10]]).

### Toss work area `0x02015280` (0xC58 bytes, `struct Work15280`)
`+0x618` 3 × 24-byte entries (`ObjAffineInit`). `+0xAAC` toss block: 8 × 12-byte slots {timer, frame, state (1 = flying), y s16 8.8, t u16, +8/+9 result tile, +0xA landed}, then `+0x60` count, `+0x61` next, `+0x62` mode, `+0x63`, `+0x64` landed-zero count, `+0x65` done. `+0xB14` 4 × 4 bytes, `+0xB24…+0xB3D` misc, `+0xB40` u16 timer, `+0xB48` object for `FadeStart/FadeTick`, `+0xB4E` state (2 = exit, 3 = BLDCNT 0x1040), `+0xB50` object (`CoinToss_UpdateSparkles/52D4/5344`), `+0xC54` phase, `+0xC55` delay, `+0xC56` launched.

## Matching tricks

- **Bitfield byte merge.** When a request writes `animKind` first and `animActive = 1` last, with no other access to the byte in between, old_agbcc merges them into one `strb (kind<<1)|1` or `strb #0xB`. The first statement must still be `animKind = …`: it makes the `0x830` address get computed first (`DuelAnim_Request`, `DuelAnim_PlayZoneEffect`).
- **Avoid jump threading with a memory re-test (`DuelCursor_Select`).** `if (sScreen.zone828 == 0) {…} if (zone == 0 || zone == 5)`: CSE turns the first test into the register compare, but the redundant `cmp r3,#0` stays, as in the ROM. `if (zone == 0)` twice lets the compiler thread the jump.
- **No local for a re-read u16 (`CoinToss_InitCoins`).** Three separate reads of `0x02017A30.opts` (CSE'd into one `ldrh`) give `lsl #16; lsr #29` for `(opts >> 13) & 4`. A `u16 flags` local gives `lsr #13`.
- **`x + (c ? 5 : 0)` as the index (`CoinToss_DrawGlints`)** gives `ldrb; cmp; beq; add #5`. `c ? f + 5 : f` duplicates the load, and a separate `if (c) f += 5` changes the loop's register allocation.
- **`s[i].field` everywhere instead of a slot pointer** (`CoinToss_UpdateFlightUniform`) gives `add r5, off, base` operand order.
- **Scroll interpolation (`DuelScreen_Update`):** only matches as `d *= w; d /= 256; scroll = from + d;`. The one-expression forms differ by a `mov`. `int steps = field; if (steps > 0)` keeps the full `lsl/lsr` extract and a signed `ble`.
- **`DuelAnim_Update` returns `u16`** (the caller narrows it with `lsl #16`).
- **Zero source for CpuSet fill (`CoinToss_Load`)** must be `vu16` (volatile), otherwise `mov r5,#0` is scheduled before `mov r0,sp`.
- `(i + 1) * 240 / (n + 1) - 16` for the token x (`__divsi3`); the int tile `tbl[...] + 0x200` must not be narrowed to u16.
