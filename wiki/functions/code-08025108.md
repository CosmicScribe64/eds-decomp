# Unit code_08025108

`0x08025108`–`0x08026123`, Thumb, `old_agbcc -O2`. Source: `src/code_08025108.c`.

Unit status: `unit bytes MATCH`, **22/22 functions in C** (verified with `tools/check.py code_08025108`). All `0x101C` unit bytes match the baserom.

The unit has two halves:
- `0x08025108`–`0x08025344`: the rest of the token-toss screen from [[code-0802408c]]. It covers the result animation, picking the winners, and the sparkle particle pool at `0x02015DD0` (= toss work `+0xB50`). Hypothesis: the **coin toss** screen.
- `0x08025374`–`0x080260EC`: a second screen on the work area `0x0201F820` (0xAF0 bytes). One sprite group swings on a sine path (`gUnk_08087BA4`) and a second one bounces with ramps. The result is `gUnk_080822FC[face][(t+2)%4]`, taken from `gUnk_08082308[(n−1)%6][side]`, and ends up in `0x02017A30+8`. Hypothesis: the **dice roll** screen (6 rows, die faces).

## Data

- Sparkle (8 bytes): byte 0 = `active:1` (u32 container), `timer:2`, `frame:5` (u8 container); `+4` x, `+5` y. There are 32 of them, and `+0x100` holds `next`.
- Toss slot (12 bytes): `+8` resultTimer, `+9` resultFrame (0–4), `+0xA` resultState (1 animating, 2 done). See [[code-0802408c]].
- `0x0201F820` work (0xAF0 bytes): `+0x618` (`sub_0807B534`), `+0x918` and `+0x92C` sprite groups (`{u32, u16 *templates @+4, u32, u8 count @+0xC, u8 @+0xE}`), `+0xABC` object for `sub_080787F4/sub_0807883C` (`+6` = 2 when finished), `+0xAC4` step, `+0xAC5` spin counter, `+0xAC6..+0xAC9` face/row bytes, `+0xACA` result, `+0xACB` countdown, `+0xACC` started flag, `+0xACD` palette, `+0xAD0/+0xAD8/+0xAE0` ramps (`{u8 state; u8; s16 cur; s16 target; s16}`), `+0xAE8` fade, `+0xAEA` mode, `+0xAEC/+0xAEE` orbit angle/speed.
- `gUnk_081999EC[face]` points to an array of 20 frames `{u8, u8 count, u16, u16 *templates}`. `gUnk_08081FD4[8]` holds the spin frames.
- `gUnk_08087BA4` is a 256-entry s16 sine table (cos = index + 0x40).

## Matching tricks

- **K&R definitions for functions whose callers don't narrow the arguments.** `sub_08025374` / `sub_08025430` take `u16` parameters, but the callers in this unit pass `x + 0x68` without `lsl/lsr`. A prototyped definition makes the callers narrow. A K&R-style definition (`f(a, b) u16 a; …`) gives the ROM's code, and the callee still narrows its own parameters.
- **Returned pointer kept in its own pseudo (`sub_08025374`).** `u16 *oam = call(); u16 *ret = oam; … return ret;` produces the ROM's `mov ip, r7` copy. `ret = call(); oam = ret;` gets copy-propagated away.
- **Bitfield containers mixed in one byte:** `u32 active:1` (tested with `lsl #31`) together with `u8 timer:2; u8 frame:5`, and `if (--p->timer == 3)` (`sub_08025258`).
- **Two `if` blocks with identical tails** (`if (mode == 2) {A[step]…} else {B[step]…}`) are cross-jumped into the ROM's "pick the table, then shared code" shape. A pointer-select or a ternary gets if-converted (`sub_08025F50`).
- **Sub-expression evaluated into a named temporary** (`bob = (… >> 4) + 8; y - bob`), so that `y - 8` doesn't get hoisted (`sub_080256D8`, `sub_080259DC`). In `sub_080259DC`, `sx = dx + 0x68; sx2 = x + sx;` before the call reproduces `add r4, r0, r4`. The order of local declarations picks the stack slots (`g` before `dy`).
- A dead first `y = …` computation keeps its `sub_0807B4D0` call (`sub_080259DC`).

## Roll setup match (2026-09-30)

The earlier allocation near miss is resolved. An explicit initialized `u8 *result = &w->result`, kept live after its last store with one empty input constraint, assigns the work base and result address to the ROM's `r7`/`r6`. Loading the second table byte into `u8 raw` and adding 2 into a separate signed `int sum` gives the ROM's `ldrb r1` / `add r2` before the signed remainder sequence. The final `u8 t` still narrows the remainder at the original point. Constraints on `raw` and `sum` were tried and removed after isolated byte comparisons showed they were unnecessary. No register pins or emitted inline instructions are used.

`tools/dr python3 tools/check.py code_08025108` confirms all 22 functions and all `0x101C` bytes match. The setup experiment also exposed a K&R extraction bug in [[decomp-permuter]], which had previously left other function bodies in this isolated job; the repaired job contains only `sub_08026030` at its original address.
