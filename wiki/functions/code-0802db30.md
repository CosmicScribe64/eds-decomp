# Unit code_0802DB30

`0x0802DB30`-`0x0802EB57`, Thumb, `old_agbcc -O2`. Source: `src/code_0802DB30.c`.
36 small predicates `int f(struct CardRef *ref, [struct CardRef *tgt | int a], [u16 flag])` returning 0/1. They are the condition half of card effects: "can the effect of card `ref` be activated / target `tgt` now?" (hypothesis, by the shape of the checks; the dispatcher that calls them by card number is not in this unit). Same `CardRef` as in [[code-08009a68]] / [[code-0802aac0]].

Unit status: `unit bytes MATCH` (0x1028 bytes, `tools/check.py code_0802DB30`), **36/36 functions in C**. Rechecked on 2026-09-30 after enabling the final function, `EffectLastWillPrepare`.

## Shared headers
This unit now uses `#include "duel.h"` (2026-09-30 header migration). It relies on the canonical `struct DuelCard`, `DuelZone`, `DuelZonesPlayer`, `DuelPlayer` and `DuelState`, and the externs `gDuel`, `gDuelPlayers`, `gDuelZones`. Five local struct definitions (`DuelCard`, `DuelZone`, `DuelZonesPlayer`, `DuelPlayer`, `DuelGlobal`) and their local externs were removed; `DuelGlobal` was replaced by the canonical `struct DuelState`, its `side1B12` field renamed to `linkSkip`, and `DuelPlayer.count904` / `list904` renamed to `graveCount` / `graveyard`. `struct CardRef` is not covered by the shared headers and stays local. `main.h` and `duel_ui.h` are not needed
(no `gMain` / `gDuelCmd` / `gDuelScreen` access).

Local views kept (because a canonical field has a different declared type/bitfield split):
- `struct DuelZoneFlag7`: canonical `DuelZone` has `u8 unk7` at +0x07, but `EffectOncePerTurnPrepare` reads bit 5 as a 0/1 bitfield (ROM `ldrb [+7]; lsls #26; lsrs #31`). This one-byte overlay (`pad[7]` then `flag7_5:1`) is used only in that function.

## Struct CardRef (0x14 bytes, argument 1)
`+0 u16 id` (card ID), `+2 bit 0 player`, `+2 bits 4-9 zone`, `+2 bits 10-15 kind` (`ldrb [+3]; lsr #2`, compares as `& 0xFC`; values seen: 2, 5-7, 0x10, 0x13, 5/6), `+6 u16 pos` (target: low byte player, high byte zone), `+8 u16` (high byte compared `<= 4` in `EffectAttackResponsePrepare`). Argument 2 is either an int (unused) or a second `CardRef *` (the target card; its id is at `+0`); argument 3 is a `u16 flag` that must be 0 (`lsl #16; cmp #0`).

## Data used
Per-player state `gDuelPlayers[2]` (0xD64): `+0` u16 life points, `+2` hand count, `+3` deck count, `+4` count of list `+0x904`, `+5` fusion-deck count, `+0xB` bit 3 flag, `+0x28` zones, `+0x684` hand, `+0x904`, `+0xA44` lists. `0x020192E0 + 0x1B12`: bit 1 side/turn player, bits 2-4 phase (hypotheses; same byte as `flags1B12` in unit code_0800C894 and [[code-08009a68]]). Card type via `gCardStats[id & 0x7FF]` bits 20-24 (1 = monster in these checks, 21 Magic, 22 Trap).

## Matching tricks
- **Return layout.** `if (cond) return 1; return 0;` and `if (!cond) return 0; return 1;` differ in block order. Use whichever gives the ROM's order: `return 0` block last with `ble`/`bne` to it means `if (bad) return 0; ... return 1`.
- **Signed range on a bitfield** (`kind`, `type`): `cmp #7; bgt; cmp #5; blt` needs an `int` local (`int k = ref->kind; if (k > 7 || k < 5) return 0;`) or `switch ((int)x) { case 5: case 6: case 7: ... }`. `k <= 7 && k >= 5` gives a `sub; cmp; bhi` unsigned range test.
- **`& 1` that survives** in loops (`EffectPolymerizationPrepare`, `E058`, `E42C`, `EA74`): write the same `1 & ref->player` (or `(1 - ref->player) & 1`) in both the loop condition and the body, and hold the card ID in a `u16` local (`u16 id = CARD_ID(word)`), so the `& 0x7FF` of the stats lookup is kept and its constant hoisted.
- **Raw byte `& 1`** to compare two players (`EffectFairysHandMirrorPrepare`): `(((u8 *)tgt)[2] & 1) == (((u8 *)ref)[2] & 1)` (the bitfield form folds).
- **Opponent index:** `struct DuelPlayer *pl = gDuelPlayers; int p = ref->player; p ^= 1; pl[p]` (`EffectOpponentHasHandPrepare`); the base pointer local must come first.
- **Early-return form makes the `return 1` block come first** in loop functions (`EffectFinalDestinyPrepare`, `EffectPolymerizationPrepare`): `if (x <= 4) return 0; for (...)`.
- **Switch compare trees (`EffectSpellResponsePrepare`, `EffectAttackResponsePrepare`).** Inner `switch` on a card number ending with `default: return 0;` stops old_agbcc from cross-jumping the leaf `cmp; beq` tails between trees (`EffectSpellResponsePrepare` matched only with the explicit default). In `EffectAttackResponsePrepare` the `case A: case B: ...: return 1;` group must come first in the source, with every other case ending in an explicit `return`. To recover case sets from the ROM, simulate the compare tree (mov/ldr/sub/add on r0, `cmp r1,r0`, conditional branches) for every value 0..0x7FF.
- **Zone address used twice** (`EffectAttackResponsePrepare`): a fresh `int p = (1 - ref->player) & 1; struct DuelZone *z = ZB(p, k);` per use.
- **Player-bit re-extraction** (`EffectLastWillPrepare`, also [[code-0802eb58]]): read the player bit into a shifted `u32`, test player flag `+0xB` bit 3 as `(s32)((u32)flags << 28) < 0`, then use an empty read/write asm constraint on the initialized shifted value before the call. This reproduces the ROM's `lsr r0,r3,#31` argument extraction instead of common-subexpression reuse of the normalized index. The compiler hint emits no instructions and is marked FAKEMATCH in source.
