# Unit code_0802FB64

`0x0802FB64`-`0x08030B87`, Thumb, `old_agbcc -O2`. Source: `src/code_0802FB64.c`. Follows [[code-0802eb58]] / [[code-0802db30]] (same `CardRef`, `DuelZone`, `DuelPlayer`, `DuelGlobal` layouts).

Unit status: `unit bytes MATCH` (0x1024 bytes), **31/32 functions in C**; 1 remains `INCLUDE_ASM`. Verified with `tools/check.py code_0802FB64` on 2026-09-30 after enabling `sub_08030028`, `sub_08030578`, `sub_08030928`, and `sub_08030A64`.

The unit has two kinds of functions:
- **Conditions** `int f(struct CardRef *ref, [tgt], [u16 flag])` (0x0802FB64-0x0802FFE4): "can this card effect be used?" predicates, like the previous units.
- **Effect steps** `int f(struct CardRef *ref)` (0x08030028-0x08030B4C): they run one step of a card effect. Most start with `if (ref+4 & 4) return 0` (an "already handled" flag), test `ref+0xA & 7` (step number 1 or 2) or `gUnk_02017A40[0x3E0]` (the step state 0x7D-0x80 of a small state machine that returns the next state, 0x64 = done) and call the animation/sound helper `sub_0801EC58(id | 0x8000 if player 1, ...)`, `sub_08018544(player, zone, 1)`, `sub_08019860(player, amount)` etc. (hypothesis: the dispatcher is elsewhere).

## Data
- `CardRef` gains `+0xA` (byte, `& 7` = step number), `+0xC` u16 `posC` (player low byte, zone high byte; the low 12 bits are also a card id in `0x08030578`), `+0xE` u16, `+4` byte bit 2 "handled" flag, `+2` bits 1-3 (mode, 3 = the effect-step variant).
- `gUnk_02017A40 + 0x3E0`: effect state byte (0x7D-0x80); `+0x3E5` a flag byte.
- `struct Unk02017E20` (hypothesis): `+0` counter byte, `+0x15C` four 8-bit bitfields starting at bit 12 (cleared by `sub_08030620`), `+0x164` u32[5] copy of a player's `+0x7C4` block (deck words). The compiler derived all these addresses from one register, so they are one object.
- Card level (bits 25-28 of the stats word; types 0x15-0x17 give 0 and 0x18 gives 10): macro `CARD_LEVEL`, as in [[code-0802eb58]].
- `0x0201D810` `ListView` (row = `+5` bits 0-1, top = `+6`, cards = `+0xC`), see [[code-0802aac0]]. `0x02015F00 + 0x1B22` holds the saved list position.

## Matching tricks
- **Chained `||` vs separate `if ... return 0;`**: `sub_0802FE6C` needs the separate form; agbcc then re-extracts the `player` bitfield (`lsrs r1,r1,#31`) for `1 - player` instead of reusing the compare's register.
- **Drop a byte local and inline it**: `sub_0802FF90` matched only after replacing `u16 w = ref->unk8; if ((w & 0xF) != ...)` with the inline `if ((ref->unk8 & 0xF) != ...)` (the local made the compiler copy the wrong operand into r0).
- **Move a loop-invariant mask into the inner loop body**: `sub_0802FD90` matched with `p = i & 1;` as a statement inside the inner `for` (agbcc hoists it but emits the ROM's `ldr …; adds …; movs …; ands …` instead of the 2-byte-shorter form).
- **64-bit base stops table-address hoisting** (see [[decomp-permuter]]): `sub_0802FEA4` needed `unsigned long long base = 0x08621DE0;` for the *type* access while the `default` level access keeps the literal, so the table reloads inside the loop like the ROM.
- **An explicit `return 0;` after a branch stops old_agbcc cross-jumping** two identical tail calls (`sub_08030400`).
- **Symbol addresses are hoisted, constant addresses are not.** A `gUnk_xxx[...]` reference used twice inside a loop gets its `ldr rX,=sym` hoisted into a callee-saved register; `((const u16 *)0x08622AB4)[...]` (integer constant) is loaded where used (`sub_080301C0`, `0802FEA4`).
- **`u8`/`u16` flag variable gives the `neg / orr / lsr #31` idiom** for `ok = f() != 0` (a plain `int ok` compiles to a branch): `u8 ok = f(x) != 0; if (...) ok = 0;` (`sub_0802FD90`).
- **One struct with CSE'd offsets.** When the ROM addresses several RAM objects as `r5 - 8`, `r5 - 4`, `r5 - 0x164` from one literal, they are members of one struct (one symbol); declare it once (`sub_08030620`). Bitfield assignments of 8-bit fields at bit 12/20/28/36 give exactly the u32 / u16 / two u8 / u16 read-modify-write sequences.
- **Integer compare on `int id`:** `int id = CARD_ID(word); if (id > 0 ...)` gives `ble`, the `u16` form gives `beq` (`sub_080300D8`).
- **`switch` bodies are laid out in source order and a body without `break` falls into the next**: 0x80 case first, then 0x7F, 0x7E, 0x7D (`sub_08030620`, `08030928`). Use `goto sNN;` back to an earlier `return` to keep one shared block (`sub_08030928`).
- **Raw byte `& 1` for the ternary** `(((u8 *)ref)[2] & 1) ? 0x8060 : 0x60` is `movs r0,#1; ldrb; ands`; `1 & ref->player` is the bitfield form (`lsls/lsrs`). Sound ids are `id | 0x8000` for player 1.
- Use `u32` shifts for a bitfield read from a halfword (`(u32)(ref->posC << 20) >> 20`); `int` gives `asrs`.
- **Assignment inside an argument** fixes the evaluation order of a local (`sub_08009CAC(ref->player, CARD_NUMBER(id = ...))`).

## Verified C conversions (2026-09-30)

- `sub_08030A28`, Thumb, `0x3C` bytes, matching C. It is the mode-3 LP effect, and other modes delegate to `sub_08030880`. An empty r1 clobber after reading byte 2 preserves the shared byte in r3.
- `sub_08030B4C`, Thumb, `0x3C` bytes, matching C. It wraps event 0xD0 for mode 3, and other modes delegate to `sub_08030880`. The same byte hint plus player/message locals assigned to r0/r3 reproduces the ROM ternary and call setup.
- `sub_08030A64`, Thumb, `0xE8` bytes, matching C. Byte `+2` is held in `r3` for the mode check and first sound message. The inline `PlayerBitFromModeByte` helper constrains the shifted player bit to `r0` before the right shift, preserving the ROM's `lsl #31; lsr #31` instead of an `and #1`. The empty input constraint is marked FAKEMATCH and emits no instructions. The second sound re-reads byte `+2` after the first call, as the ROM does.
- `sub_08030578`, Thumb, `0x74` bytes, matching C. A scoped sound-id local in `r3` reproduces the explicit 0xD2/0x80D2 branch. Initialized position/zero locals and an empty input constraint with `r0` clobbered prepare `r1/r2` before the sound-id copy to `r0`, preserving the original call setup. This compiler hint emits no instructions and is marked FAKEMATCH.
- `sub_08030028`, Thumb, `0xB0` bytes, matching C. Empty input constraints on the first zone address and recomputed player mask preserve the original first multiply/address in `r0` and the later mask in `r2`. Both are marked FAKEMATCH and emit no instructions.
- `sub_08030928`, Thumb, `0x100` bytes, matching C. An initialized `0x3E5` offset constrained after its byte store preserves the offset in `r2` and zero in `r0`. A separate initialized `u16` position constrained after the zone shift with `r2` clobbered preserves the position in `r3` and the later mode-byte scratch in `r1`. Both empty compiler hints are marked FAKEMATCH, emit no instructions, and retain the original ABI.
