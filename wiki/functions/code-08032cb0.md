# Unit code_08032CB0

The unit covers `0x08032CB0`-`0x08033DAB` (Thumb, `old_agbcc -O2`), and its source is `src/code_08032CB0.c`. It follows [[code-0802db30]] (condition predicates). This unit holds the **effect step handlers**, functions of the form `int f(struct EffCtx *ctx)` that are gated by `ctx->flags4 & 4` (skip flag) and run one step of a card effect (log messages via `sub_0801EC58`, prompts via `sub_080602A4`, moves via `sub_08017AB4`/`sub_08019860`). Some have a state machine driven by the step byte `0x02017A40+0x3E0` (values 0x7C-0x80) and sub-step `+0x3E1`; the return value is the next step (0x7C-0x7F) or 0 for done (hypothesis).

Unit status: `unit bytes MATCH` (`tools/check.py code_08032CB0`, complete 0x10FC-byte unit), **12/12 functions in C** since workflow wave 1 (2026-10-01), when the last two fallbacks `0x08032D10` and `0x08033AEC` matched.

## Struct EffCtx (argument 1; same head as `CardRef` in [[code-0802cae8]])
`+0 u16 id`, `+2 bit 0 player`, `+2 bits 4-9 zone`, `+2 bits 10-15 kind`, `+4 u8 flags` (bit 2 = skip), `+0xA u8` (bits 0-2 = phase; several handlers need `== 1`), `+0xC u16 pos` (low byte player, high byte zone of a target card).

## Matching tricks
- Raw `1 & ((u8 *)ctx)[2]` for message selects (`ctx->player ? 0x8094 : 0x94`): the bitfield form gives `lsl/lsr`, the raw byte gives `mov #1; ldrb; and`.
- Zone address from `pos`: `int zone = pos >> 8; int player = ((u8 *)&pos)[0] & 1; z = zone*0x94 + player*0xD64 + base` as locals (the macro with `& 1` inside gives a different multiplication order).
- Step dispatch with 2 values (0x7F, 0x80) that has range checks first: `switch (step) { case 0x7F: case 0x80: { switch (step) {...} ... } default: return 0; }` (nested switch reproduces `cmp #0x80; ble` / `cmp #0x7F; bge` then the eq chain).
- `flag = 1; if (c) { flag = 0; if (x) flag = 1; }` gives the `negs; orrs; lsrs` setcc.
- Sign test of bit 5 as `((int)((u32)((u8 *)s)[8] << 26) < 0)` gives `lsl #26; cmp #0; bge` (the bitfield form gives `and #0x20`, and hoists the 0x20).
- Pointer to a 12-byte array element: load the base first with `slots = gUnk; s = slots + p;` to get the literal load before the index arithmetic.
- `u32 zero = (u8)(ctx->flags4 & 4);` gives a single `lsr r7,r0,#24` (the `u8` local gives an extra `adds`).
- Large struct offsets (`0x3E1`) through a struct field give the two-literal `ldr base; ldr off; add` form; `base + 0x3E1` with a `u8 *` gives one literal.
- Card-type helper with an inlined `if (ty == t) r = 1` (`static inline int TypeIs(u32 id, u32 t) { u32 ty = CARD_TYPE(id); int r = 0; if (ty == t) r = 1; return r; }`) reproduces `movs r1,#0; cmp; bne; movs r1,#1; adds r3,r1,#0`; a direct `flag = (type == 0x15)` does not.
- A message id held in a local (`int msg = raw ? 0x8074 : 0x74; f(msg, ...)`) picks register r1 (the inline ternary picks r2) in `0x08032F20`.
- Unit-wide: `PLAYER_RAW(c) = 1 & ((u8 *)c)[2]`; 12-bit card id `CARD_ID`, 11-bit `CARD_ID11`; `CARD_TYPE(CARD_ID11((u32)u16id))` gives `lsl #21; lsr #19` for a halfword id, `CARD_TYPE(u16id)` alone gives `and #0x7FF; lsl #2`.
- `(struct DuelZone *)((u32)&gUnk_0201930C[p] + z * 0x94)` with a local `pp = &gUnk_0201930C[p]` keeps the `(p*0xD64 + base) + z*0x94` association; inline it and agbcc reassociates.
- **Initialized pointer lifetimes (`sub_080334E4`, FAKEMATCH).** The first draft had the correct 0x3E8 size and differed by 20 bytes in two register groups. An input-only empty constraint on the initialized destination `b`, immediately after the first copy in case 0x7C, assigns b/one to r8/r9. An input-only constraint on the formed case-0x7A card pointer, after declaring `int flag=0`, assigns card/flag/0x47F to r4/r5/r6 while preserving address calculation in scratch registers. These two compiler hints add no machine instructions or memory accesses and preserve the original ABI. Both register pins and read/write constraints were minimized away; removing the destination input leaves seven differing bytes, and removing the card input leaves thirteen. Placing a named r8 input before the copy adds an unwanted move; pinning the card to r4 changes its address calculation registers. Flag widths, declaration reordering, delayed card formation and alternate pointer views did not match. Exact full-unit log: `build/middle_experiments/sub_080334E4/unit-check.log`; successful and minimization grids: `three_card_flag_scope.py`, `three_card_minimize.py`, `three_card_clean.py`.

## Phase-1 effect and hand-pick prompt matched (wave 1, 2026-10-01)

Both remaining fallbacks matched; the unit is complete. Working notes: `build/wf/sub_08032D10/NOTES.md`, `build/wf/sub_08033AEC/NOTES.md`.

### `sub_08032D10` (0x16C, start score 30; FAKEMATCH)

1. `s16 c8 = (u8)cnt << 8` gave `asrs` where the ROM has `lsrs`. Writing `ctx->player | (u8)cnt << 8` inline in both calls (CSE shares it) fixes the shift and its placement.
2. The `player & 1` AND came after `zone*0x94`; a separate `p0 = player & 1;` statement before the sum fixes it.
3. zone/tid in r9/sl were swapped; declaration order and local types do not help. One pin fixes it (`register int zone asm("sl")`, or tid in r9).
4. In block 4 (`z3->flag6_1`) the ROM reloads `ldr r7, =0xD64`; our build reused r7 from the 0x2DA block through **reload inheritance** (the 0xD64 pseudo is spilled with a REG_EQUIV constant and r7 still held it). `asm volatile("" ::: "r7");` placed **before** `if (CARD_NUMBER(...) == 0x2DA)` breaks the inheritance. Placed at the start of block 4 it gives score 16 (reload picks r3).
- Failed: an `&&` chain or inline `ZB` expressions without the p1/z1, p2/z2, p3/z3 user variables (score ~180-200); do/while(0) and for/break wrappers (182); a fresh 0xD64 pseudo via `asm("" : "+r"(k))` (116). The permuter's best used `register char tid`, which is not semantics-preserving and was rejected.

### `sub_08033AEC` (0x2C0, start score 42; ordinary C)

1. `hand[(u16)(i)]` gave an extra `lsl/lsr #16`; plain `hand[i]` fixes it.
2. In the 0x7D loop the ROM copies the `0x020192E4` base to r7 before loading 0x7FF into r4. A named comparison temporary fixes the order: `int t = CARD_TYPE(id) - 1; if (t != 0) continue;` (compare `sub_0802F958`'s `new_var`). `t = CARD_TYPE(id) != 1` also fixes the registers but gives `cmp r0, r6`.
3. Case 0x7E had type in r5 and the card pointer in r4; the ROM swaps them. Global-alloc priority is `floor_log2(refs) * refs / live_length`; regmove extends the type's range to the message test (6 refs / 37 insns) against the card's 4 refs / 22. The card's flow-time live length must reach 25. `s16 f = (s8)PLAYER_RAW(ctx);` used as the 0x80C2/0xC2 selector adds sign-extension insns, which combine later deletes, while the card is live (26). `s8 f = PLAYER_RAW(ctx); s8 g = f;` and `(s8)(f + 0)` also work. Casts directly on `PLAYER_RAW` fold at tree level and do not.
- Live length is an exact count of flow-time insns before combine; notes and labels are not counted. See [[matching-tricks#Register allocation priority and reload rotation]].
