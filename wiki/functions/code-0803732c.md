# Unit code_0803732C

`0x0803732C`-`0x080383EF`, Thumb, `old_agbcc -O2`. Source: `src/code_0803732C.c`. Same style as [[code-08031bc8]] / [[code-0802fb64]]. These are card-effect executors `int f(struct CardRef *ref)` that return 0 or the next step state (0x64 = done, 0x7B-0x80 = steps of the `gUnk_02017A40[0x3E0]` state machine). All start with `if (ref->skip4) return 0`.

Unit status: `unit bytes MATCH`, **12/14 functions in C**; 2 remain `INCLUDE_ASM`. Verified with `tools/check.py code_0803732C`.

## Shared headers (2026-09-30 migration)
This unit uses the canonical layouts from `include/duel.h`: `struct DuelCard`, `DuelZone`, `DuelPlayer`, `DuelState`, `DuelZonesPlayer`, and the globals `gUnk_020192E0`, `gUnk_020192E4`, `gUnk_0201930C`. `include/main.h` is **not** needed (the unit never touches `gUnk_03000040`).

Six local struct definitions were removed: `DuelCard`, `DuelZone`, `DuelZonesPlayer`, `PlayerHand` (renamed to `struct DuelPlayer`, byte-identical layout) and `DuelG` in an earlier pass, then the `DuelStateSide` tail view. The tail view is no longer needed because `duel.h`'s `struct DuelState` now covers `+0x1ACC..+0x1B20` (queue and flags). `0x0803732C` therefore reads the turn-side bit at `+0x1B12` bit 1 directly as `gUnk_020192E0.linkSkip`, and its `(u8 *)&gUnk_020192E0` byte view reaches `+0x1B64`/`+0x1B66` as before. With the canonical struct, the previously parked `0x0803732C` compiles byte-identically. The earlier local view had placed the bit wrongly because `sizeof(struct DuelState)` includes trailing padding. **No local views are kept.**

## Matching tricks
- **`u8 skip = 4 & ((u8 *)ref)[4]; if (!skip ...)`** keeps the (u8) truncation, and the compiler then reuses `skip` (known 0) as the zero constant in later stores (`0x08037CD4`).
- **`int pp = 1 & ref->player;` then `ref->player` written again later** gives the ROM's "one `lsl #31` register, `lsr #31` re-extracted" shape (`0x08037CD4`, `0x0803821C`).
- **Local `int pa = tp & 1;` before `ZB(pa, tz)`** fixes the order of the `& 1` before the `* 0x94` (`0x08038320`, `0x0803821C`).
- **Prototype parameter type decides the `lsl/lsr #16`.** With `sub_08017AB4(player, int a, u16 b, u16 c)`, an `int` second parameter avoids the narrowing of `sub_0807548C()`'s result. An unprototyped `void sub_08018DC8();` lets the same function be called with 3 and 4 arguments.
- **Two zone reads.** Read the card word through one zone pointer and the flags through a second `ZB()` pointer (`0x0803821C`). A shared `&z->flags` pointer makes the compiler hoist `base + 6`.
- **Switch on the card number through the symbol table**: `gUnk_08622AB4[0x7FF & ref->id]` hoists mask and table into callee-saved registers (as in `0x08037AF4`), the integer-constant form does not.
- Two-object hoist: `ZB` (`0x0201930C`) and the player struct (`0x020192E4`) are computed one from the other (`subs rX, #0x28`) when written as `(u32)gUnk_020192E4 + 0x28` in one and `gUnk_020192E4[i]` in the other.
- **`volatile` re-read after a byte store** (`0x0803732C` step 0x7D): `EFF_SIDE = 1 - EFF_SIDE; sd = gUnk_020192E0.linkSkip; if (*(volatile u8 *)&EFF_SIDE != sd)` reproduces the ROM's reload of the byte after the store (plain code forwards the stored register and adds `lsl/lsr #24`). Read the *other* operand into a local first to get the ROM's order.
- **Frame-address local + pointer**: a local `struct PosWord x` whose bit is flipped through a separate `px = &x;` (assigned right after the word is built) gives the ROM's early `add r5, sp, #4` (`0x0803732C`).
- **Unfolded 16-bit access into a big global**: `u8 *g = gUnk_020192E0; *(u16 *)(g + 0x1B64)` keeps `ldr rB,=sym; ldr rN,=0x1B64; add`, whereas `*(u16 *)&arr[0x1B64]` folds into one `sym+0x1B64` literal.
- **Constant addresses vs symbols** decide CSE: `(u32)gUnk_02017E20 + 8` and `+ 1` are derived from one literal (`subs r5, r1, #7`), two plain integer constants are not (`0x08037ED8`).
- **Local pointer to a global array, assigned after the call** (`0x08037CD4`): `rnd = sub_08076F9C(); ph = gUnk_020192E4; rnd % ph[(1 - p) & 1].handCount` makes the ROM's literal load come right after the `bl`. `ph[(1 - ref->player) & 1]` (not `^ 1`) gives the ROM's `eors` operand order.
- **Grid search harness** (scratchpad `code_0803732C/grid.py`, `T`). For register-allocation puzzles it is cheaper to generate 50 source variants (types, declaration order, if/switch) and diff them all. That sweep found no match for `0x080375F8`, but the C recovered later matches that function exactly.
