## Structs and globals (in addition to [[code-080361d0]])
- `0x020192E4` (player state, stride 0xD64) is one struct: `+2` `handCount`, `+3` `deckCount`, `+0x28` `zones[11]` (= `0x0201930C`, `DuelZone` 0x94 each), `+0x684` `hand[80]` (card words, = `0x02019968`), `+0x7C4` `deck[80]`. Accessing zones, hand count and hand cards through **one symbol** (`gUnk_020192E4[p].hand[k]`, `.handCount`, `.zones[z]`) reproduces the ROM's `ldr base; sub #0x28` / `0xFFFFF97C` address arithmetic (`0x08039638`, `0x0803A410`).
- `0x0201CFB0` screen state: `+0x824`, `+0x828`, `+0x82C` are u32 (a selected player / zone pair; bytes 0 of them are used as position bytes).
- `0x02017A40` effect state: `+0x3E0` phase, `+0x4E4` CardRef copy, `+0x4F8` fn, `+0x542` u16, `+0x544` two u16 halves of a card word.
- `sub_080199E0(p, n)`: draws/adds n cards (hypothesis); `sub_08046BE0(p, n)`: display of a count (hypothesis).

## Matching tricks
- **Zone pointer walk**: `struct DuelZone *z = gUnk_0201930C[i & 1].zones; for (j = 0; j <= 4; j++, z++)` gives the ROM's `adds r1,#0x94` loops with `i`/`j` in caller-saved registers; the index form `ZB(i & 1, j)` puts `i` in r4.
- **`ZB2(p, z)` = `p * 0xD64 + z * 0x94 + base`** written p-first *emits* the z-first multiply order the ROM has (`sub_0803A378`), the reverse of `ZB`.
- **Break out of a loop with `goto found;` and the call after the switch** keeps the loop counters out of callee-saved registers (no call inside the loop).
- **Local `u8 *es = (u8 *)0x02017A40;` + byte offsets** (`es[0x3E0]`, `*(fn *)(es + 0x4F8)`, `es + 0x4E4`) reproduced the tail of the dispatcher `0x08039C48`, where the ROM re-loads the base instead of reusing the register that holds the symbol (`sub_08039C48`); the head uses the symbol (`ES->cur`).
- **Separate init statements change register order**: `int tp = ...; int v = f(tp); int j; int p; j = 0; p = 1 - tp;` matched `sub_08039D8C` where `int j; int p = ..; p = 1 - p;` did not.
- **`(ref, arg)` second parameter** that is only forwarded (`sub_0803A4B8` passes it on to `sub_08036030(ref, arg)`) changes which scratch register the prologue uses (`r2` instead of `r1`). When it is completely unused (`sub_08039EDC`) the compiler homes `ref` in r1, reproducing the ROM's `add r1, r0, #0` instead of the sibling's callee-saved r4.
- **`num[gUnk_table]` / assignment in an argument** (`sub_08056D98(p, num = 0x4EA, 0x3E7)`) put `0x4EA` in a callee-saved register loaded *after* the `ref->player` extraction (`sub_08039F68`, attempt).
- `case 0x151 ... 0x159:` (GNU case ranges) reproduce the compare tree of a sparse `switch` (dispatcher).
- `1 & ((u8 *)ref)[2]` for the ternary message id, bitfield `ref->player` for arguments (as in the earlier units).
- **Selection read order (`sub_08039B90`)**: read the raw player word from `DSV->w824`, then the zone word from `DSV->w82C`, before masking and address arithmetic. An empty asm input constraint on the initialized card id keeps its final `lsrs #20` before extracting `ref->player`. This is a documented FAKEMATCH compiler barrier; it emits no instructions and introduces no unset values.
