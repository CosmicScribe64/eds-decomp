## Structs and globals (in addition to [[code-080361d0]])
- `0x020192E4` (player state, stride 0xD64) is one struct: `+2` `handCount`, `+3` `deckCount`, `+0x28` `zones[11]` (= `0x0201930C`, `DuelZone` 0x94 each), `+0x684` `hand[80]` (card words, = `0x02019968`), `+0x7C4` `deck[80]`. Accessing zones, hand count and hand cards through **one symbol** (`gUnk_020192E4[p].hand[k]`, `.handCount`, `.zones[z]`) reproduces the ROM's `ldr base; sub #0x28` / `0xFFFFF97C` address arithmetic (`0x08039638`, `0x0803A410`).
- `0x0201CFB0` screen state: `+0x824`, `+0x828`, `+0x82C` are u32 (a selected player / zone pair; bytes 0 of them are used as position bytes).
- `0x02017A40` effect state: `+0x3E0` phase, `+0x4E4` CardRef copy, `+0x4F8` fn, `+0x542` u16, `+0x544` two u16 halves of a card word. These are the ROM offsets. The unit's local `struct EffState` assumes a 0x14-byte `CardRef`, but the compiled `CardRef` is 0x10 bytes, so `ES->w542` lands at `+0x53E` (found by the `sub_08039F68` match, 2026-10-01; the same gap was fixed in [[code-08035198]] for `sub_080358AC`). `sub_08039F68` uses a local `struct EffStateW542 { u8 unk0[0x542]; u16 w542; }`; any new user of `ES->w542` or `ES->fn` here must check the offset.
- `sub_080199E0(p, n)`: draws/adds n cards (hypothesis); `sub_08046BE0(p, n)`: display of a count (hypothesis).

## Matching tricks
- **Zone pointer walk**: `struct DuelZone *z = gUnk_0201930C[i & 1].zones; for (j = 0; j <= 4; j++, z++)` gives the ROM's `adds r1,#0x94` loops with `i`/`j` in caller-saved registers; the index form `ZB(i & 1, j)` puts `i` in r4. (In the wave 2 matches `0x080398B0` and `0x08039F68`, where the inner loop's constants are hoisted into callee-saved registers, the opposite held: the indexed `ZB2(i & 1, j)` matched and the walk did not.)
- **`ZB2(p, z)` = `p * 0xD64 + z * 0x94 + base`** written p-first *emits* the z-first multiply order the ROM has (`sub_0803A378`), the reverse of `ZB`.
- **Break out of a loop with `goto found;` and the call after the switch** keeps the loop counters out of callee-saved registers (no call inside the loop).
- **Local `u8 *es = (u8 *)0x02017A40;` + byte offsets** (`es[0x3E0]`, `*(fn *)(es + 0x4F8)`, `es + 0x4E4`) reproduced the tail of the dispatcher `0x08039C48`, where the ROM re-loads the base instead of reusing the register that holds the symbol (`sub_08039C48`); the head uses the symbol (`ES->cur`).
- **Separate init statements change register order**: `int tp = ...; int v = f(tp); int j; int p; j = 0; p = 1 - tp;` matched `sub_08039D8C` where `int j; int p = ..; p = 1 - p;` did not.
- **`(ref, arg)` second parameter** that is only forwarded (`sub_0803A4B8` passes it on to `sub_08036030(ref, arg)`) changes which scratch register the prologue uses (`r2` instead of `r1`). When it is completely unused (`sub_08039EDC`) the compiler homes `ref` in r1, reproducing the ROM's `add r1, r0, #0` instead of the sibling's callee-saved r4.

The wave 2 match (2026-10-01, `build/wf/sub_08039F68/NOTES.md`) found that every symbol form (`gUnk_08623DF4[num]`, `num[tab]`, a local `tab` pointer) gets its own pseudo and shifts the reload registers; the matched source reads `((const u16 *)0x08623DF4)[num]` (a constant address). The assignment `num = 0x4EA` in the `sub_08056D98` argument is kept. Resolved in favour of the matched source.

- **`num[gUnk_table]` / assignment in an argument** (`sub_08056D98(p, num = 0x4EA, 0x3E7)`) put `0x4EA` in a callee-saved register loaded *after* the `ref->player` extraction (`sub_08039F68`, attempt).
- `case 0x151 ... 0x159:` (GNU case ranges) reproduce the compare tree of a sparse `switch` (dispatcher).
- `1 & ((u8 *)ref)[2]` for the ternary message id, bitfield `ref->player` for arguments (as in the earlier units).
- **Selection read order (`sub_08039B90`)**: read the raw player word from `DSV->w824`, then the zone word from `DSV->w82C`, before masking and address arithmetic. An empty asm input constraint on the initialized card id keeps its final `lsrs #20` before extracting `ref->player`. This is a documented FAKEMATCH compiler barrier; it emits no instructions and introduces no unset values.

## Wave 2 matches (2026-10-01)

Both match in ordinary C. Working notes: `build/wf/sub_080398B0/NOTES.md`, `build/wf/sub_08039F68/NOTES.md`.

### `sub_080398B0` (0x254, start score 56; ordinary C)

1. Zone scan: `struct DuelZone *z = ZB2(i & 1, j);` inside the inner loop (as in the sibling `sub_08039F68`) instead of a pointer advanced with `z++`. This gives the ROM's hoisting order (1, 0xD64, base and 2 in r8, r6, r5, r4).
2. Step 0x7D packed argument `(u8)DSV->w828 | (u8)DSV->w82C << 8` (w828 first, as in `sub_08051DF4` of [[code-08051a9c]]): the emitted order is the same, but the live lengths change, so `&w824`/`&w828`/`&w82C` get r6/r4/r8.
3. Name table as the integer constant `((const u8 *)0x0822C720)` (`NAMES_0822C720`) in **both** steps 0x7F and 0x7E. The const_int stays in the add, so reload loads it into a rotating reload register (r0 in 0x7F, r3 in 0x7E), which also puts every later reload in 0x7D on the ROM's registers. With the extern symbol, local-alloc gives it r0 in both steps; converting only 0x7E starts the rotation from r7 and wraps back to r0.
- Failed: a function-entry `const u8 *names = gUnk_0822C720;` (hard register r3 from entry, 14 bytes longer, score 111).

### `sub_08039F68` (0x214, start score 48; ordinary C)

1. Zone scan as an indexed loop, `struct DuelZone *z = ZB2(i & 1, j);` with `int j`: strength reduction builds the zone-pointer induction variable in the inner preheader after `j = 0`, and loop.c hoists 1 and 0xD64 into r8/r9. The walking pointer `z = ZB2(i & 1, 0); z++` did not hoist them; the array form `&gUnk_0201930C[i & 1].zones[j]` gives `add r1, r5, r0` instead of ZB2's `add r1, r0, r5`.
2. Constant-address table `((const u16 *)0x08623DF4)[num]`: the add stays `(plus idx const)` and reload loads the constant into a spill register (`ldr r7`), which also shifts the round-robin spill registers of the loop (`mov r0,#1; mov r8,r0`, `mov r7,r8; and`, `mov r1,r9; mul`). Any symbol form (direct, a local `tab`, an integer add) gets its own pseudo and changes every later reload register.
