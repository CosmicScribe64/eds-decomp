## Matching tricks
- **`u16 id` instead of `int id`** gives the extra register copy and the `ldr r2,=0x7FF; adds r1,r2,#0` form the ROM has for `id & 0x7FF` (`EffectDestroyOpponentLevel4Resolve`).
- **`u8 r = Random() & 1;`** gives `movs r0,#1; ands r4,r0` (separate constant) as in `EffectCoinTossZeroAttackerResolve`; `int r` shares the constant with a later `1 & byte` (as in `0x0803A1C0`).
- **Bitfield instead of a byte mask** for a zone flag or mark (`->flag6_1`, `((struct ZoneB1 *)z)->f6 = 0`) avoids folding `+6` into the pool literal and yields the ROM's `movs r0,#0x41; negs r0,r0` for the clear.
- **Loop increment order**: `for (i = 0; i <= 1; t++, i++)` (pointer first) gives the ROM's `adds r4,#2; subs r6,#1`; `i++, t++` gives the reverse (`0x0803A6B0`).
- **Reading the byte and the halfword of `targets[i]` separately**: `int tz = *t >> 8;` before `1 & *(u8 *)t` reproduces `ldrh; lsrs; ldrb; ands` (a plain `(u8)ref->targets[i]` merges into the halfword).
- **`ZB(p, tz)` with `int p = n & byte;` computed first** reproduces the ROM's multiply order where `ZB2` (p-first text) is wrong; which macro is needed differs between functions, so try both (`ZB` for `0x0803A9C8`, `0x0803B06C`, `0x0803B1EC`; `ZB2` for `0x0803A654`, `0x0803A6B0`, `0x0803AA80`).
- **Ternary message ids** in an `if/else` on `EFF_PHASE == 0x80` (not a `switch`) for two-state machines (`0x0803A890`, `0x0803AB78`).
- **Indexed check loop followed by a walking call loop** (`EffectTributeTwoMonstersResolve`): reuse [[code-08033dac]]'s initialized-offset constraint. Set `i = 0` before assigning a separate `targets` base in r3; each check iteration computes `off = i * 2` in r0 and passes that initialized value through an empty read/write constraint before adding the base. This prevents strength reduction of the checks. Afterward assign a normal `t = targets` for the call loop; the r3 base is no longer needed when calls begin. Keeping one mutable pointer for both loops introduces a callee-saved base copy in r7 and changes the save set. An ordinary offset local or pointer-initialization order alone did not match. The empty hint emits no instructions and is marked FAKEMATCH. Original ABI unchanged; complete `0x101C`-byte unit verified exact.
