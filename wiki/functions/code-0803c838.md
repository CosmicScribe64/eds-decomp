# Unit code_0803C838

`0x0803C838`-`0x0803D57B` + one 0x800-byte function to `0x0803DD7B`, Thumb, `old_agbcc -O2`. Source: `src/code_0803C838.c`. Continues [[code-0803b670]] (`int f(struct CardRef *ref)` effect executors, state byte `gUnk_02017A40[0x3E0]`, side `[0x3E1]`, counter `[0x3E2]`) and adds a small "fusion recipe" helper family (card-number tables `gUnk_0819A7C8` / `gUnk_0819A970`).

Unit status: `unit bytes MATCH`, **8/14 functions in C**; 6 stay `INCLUDE_ASM` (attempts for six of them under `#if 0`, reasons in the source).

## Structs and globals
- `0x02017A40 + 0x502` (low 2 bits) = count, `+0x504` = u16 array (recorded fusion ingredients, hypothesis); `+0x542` = u16 (card id of the fusion target, hypothesis).
- `gUnk_020192E4[p] + 0xC`: a flag byte (bit 5 set by `0x0803CB04`); `+7` bit 3 as in [[code-0803b670]].
- Card numbers above `0x7CF` are normalised with `- 0x7D0` before comparing (a second bank of the same card numbers, hypothesis).

## Matching tricks
- **`goto again;` instead of `for (;;)`** keeps the constants `0x03E703E7` / `0x3E7` loaded inside the loop (no loop-invariant hoisting into r8) in `0x0803CB60`. The unconditional `if (CB28(y) && CB28(z)) return 0;` before the label yields the ROM's "jump into the shared return" layout.
- **`int r = call(); if ((u16)r == 0) return 0; return 1;`** (callee returning `int`, u16-truncated at the test) gives `lsls; cmp; beq` without `lsrs` (`0x0803D0B8`); `if (r != 0) return 1; return 0;` lays the branches out the other way round.
- **`u8 *base = (u8 *)gUnk_020192E4; u8 *ps = base + ref->player * 0xD64; ps[0xC] \|= 0x20;`** gives the ROM's `ldr base` first and `mul const,player` in place (`0x0803CB04`); the struct forms use an extra register.
- **`for (i = 0, e = tbl; i <= N; e += 4, i++)`**: initialiser and increment order decide the `movs`/`ldr` and `adds` order (`0x0803CDEC`).
- **`u16 x = CARD_NUMBER(a); if (x > 0x7CF) x -= 0x7D0;`** gives `cmp; bls; add; lsl; lsr` (u16 subtract); with `int x` there is no narrowing (`0x0803D3D0`).
- **Wrong-signature hint**: `sub_0803CC18` takes 4 arguments; `0x0803D0B8` passes `d` through in r3 (it was the reason `d` got a `lsr` in the ROM).
- **`0x0803CC18` matched** with the same `goto again;`/`u16`-number idiom as `0x0803CB60`, but the three ingredients need an `if (y == e[1]) / else if (y == e[2]) / else if (y == e[3])` chain whose branches share the wildcard tails; keeping the `return 0` (not a loop advance) inside the matched-result branches is what the ROM does. The "no ingredient matched and `b` is not a wildcard" case must fall through to `e += 4; goto again;` (only that path keeps scanning).
- The tricks of [[code-0803b670]] (`int tp = (u8)...`, shared return label, fall-through cases) apply here too.

## Open problems
`0x0803C838` (tz/tp register split), `0x0803CE90` (mask hoisting into r9 in the first two loops only), `0x0803D048` (ROM keeps `player` in r4 and `pos` in two registers), `0x0803D0E8` (register allocation only; parked draft), `0x0803D3D0` / `0x0803D460` (do-while loops with a strength-reduced pointer and `ip`-hoisted table entry), `0x0803D57C` untouched.

A bounded 2026-09-30 `sub_0803D3D0` batch tried counter initialization before the count/base loads, a separate base reused for the walking pointer, `do` loops, both table-read orders, and an explicit invariant pointer to the `num` table entry. Initialized base/entry constraints and a named r4 base did not match. The ROM uses signed `ble` comparisons and has no 16-bit narrowing after either normalization subtraction, so the existing `int x, y` behavior is the correct target here; the `u16` idiom above explains differing codegen and does not by itself match this routine. No failed isolated variant was enabled. Scratch scripts: `build/middle_experiments/fusion_member*.py`.

Fresh `sub_0803CE90` analysis corrected its parked draft: the ROM exact-number hand scan (`0x0803CF26`) performs the 12-bit extract, mask and number lookup without testing `id != 0`; the other three scans retain that test. The old "logic verified" annotation overlooked this distinction. The draft now preserves that ROM behavior, including a possible zero-ID number lookup. Narrow reader/number helper boundaries and explicit mask lifetime grids remain partial: loop-scoped initialized read/write masks restore the complete 0x1B8 size, but still differ by 204 bytes. An initialized pre-loop u16 mask plus an index-first hand-word helper differed by 233 bytes and retained the old guard, so it is not a faithful candidate. No variant was enabled. Evidence: `build/middle_experiments/sub_0803CE90/scoped-mask-diff.txt`; scratch grids `fusion_search_boundaries.py` and `fusion_search_mask_scope.py`.

## `sub_0803D048` matched (2026-10-01)
**Each branch returns its own card load**, and the hand-slot branch computes its offset in a `u16` local. That is lossless, since `0xFFF * 4 + 0xD64 = 0x4D60`. The zone branch uses a `u32` offset. A single shared `off`/`base` pair kept `player` out of r4. The automated type sweep showed that a `u16` offset fixed the allocation, and splitting the branches removes the truncation it caused in the 0x94 branch. The result is ordinary C.
