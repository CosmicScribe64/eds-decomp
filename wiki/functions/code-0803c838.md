## Structs and globals
- `0x02017A40 + 0x502` (low 2 bits) = count, `+0x504` = u16 array (recorded fusion ingredients, hypothesis); `+0x542` = u16 (card id of the fusion target, hypothesis).
- `gDuelPlayers[p] + 0xC`: a flag byte (bit 5 set by `0x0803CB04`); `+7` bit 3 as in [[code-0803b670]].
- Card numbers above `0x7CF` are normalised with `- 0x7D0` before comparing (a second bank of the same card numbers, hypothesis).

## Matching tricks
- **`goto again;` instead of `for (;;)`** keeps the constants `0x03E703E7` / `0x3E7` loaded inside the loop (no loop-invariant hoisting into r8) in `0x0803CB60`. The unconditional `if (CB28(y) && CB28(z)) return 0;` before the label yields the ROM's "jump into the shared return" layout.
- **`int r = call(); if ((u16)r == 0) return 0; return 1;`** (callee returning `int`, u16-truncated at the test) gives `lsls; cmp; beq` without `lsrs` (`0x0803D0B8`); `if (r != 0) return 1; return 0;` lays the branches out the other way round.
- **`u8 *base = (u8 *)gDuelPlayers; u8 *ps = base + ref->player * 0xD64; ps[0xC] \|= 0x20;`** gives the ROM's `ldr base` first and `mul const,player` in place (`0x0803CB04`); the struct forms use an extra register.
- **`for (i = 0, e = tbl; i <= N; e += 4, i++)`**: initialiser and increment order decide the `movs`/`ldr` and `adds` order (`0x0803CDEC`).

## `GetFusionSlotCardId` matched (2026-10-01)
**Each branch returns its own card load**, and the hand-slot branch computes its offset in a `u16` local. That is lossless, since `0xFFF * 4 + 0xD64 = 0x4D60`. The zone branch uses a `u32` offset. A single shared `off`/`base` pair kept `player` out of r4. The automated type sweep showed that a `u16` offset fixed the allocation, and splitting the branches removes the truncation it caused in the 0x94 branch. The result is ordinary C.

## Wave 2 matches (2026-10-01)

### `IsPendingFusionMaterial` (0x90, start score 66; ordinary C)

- The old draft used a u16 pointer local and a hand-written `(u32)byte << 30 >> 30` count. The struct-over-`gChain` form of the matched neighbour `RemovePendingFusionMaterial` (`FL->list[i]`, `i < FL->cnt` re-read in the condition) scored 29: loop.c derives the `+0x504` walking pointer from the base in the pre-header, as in the ROM.
- Score 0 came from declaring the count as `u32 cnt : 2` instead of `u8 cnt : 2`. A u8 bitfield extraction has a QImode subreg step (`lsr 30` into a QI subreg, then zero_extend); loop.c will not move a subreg set, so only `ldrb`+`lsl` got hoisted and the loop kept a `lsr`. The u32 bitfield is plain SImode `lsl/lsr`: the whole chain is hoisted, cse2 turns it into a pre-header copy (`adds r6, r1, #0`), and the entry test stays `cmp r3, r1; bge`.
- Failed: a local `int n = FL->cnt` (32; 28 with `int i = 0` first), which has no pre-header copy.
- Contrast: `RemovePendingFusionMaterial` below matches with `u8 cnt : 2` over the same bytes, so each function keeps its own local struct with the bitfield type its ROM code needs.

### `FindFusionMaterialSlot` (0x1B8, start score 118; ordinary C)

- The card id landed in r0/r1 in every loop (ROM r2), which shifted `pa*0xD64`, the mask and `a+0x7D0` hoists (r9/ip swapped in loop 2, a missing `subs r2,#47` from move2add) and every reload register.
- What matched: one function-scope `u16 id` shared by all four loops instead of a block-local id per loop (this alone put id in r2 everywhere and fixed the hoisted constants); `u16 id` in loop 3 too (u32/int restored the size but gave the wrong `and` shape; the ROM wants the HImode-mask `ldr rX; adds r0,rX,#0; ands`); and the hand word as `*(u32 *)(pa * 0xD64 + i * 4 + (u32)gDuelHands)` (agbcc emits the second term first, so player-first source gives the ROM's `lsls r1,r4,#2` before the multiply).
- The exact-number hand scan has no `id != 0` test, as the earlier analysis above found. Not needed: swapping the mask operand order (`0x7FF & id`).

### `FindFusionMaterials` (0x2E8, start score 250; ordinary C)

- The category test is an inline helper `FusKind_D0E8` with the same shape as `TargetKind` in [[code-08044224]]: `switch (CARD_NUMBER(id)) { case 0x776: return 3; case 0x777: case 0x778: return 1; }`. The case tree emits the ROM's two signed compares (`blt`/`bgt`); an if-range test folds into one `(u16)(n - 0x776) <= 2`. The two-predecessor label also stops CSE (follow-jumps), so the type switch reloads `CARD_STATS` as the ROM does.
- `switch ((int)CARD_TYPE(id))` for the signed `bgt`, case order 0x16 -> 7, 0x15 -> 8, 0x17 -> 9.
- Loops: `for (i = 0, e = table; i <= N; e += 4, i++)` with `u32 i` (as in `IsMaterialOfFusion`, see Matching tricks) and the compare written `num == e[0]` (`cmp r2, r3`).
- Tail in both loops: `if ((out[0] & 0x8000) && (out[1] & 0x8000) [&& out[2] ...]) { if (CountMonsters(player) == 5) return 0; } return 1;`; cross-jumping merges the tails as in the ROM.

### `RemovePendingFusionMaterial` (0x11C, start score 105; ordinary C)

- Matched on the first try with plain source. The old draft used `u16 i` (narrowing after each increment), hand-written do-while loops with a walking pointer and a hand-written `(u32)byte << 30 >> 30` count.
- A local struct over `gChain` with `u8 cnt : 2` at `+0x502` and `u16 list[3]` at `+0x504`; both loops are plain `for (i = 0; i < FL->cnt; i++)` with `int i` indexing `FL->list[i]`. Loop 1 reads `y = CARD_NUMBER(list[i])` before `x = CARD_NUMBER(num)`, normalises x first and compares `y == x`.
- The compiler does the rest: loop inversion gives the `(byte << 30) != 0` entry test, strength reduction makes loop 1's walking pointer (initialised after the hoisted invariants), and loop 2 calls functions, so its address is recomputed from `i` every iteration.
