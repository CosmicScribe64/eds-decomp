# Unit code_0803FE70

`0x0803FE70`-`0x08040EBB`, Thumb, `old_agbcc -O2`. Source: `src/code_0803FE70.c`. Sits after [[code-0803c838]] / `code_0803DD7C` (helper `sub_0803DD7C` appends a target word to `ref->targets[numTargets++]`, and `sub_0803DDAC(ref, player, zone)` validates and adds a chosen zone). Every function here is a **target selector** `int f(struct CardRef *ref)` for one card effect: it returns 1 when the selection is finished (targets stored in the `CardRef`, or none possible) and 0 while it waits for the player. State byte: **`0x02017A40 + 0x3E5`** (step 0 shows the prompt text with `sub_080602A4(0x206, 0x712, 0xB, text)`, step 1 and later wait for input, and the byte resets to 0 when the B/cancel bit `gMain+6 & 2` is seen).

Unit status: `unit bytes MATCH` (0x104C bytes), **15/17 functions in C**; 2 remain `INCLUDE_ASM`. Verified with `tools/check.py code_0803FE70` on 2026-09-30 after enabling `sub_08040110` and `sub_08040D84`.

## Structs and globals
- `CardRef` (see [[code-08030b88]]): `+3` byte (flags, `& 0xFC` used), `+8` u16 (`>> 8` used), `targets[3]` at `+0xC`.
- Cursor of the duel screen `gUnk_0201CFB0`: `+0x824` is the player and `+0x828` plus `+0x82C` give the zone (row and column). Every selector uses them.
- `gUnk_020192E0 + 0x1B64` u16 / `+0x1B66` u16: results of the last prompt (`sub_08022678`).
- `0x03000040 + 6` (u16): input flags, bit 1 = cancel; `+0x4872` u16: text-entry result.
- Selector step byte `0x02017A40 + 0x3E5`; `0x3E6` / `0x3E7` cleared by `0x080408B4`.
- `sub_0800C8BC(player, zone)` returns a small monster attribute/class (compared with 7); `gUnk_0822C720[n]` holds 0x40-byte card names.

## Matching tricks
Most of these apply to every selector of this family. See also [[code-08040ebc]].
- **`u8 *es = gUnk_02017A40; u8 *st = es + 0x3E5;`** gives the unfolded `ldr; ldr; adds` step pointer. A direct `gUnk_02017A40[0x3E5]++` (statement, not `&x[..]`) also gives the pair form and is what the ROM uses when the pointer must not live across a call (`0x080408B4`: every case re-materialises it; `0x0803FE70`).
- **Write the shared `(*st)++; return 0;` tail into every case (no `goto inc`).** gcc's cross-jumping then merges the tails exactly like the ROM (which block survives, whether the text calls `sub_080602A4(0x206, 0x712, 0xB, X)` get merged, and which of ref/st gets r4 vs r5 all follow from this; with `goto` the register priorities came out swapped). Matched `0x08040B14`, `0x080409E0`, `0x080408B4`; a case that never increments (returns 1) changes which tail survives.
- **`int z = 0;` (declared inside the cancel block, after any pointer) and `*st = z; return z;`** reproduces `movs r0,#0; strb r0,[st]; b end`; the other `return 0`s stay plain.
- **Target word `(u8)p | (u8)zn << 8` in this operand order, stored in a `u16 w`** (`0x080409E0`, `0x08040FB0` in the next unit); `(u8)zn << 8 | (u8)p` schedules the shifts differently. For the `((1 - p) << 24 >> 8 | (u32)zn << 24) >> 16` form the extra parentheses around `((u32)zn << 24)` matter (`0x08040110`).
- **`u32 p = w824;` declared before `int zn = w828 + w82C;`** makes gcc compute the address of `w824` first but load it after the sum (D00-style ordering).
- **`ZB2(pl, zn)` with `int pl = 1 & p;` first** matches the z-first multiply order in `0x08040040`.
- **`gUnk_0822C720[idx]` as `const char [][0x40]`**, and for a pointer held across calls a local `u8 *mv; ... mv = (u8 *)&gUnk_03000040; r = (u16 *)(mv + 0x4872);` assigned late gives the `ldr; ldr; adds` order (`0x080408B4`).
- **Uninitialised local** (`int keys;` assigned in only two `case`s of a `switch`) reproduces a call argument left over in r2 on the default path (`0x08040110`).
- **`switch` whose `default` shares the ROM's `return 1`**: put `default: return 1;` last and let case 3 fall out of the block. gcc merges the `return 0` paths.
- **Beware stale files.** Docker sometimes compiles the previous version of a file that was just rewritten. A script that rewrites a file and immediately runs `check.py` should sleep about 1.5 s. Several false "match" and "error" results in early experiments came from this.

## Open problems

Remaining `INCLUDE_ASM`: `sub_08040294`, `sub_08040478`. Each keeps its original assembly; decoded drafts and current mismatch notes remain guarded by `#if 0` in the unit source.

For `sub_08040478`, a bounded 2026-09-30 batch checked the matched `sub_0803DFE4` sibling and [[code-0803dd7c]]'s id-width trick. `CARD_TYPE((u16)id)` improves the baseline but does not supply the ROM's fourth invariant. An initialized `0x7FF` mask passed through an empty read/write constraint inside the first loop does hoist that mask and recovers the `0x16C` size. It remains 78 differing bytes: the three high-register invariants rotate (base r9, one r8, stride ip, versus ROM ip/r9/r8), and the second loop still reuses them rather than rematerializing the ROM's player-base calculation. Declaring the mask before the outer loop, naming it r7, moving it before the id load, and initialized player-base constraints did not match. Pointer increment before counter increment recovers the second loop's update order. None of these failed isolated variants was enabled; scratch scripts are `build/middle_experiments/trap_selector*.py`.

## Verified C conversions (2026-09-30)

- `sub_08040CA8`, Thumb, `0xDC` bytes, matching C. It is the target-selection prompt and input handler. Named r1/r2/r3 locals preserve format, scaled card-name index and name-table address; integer addition with the index first reproduces the add operand order.
- `sub_08040110`, Thumb, `0x184` bytes, matching C. The second branch clears the low three bits of `ref` byte `+0xA` using a named `r1` byte local and an empty asm input constraint. This reproduces the target-count bitfield update's scratch register. The compiler-only hint is marked FAKEMATCH in source and emits no instructions.
- `sub_08040D84`, Thumb, `0x138` bytes, matching C. An empty input constraint on the shifted player bit keeps that load before the zone-index multiplication. A static inline address helper constrains the opponent-stride product before adding `offset + product + base`, reproducing both address-sum operand orders. Returning the same local zero stored during cancellation branches directly to the epilogue. Both compiler constraints are marked FAKEMATCH and emit no instructions.

The compiler hints emit no instructions. Each conversion passed a whole-unit byte comparison with the baserom; remaining assembly functions retain their original bytes. Earlier notes describing these functions as allocation near misses are resolved by the matching C above.

The source also contains the verified matching C for `sub_0804067C`. Status counts and function-table rows above reflect those recovered matches.

## `sub_08040110` dispatch restriction (verified 2026-09-30)

The ROM sets its input-key mask only for card numbers `0x431` and `0x525`; the other switch path passes the existing `r2` value to `sub_08052F38`. The decompiled routine preserves this existing behavior rather than adding a default value.

Scanning all 426 records (`0x18` bytes each) of the effect table at `0x0819A9D4` for selector pointer `0x08040111` in field `+0x14` found exactly two entries: record 216 at `0x0819BE14`, key `0x431`, and record 327 at `0x0819C87C`, key `0x525`. The matching `sub_08051098` looks up the effect index using `sub_08047058(id45C)`, loads this `+0x14` callback, and invokes it with the working and other `CardRef`. This verifies the table dispatch's card-number restriction; it does not claim every conceivable direct caller is constrained. There are no direct calls to this function in the current disassembly.
