## Matching tricks
- Write `if (a == 0 && b == 0) return 0; return 1;`, not `if (a || b) return 1; return 0;`, to reproduce the layout with `mov r0,#0; b` first (`0x080431E4`, `0x08043230`).
- **`(x0 + i * 10) | (y << 16)`** in a loop that also calls: the strength-reduced giv is initialised from `x0` in the preheader and `y << 16` stays in the loop only with this operand order (`0x08043758`). Loop index into a byte at `0x02017A40+0x510` (offset written as `0xA2 << 3`, which is 0x510, not 0x512).
- **`int y = expr << 3; y += 8;`** keeps a single `lsls; adds` pair.
- **A struct of at most 4 bytes** is read as a whole word by old_agbcc; pad bitfield structs to their real size (`u8 rest[..]`) so the fields are read with `ldrb`/`ldrh`.
- **Hoisting**: old_agbcc's loop-invariant motion decides which of `0x7FF`, table literals and `p*0xD64` end up in registers. Historically `0x080436B8` and `0x0804325C` hoisted a different subset than the C forms tried; both matched in waves 2-3 (see below). The former `0x08043600` obstacle is resolved by the inline helpers below.
- **Ordinary C replacement for prior hints** (`0x08043600`): the old long-long table address and dead `u16 new_var` copy improved the parked draft but are absent from the accepted source. `GetRecipeCardLevel(u16 id)` supplies the narrow boundary and constant-pointer accesses. `GetRecipeHandWord` stages the player byte offset and reads `idx * 4 + off + base + 0x684`, reproducing the preheader's hand-base construction before the offset copy. A separate cost local accumulated as `c += total; total = c;` fixes the last reversed `adds` operands; `total = c + total` is still two bytes off.
- **Separate initial guard from loop indexing** (`0x0804353C`): use local `p` only in the initial nonempty-table guard, then direct `gUnk_0819A990[i]` accesses in both the loop condition and equality. Combined with `((const u16 *)0x08622AB4)[id & 0x7FF]`, this preserves the ROM's two induction pointers and exact allocation. Merely changing the card-map expression left 40 differing bytes.
- **Ordering and a proven narrow local** (`0x08043594`): declare the hand-word read before the recipe key. The key helper initializes `base`, initializes `off = idx * 4`, then reads the halfword at `base + off` and masks its low 13 bits. Store that result in `u16 a`; a `u32` local leaves ten differing bytes. Narrowing is lossless because the helper returns at most 8191. The hand loop counter remains `u16`, matching its explicit truncation.
- **Class helper and address staging** (`0x0804412C`): a switch on card numbers 0x776/0x777/0x778 produces the correct two range comparisons. Constant-pointer stats accesses avoid a hoisted table. Returning the class through `s8` is lossless (all paths return 0-9) and keeps every class path entering the common signed test without an empty asm input. Both successful exits use one final `yes` label. The list reader separately initializes `p = player & 1`, `idx4 = idx * 4`, and `off = p * 0xD64`, then loads `idx4 + off + base`; combining `p` and the multiplication left eight differing bytes.
- Historical (matched in wave 2, see below): `0x080436B8`: unlike `0x08043600`, the ROM there deliberately spills `p & 1` and `0x7FF` to the stack around the `sub_08008A6C` call; every C draft keeps them in `r8`/`r9` instead, and the permuter could not force the stack form.
- **Trick sweep (2026-09-30), no match**: for `0x0804325C`, `0x08043600`, `0x080436B8`, `0x08043AA8` the proven fakematch tricks were tried in the source and checked with `check.py --diff`: (1) re-read the field/global at each use, (2) route one address use through `unsigned long long tmp = addr; (T *)(u32)tmp`, (3) rewrite the `for` as a `goto` loop with manual induction (`i = 0; if (i < n) { loop: ...; i++; if (i < n) goto loop; }`), (4) cache invariants in locals declared at the top, (5) wrap register sequences in `do { ... } while (0)`, (6) reorder local declarations/first uses. ### `sub_0804325C` (0x2E0, recorded start score 0; FAKEMATCH)

The recorded start score 0 is a bookkeeping artifact, not a byte-identical draft blocked elsewhere: `prep.json` was rewritten at 00:55, two minutes before the apply, when the working copy already matched (hypothesis from the file timestamps; `prev_session_unit.c` shows the work spanned two agent sessions). 1. **0x7FF hoist and the loop.c threshold.** The inner zone loop must stay at 245 RTL insns or fewer at loop time. 3. **FAKEMATCH zone-base pin.** As hoisted constants with REG_EQUIV notes, the base and 0x7FF get their live length doubled (local-alloc `update_equiv_regs`), which ranked the base below the multiply (base sl, multiply r9). `register u32 zb asm("r9")`, set in the `for` init after `p = 0`.
4. **The last step (8 to 0):** the `r == 0` b91 test goes through `Zone325C(p, z, zb2)`, where `zb2 = (u32)gUnk_0201930C` is a top-level local that gets spilled. Its load is then a round-robin reload, which advances `last_spill_reg` so that the 0x409 check picks r1/r2 as in the ROM; every other base form gives r0/r1.
5. The b6 store needs the AND operands in the order (constant, value): call `((u16 (*)(void))sub_08043230)()` (FAKEMATCH comment in the source; the callee probably returns `u16`).
6. Smaller: the `id` copy after `r = 0` is a re-read of `CARD_ID(zn->w0)` that CSE turns into a copy; the subtype switch is a GetMagicSubtype-style inline `Sub325C` with a `stats` local; tables are constant pointers so GCSE does not merge their loads.
- Failed: a `mask` variable for 0x7FF (GCSE merges the `(and id mask)` uses), bitfield flag tests (same RTL as `u8 & const`), `s16 r` (store-flag, but six sign-extension insns), other forms of the b6 store. Tools: `exp.sh` (score plus loop.c move decisions), `sbs.py` (side-by-side `.s`). See [[matching-tricks#Register allocation priority and reload rotation]].
