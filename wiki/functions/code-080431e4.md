## Matching tricks
- Write `if (a == 0 && b == 0) return 0; return 1;`, not `if (a || b) return 1; return 0;`, to reproduce the layout with `mov r0,#0; b` first (`0x080431E4`, `0x08043230`).
- **`(x0 + i * 10) | (y << 16)`** in a loop that also calls: the strength-reduced giv is initialised from `x0` in the preheader and `y << 16` stays in the loop only with this operand order (`0x08043758`). Loop index into a byte at `0x02017A40+0x510` (offset written as `0xA2 << 3`, which is 0x510, not 0x512).
- **`int y = expr << 3; y += 8;`** keeps a single `lsls; adds` pair.
- **A struct of at most 4 bytes** is read as a whole word by old_agbcc; pad bitfield structs to their real size (`u8 rest[..]`) so the fields are read with `ldrb`/`ldrh`.
- **Hoisting**: old_agbcc's loop-invariant motion decides which of `0x7FF`, table literals and `p*0xD64` end up in registers. `0x080436B8` and `0x0804325C` still hoist a different subset than the C forms tried (see NONMATCHING notes in the source). The former `0x08043600` obstacle is resolved by the inline helpers below.
- **Ordinary C replacement for prior hints** (`0x08043600`): the old long-long table address and dead `u16 new_var` copy improved the parked draft but are absent from the accepted source. `GetRecipeCardLevel(u16 id)` supplies the narrow boundary and constant-pointer accesses. `GetRecipeHandWord` stages the player byte offset and reads `idx * 4 + off + base + 0x684`, reproducing the preheader's hand-base construction before the offset copy. A separate cost local accumulated as `c += total; total = c;` fixes the last reversed `adds` operands; `total = c + total` is still two bytes off.
- **Separate initial guard from loop indexing** (`0x0804353C`): use local `p` only in the initial nonempty-table guard, then direct `gUnk_0819A990[i]` accesses in both the loop condition and equality. Combined with `((const u16 *)0x08622AB4)[id & 0x7FF]`, this preserves the ROM's two induction pointers and exact allocation. Merely changing the card-map expression left 40 differing bytes.
- **Ordering and a proven narrow local** (`0x08043594`): declare the hand-word read before the recipe key. The key helper initializes `base`, initializes `off = idx * 4`, then reads the halfword at `base + off` and masks its low 13 bits. Store that result in `u16 a`; a `u32` local leaves ten differing bytes. Narrowing is lossless because the helper returns at most 8191. The hand loop counter remains `u16`, matching its explicit truncation.
- **Class helper and address staging** (`0x0804412C`): a switch on card numbers 0x776/0x777/0x778 produces the correct two range comparisons. Constant-pointer stats accesses avoid a hoisted table. Returning the class through `s8` is lossless (all paths return 0-9) and keeps every class path entering the common signed test without an empty asm input. Both successful exits use one final `yes` label. The list reader separately initializes `p = player & 1`, `idx4 = idx * 4`, and `off = p * 0xD64`, then loads `idx4 + off + base`; combining `p` and the multiplication left eight differing bytes.
- `0x080436B8`: unlike `0x08043600`, the ROM there deliberately spills `p & 1` and `0x7FF` to the stack around the `sub_08008A6C` call; every C draft keeps them in `r8`/`r9` instead, and the permuter could not force the stack form.
- **Trick sweep (2026-09-30), no match**: for `0x0804325C`, `0x08043600`, `0x080436B8`, `0x08043AA8` the proven fakematch tricks were tried in the source and checked with `check.py --diff`: (1) re-read the field/global at each use, (2) route one address use through `unsigned long long tmp = addr; (T *)(u32)tmp`, (3) rewrite the `for` as a `goto` loop with manual induction (`i = 0; if (i < n) { loop: ...; i++; if (i < n) goto loop; }`), (4) cache invariants in locals declared at the top, (5) wrap register sequences in `do { ... } while (0)`, (6) reorder local declarations/first uses. None changed the allocation to the ROM's. `0x08043600` stays 2 instructions off (preheader emission order + `adds r6,r0,r6` vs `adds r6,r6,r0`); the others are 70-340 diff lines. Caveat: `0x0804325C` / `0x08043AA8` diffs shift once sizes differ, so count hunks, not raw lines.

The preceding sweep is historical, because the later ordinary-C `sub_08043600` match supersedes its two-instruction limitation. A later bounded probe of `sub_080436B8` reused the level helper and staged zone reader, including `int`/`u8`/`u16` inline argument and `u32`/`u16` result/local combinations.
