## Structures and tables (hypotheses)
- **`gUnk_0819A9D4`** effect table: 24-byte entries: `u16 cardIdx` (+0), handler function pointer at **+8** (`u16 fn(ref, u16 posBytes)`, 0 = none), rest unknown. Sorted by `cardIdx`, 0x1AA entries.
- **`0x08622AB4`** maps an internal card ID (low 11 bits) to a card number/key, as in [[code-080431e4]]. `0x08623DF4` performs the reverse lookup used for card names and announcements.
- Player struct at `0x020192E4` (0xD64 bytes): `+2` hand count, `+6` count of a second list at `+0xB84`, `+7` flag byte (bit 3, bit 4 tested), hand list at `+0x684` (as in [[code-080431e4]]).
- Zone at `0x0201930C + p*0xD64 + z*0x94`: `w0 & 0xFFF` card number, byte `+6` flags (bit1 face-down; bits 2-5 an index 0-3 in `sub_08046D3C`).

## Matching tricks
- **Table lookup with a constant index kept in a register (`lsl r0,r6,1; ldr r1,=tab; add`)**: write the table as a **cast literal** `((const u16 *)0x08623DF4)[id]` with `u32 id = 0x475;` also passed as call argument. The symbol form `gUnk_08623DF4[id]` swaps the add operands. Same for `0x08622AB4` (index `(id << 21) >> 21`).
- **`(u8)a | (u8)b << 8`** with `int` params reproduces `lsl 24; lsl 24; lsr 8; orr; lsr 16` (a two-byte pos argument); the shift-and-mask forms give the wrong order.
- **Many `&&` tests on the same constants**: `if (a == 0 && b == 0 ...)` lets gcc rewrite `0x5F6` as `r4 + 16`; write early-`return 0` statements (`if (f() != 0) return 0;` chain) to force the separate literal loads.
- **Bitfield struct of 4 bytes or less is read as a whole word**: pad it to the real size (`u8 pad[6]; u8 lo:2, kind:4, hi:2; u8 rest[..]`) to get `ldrb`.
- **`switch` on a bitfield** gives the signed `cmp/bgt` decision tree; use an `int t = ...` local for the `switch (t)` of `sub_08046F20` (unsigned expression gives `bcc/bls`).
- **Zone address, separate base (found in [[code-08048fe0]])**: `int s1 = z * 0x94 + (p & 1) * 0xD64; zn = (T *)(s1 + 0x0201930C);` matches the loop form of `sub_08046808` (only p+1/pofs registers still swapped). The prologue form of `sub_08046738`/`sub_08046CB0` matches with a symbol-backed byte base (see below).
- **Zone address** `zone*0x94 + (p&1)*0xD64 + 0x0201930C` in byte arithmetic (inline `(p & 1)`, not a temporary) matches inside loops (`sub_08046808` hoisting of `1`/`0xD64`), but as a standalone prologue (`sub_08046738`, `sub_08046CB0`) the ROM copies `zone` before multiplying and puts `p&1` in r1; the separate symbol-backed base below reproduces it.
- **Standalone zone address (`sub_08046738`, `sub_08046CB0`)**: compute `int s1 = zone * 0x94 + pi * 0xD64`, then use a separate **symbol-backed** byte base `u8 *zb = (u8 *)gUnk_0201930C; z = (struct DuelZone *)(s1 + (int)zb);`. This reproduces the zone-copy multiply and register allocation; the literal address form does not.

### Earlier state-domain evidence and semantic blocker (2026-09-30)

The matched command-menu handler `sub_0801DC04` in [[code-0801ce68]] resets the command substate (its `SEL.unk34`, the draft's `step`) to zero when A confirms a command. Within `sub_080471E8`, the only explicit entry to state 40 is card number `0x34D` in state 0, which first writes `sequence = 0`. State 40 preserves the sequence and advances to 41. State 41 increments it only after a matching selected card; it returns to 40 only while the new value is at most 2, and otherwise advances to 42. Thus the observed transition graph supports the valid domain 0..2. State 70 is likewise entered from state 0 only for card numbers `0x5EC`..`0x5EF`.

> [!warning] Unresolved invalid-state behavior
> For sequence values 3..15, the state-40/41 assembly switches do not assign the required-card register and continue with its incoming value. The parked draft returns on this path, so it is **not semantically equivalent for arbitrary state memory**. For state 70 with an unrelated card number, the ROM consumes text it did not populate; the draft returns. The local transition graph does not by itself prove that every external writer/callee preserves the invariant. Keep the assembly fallback until the domain, original variable lifetimes, and whole-unit bytes are all resolved. No invented uninitialized register scaffolding was enabled.

A private experiment removed these guards to study the apparent original switch lifetimes, then represented the player flag through a field at offset 0x10. Its best diagnostic reached 692 normalized differences and 15 matching-shape chunks (adding state 58), but remained 0x1E20 bytes and unresolved on invalid inputs. It was **not installed**. Separate per-case required-card locals were worse (710 or 1,165 differences); simply changing signed/unsigned bit tests also regressed codegen. Evidence: `anchor_domains.log`, `anchor_lifetimes.log`, and `lifetime1.report.json`. The guarded source reconstruction is retained to make future work reviewable.
