# Unit code_0804A008

`0x0804A008`-`0x0804B63F`, Thumb, `old_agbcc -O2`. Source: `src/code_0804A008.c`. Comes after the target-selection units ([[code-080431e4]]). It works on the *battle state* `gBattle` (`0x02018450`, see [[code-0801ce68]]), the per-player duel state `0x020192E4` (+0x24 `lp`-related word, `+0x26` mask of used zones) and the "selection widget" `0x020192E0+0x1B2C` (`struct SelMask`, [[code-0801ce68]]). A step counter `cnt` lives in bits 1-8 of the halfword at `0x020192E0+0x1B16`; a second field `stage` at bits 9-16 of the word `0x020192E0+0x1B14`.

Unit status: `unit bytes MATCH`, 7/13 functions in C, covering 0x5A4 (1,444) bytes; 6 stay `INCLUDE_ASM` (complete decoded drafts of 5 under `#if 0`, `0x0804AE64` not attempted). A permutation search of declaration orders / loop shapes for `0x0804A848` (144 variants) and of declarations for `0x0804A528` (48 variants) found no match.

## Structs and globals
- `struct DuelZone` (0x94): `+0` card word (11-bit id in `<<21>>20` form for the number table, 12-bit in the zone), `+6` bit 0 / bit 1 flags, `+7` flags (bit 2, 4, 5), `+0x8C` byte (mask 0x18), `+0x90` word (bits 5-9 attribute), `+0x91` flag byte.
- `0x020192E4 + p*0xD64`: `+0` u16 (life-point-like value, compared with 500 * n), `+8` byte (bit 6), `+9` byte (bit 4), `+0x24` u16 mask of selectable zones, `+0x26` u16 mask of used zones, zones from `+0x28`.
- `gBattle` `0x02018450`: byte 0 bit 1 (direct), bit 2, bit 3/4 (step flags), bit 5, `atkSlot` bits 6-8, `defSlot` bits 9-11 of the halfword; `+0x148` / `+0x14C` u16[2] per-player values.
- `0x020192E0 +0x1B10` u16, `+0x1B12` byte, `+0x1B14` word (`stage` bits 9-16), `+0x1B16` halfword (`cnt` bits 1-8), `+0x1B26` bit 0, `+0x1B2C` `SelMask`.

## Matching tricks
- **Bitfield read via a struct with padding**: `struct X { u16 a:6; u16 z:3; ... }` accessed through a bare 2-byte global compiles to `ldr` (word) + shifts; adding `u8 pad[0x20]` (struct larger than the access) gives the ROM's `ldrh; lsl 23; lsr 29`.
- **`x->cnt++` on a u16 bitfield** gives `lsl 23; lsr 24; add 1; and 0xFF; lsl 1; and mask; orr` exactly like the ROM; `x->cnt = x->cnt + 1` does not.
- **Local `struct DuelGlobal *e = &gUnk_020192E0;`** (used more than once) gives the unfolded `ldr sym; ldr =0x1B12; add`; `(u8 *)e + 4` after the call keeps `adds r2, #4` in front of the multiply when written as `ps0 = (..)((u8 *)e + 4); ps = ps0 + (player & 1);`.
- **`(b << 27) < 0`** for a bit-4 test of a byte gives `lsl 27; cmp 0; bge` (the ROM form) where a bitfield or `& 0x10` would not.
- **`u32 pl = player & 1;` declared before `ZB(pl, zone)`** gives the ROM's early `and` and z-first multiply.
- **`ZB(...)` in place of a `zn` variable** and a `const u16 *` table access written as `*(u16 *)((u8 *)tbl + ((word << 21) >> 20))` reproduce the table load (the loop-hoisting of the table base differs otherwise, `0x0804A47C`).
- **Byte RMW after a raw test** (found in [[code-0804b640]]): `if (!(*(u8 *)&gBattle & 0x10)) { gBattle.f4 = 1; ..}` reuses the tested byte and gives `mov r0,#0x10; orr r0,r1`.
- **Bitfield clear of one flag** (`x.f5 = 0`) gives the ROM's `mov r0,#n; neg r0,r0; and` (int mask); `b & ~1` on a `u8` gives `mov r0,#0xFE`.
- **Cross-jumping is not controllable from C**: whether the ROM merges call sequences and which block of two identical tails survives (first versus last) decided `0x0804A008`, `0x0804A1C8`, `0x0804AC18`.
- **`fd = id = 0`** is optimised away; register choice for such dead copies is not controllable.

## Open problems
`0x0804A008` / `0x0804AC18`: cross-jumping (the ROM shares only the call, the tail sits in the last case; ours keeps the first block). `0x0804A848`: allocation of player/zero/g among r8/r9/sl. `0x0804A99C`: ROM re-derives `(lsr 29)` from a cached `(lsl 23)` for each zone access. `0x0804A1C8`: separate `flag0 = 1` stores per case.

## Ordinary C selection-check match (2026-09-30)

`sub_0804A528` now matches without assembly constraints. The required combination is a `u16` local card ID and a `u16` argument to the inlined `DuelCardNumber` helper, which uses the literal table pointer `((const u16 *)0x08622AB4)`. Narrowing the local alone left the original ten differing bytes; narrowing the helper alone made allocation worse. Together they reproduce the ROM's table-base registers, flag reload, and final zero assignment. The card ID comes from a 12-bit extraction, so narrowing is lossless. The public `u16 (int player, int zone, u16 flag)` ABI remains unchanged.

The accepted function extent is 0x320 (800) bytes, including the two-byte alignment after its 0x31E-byte body. `tools/dr python3 tools/check.py code_0804A008` verifies 13/13 function slices and all 0x1638 unit bytes. Evidence: `build/bigguns-duel48/code_0804A008/a528_shapes.log`, `sub_0804A528.EXACT.c`, and `accepted-check1.txt`. The other six functions remain assembly fallbacks.
