# Unit code_0804B640

Continues [[code-0804a008]]: the same battle state `gBattle` (`0x02018450`), step counter `cnt` (halfword `0x020192E0+0x1B16` = `0x0201ADF6`, bits 1-8) and `stage` (word `0x020192E0+0x1B14`, bits 9-16). Unit status: `unit bytes MATCH`, **5/5 functions in C**, covering all 0x1518 (5,400) bytes. No `INCLUDE_ASM` fallbacks remain. The two final conversions add 0xEE0 (3,808) bytes of accepted C.

## Matching tricks
- **`if (!(*(u8 *)&gBattle & 0x10)) { gBattle.f4 = 1; ...`**: the raw byte test and the bitfield set compile to one `ldrb`, then `mov r0,#0x10; orr r0,r1; strb` (the loaded byte is reused for the read-modify-write). A separate `u8 b` local or `b | 0x10` gives `orr r1,r0`.
- **Card-number table with a variable index**: `u16 no; ... sub_08008524(p, no = 0x427); ... ((const u16 *)0x08623DF4)[no]` keeps the `lsl r0,r5,#1` index arithmetic (same trick as in [[code-08019554]]).
- **Field arrays through a struct view** (`struct BattleFull { ...; u16 lp[2]; u16 unk4[2]; }` at `gBattle+0x148/0x14C`, accessed as `BF.lp[i]`, `BF.unk4[i]`) gives the ROM's strength-reduced pointer for the second store only.

## Resolved snapshot and stage matches (2026-09-30)

Both `sub_0804BAAC` (0x1CC / 460 bytes) and `sub_0804B640` (0x3DC / 988 bytes) now match in ordinary C, with no assembly constraints. Their public `int (int player)` ABIs remain unchanged. Together they add **1,448 bytes / two functions**.

- The shared `SnapshotZoneValue` inline helper separates `player & 1`, `zone * 0x94 + playerOffset`, and the symbol-backed zone base before reading the halfword at +4. This recovers the original multiply order and the loop's strength-reduced store pointer. The counter immediately after BAAC's loop is addressed relative to the already-used zone symbol.
- BAAC explicitly interprets `sub_0804A99C`'s result as `u16`, as shown by the ROM's post-call shift. Its event packer accepts the card ID as `u16` and the event kind separately; shifting kind `0x202` by 20 inside the inline helper preserves the original grouped ORs and argument-evaluation lifetimes. Hard-coding the shifted constant in the expression left 15 differing bytes.
- B640's stage field at `0x020192E0+0x1B14`, bits 9..16, needs a **u16 value container** even though the memory access spans a word. It generates the ROM's shift/narrow/add sequence for `stage += 8`. The full-offset view must cast the existing global symbol; a separate extern with an asm alias prevented the compiler from sharing the base with the counter reset.
- A `u16` coin-result local preserves the original fresh mask load instead of hoisting constant 1 into an extra high register; its value is already restricted to 0 or 1. The selected card ID and inline number lookup likewise use `u16`. State 100's positive nested condition, and cursor packing with the area byte as the first OR operand, recover the original branch layout and instruction order.

The older B640 draft referred to an undefined `STAGEE`; the accepted full-offset view resolves that missing reconstruction detail. The helper and structure experiments stayed private until the entire unit matched.

## Accepted large battle-machine match (2026-10-01)

`sub_0804BFF0` now matches all 0xB68 bytes and is active C. This resolves the parked drafts above.

1. Stage the first byte update explicitly: assign mask 127, mask the zone, form the byte pointer, shift the masked zone, initialize the retained byte to 1, load the old byte into the mask variable, then AND/OR/store. Binding **only the u32 mask to r1** makes old_agbcc retain the zone in r2 and the updated byte in r3. Binding every temporary initially recovered the mask sequence but introduced extra narrowing; removing the unnecessary bindings reached eight differing bytes. The mask and staging have explanatory `FAKEMATCH` comments.
2. Immediately before the high-byte setter, use `asm("" : "=r"(freshOne) : "0"(1), "r"(zone >> 7));`, then pass `freshOne - player` to `FinishDestination`. Operand `"0"` ties the constant input to the output register, so the empty template leaves `freshOne` initialized to exactly 1. Consuming the high bits at the same boundary puts the shift and `ip = 1` before the high-byte pointer setup. This removes the last eight differing bytes without a hard binding for `freshOne` or any emitted assembly instructions.

The original initialized halfword input constraint remains. All hints are marked `FAKEMATCH`; the public int ABI and neighboring packed bits remain intact. The cached first byte is used only before `sub_08019078`; the battle defender field still uses fresh byte reads after that call.
