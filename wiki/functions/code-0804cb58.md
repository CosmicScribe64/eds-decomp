## Structures (hypotheses)
- Battle state `0x02018450`: `u16 +0`: bit 2 flag, bits 6-8 attacker zone (`atkSlot`), `+1` bits 1-3 = defender zone; `+2` u16 card; sides at `+8` stride 12: byte 0 (bit 3 = destroyed?, bit 6), `+2` card id, `+0xA` damage.
- Per-player flag byte at `0x020192E4 + p*0xD64 + 8` (bit 0, bit 1 = effects that block damage effects).

## Matching tricks
- **Message word `A | (B | K) | id`** (`BattleStage_TriggerFlipEffect`): `u32 ev = A; u32 b = slot << 16; b |= K; ev |= b; ev |= id;`, one statement each, gives the ROM's order (one expression is reassociated and loads `K` first).
- **Bitfield sign tests**: `s8 f : 4` and `< 0` gives `lsl 28; cmp 0; blt`; for two different tests of one byte use `u8 raw` and `(int)(raw << 28) < 0`.
- **`1 - p` written inline** everywhere instead of a local `q` lets `p` take r7 in `BattleStage_InflictDamage` (with a `q` local `p` is spilled to r8).
- Two separate pseudos for `e`: `u8 *e = sym` for the initial switch value and another `e2 = sym` in the default arm reproduce the ROM's `ldr r0,=sym; ldr r2,=0x1B16; add r1,r0,r2 ... adds r3,r0,#0` prologue shape (register number still differs).
