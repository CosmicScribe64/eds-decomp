## Matching tricks
- **Invert the layout with an early return:** `if (*s == 0) { ...; return 0; } ...; return 1;` with `struct Duel *d = &gUnk_020192E0; u8 *s = &d->step;` matched `0x0805232C`/`0x08052560` (the direct `if (step != 0)` form compiled with the branch reversed, and a `&gUnk...step` pointer without the struct local made gcc use a single literal).
- **Solved puzzle (the three key callbacks):** a `local k = gUnk_03000040.keys;` makes the last `if (k & 1)` come out as `ands r1, r0` (result in k's register) because the and's destination is tied to the first, now-dead operand. **Read the member directly in every test** (`if (gUnk_03000040.keys & 0x20)`, `& 0x10`, `& 1`) instead: CSE keeps one load and the two earlier tests keep the const as the and's destination (`movs r0,#32; ands r0,r1`) because k is still live, so the last test matches the ROM too. That single change converted `0x080522C0`, `0x0805243C` and `0x080524A8` (checked with a scratch probe, `old_agbcc -da` RTL dumps to confirm the operand roles).
- **Ternary instead of a `msg` local, and sum before load (not enough, but needed):** in `0x08051DF4`, `sub_0801EC58(player != 0 ? 0x8008 : 8, ...)` instead of `u32 msg; msg = 8; if (player) msg = 0x8008;`, and `u32 b = *pb + *pc;` *before* `u32 a = *pa;`, both change the allocation (`a`/`b` land in r9/r8 as in the ROM) and shrink the diff to the three field-address registers.
- **`switch` on the step for a 3-step machine:** `0x080525C4` only matched as a `switch (*step)` with `case 0/case 1` and the store after the switch; the flat if/else-if chain made gcc inline the step-0 block (`bne`) instead of branching to it (`beq`).
- **Duplicate the tail into every branch** (`sel += n; sel = sel % m; timer = 0; return 0;` in each key arm, final `return 1/0`) gives the ROM's cross-jumped layout (`0x080522C0`).
- **`*t <= 0x3F` and `(*t >> 2) & 1` on the same `u8 *t`** (no local copy) reproduces the `lsl 24; lsr 24` narrowing in `0x08052668`.
- **Sprite helper calls** `sub_080761F0(yx, shape, attr2)` with `yx = x | (y << 16)`; `0x08052390` matched straight from the natural expression.
- **Still open:** `0x08052190`/`0x08052668` only differ in which value keeps a register (see the table), and `0x08051A9C`/`0x08051BBC`/`0x08051CD8` swap r7/r8 between the player pointer and the `0x02017A40` counter pointer. In all four, the ROM allocates the *later* value to r7 and the earlier one to r8, which local-alloc has not reproduced for any C shape tried.
- **Further findings (2026-09-30):**
  - `sub_08051A9C`: `register ... asm("r7")`/`asm("r8")` on ps/cnt forces both into correct registers, but old_agbcc emits a spurious `adds r0,r7,#0` before `ps->handCount` load and shifts the base into r3 instead of r2. Removing the `bp` local (direct global accesses for `b4FC`/`count`) doesn't change the r7/r8 swap but eliminates one register.
  - `sub_08051ED0`: Ternary `player != 0 ? 0x80C4 : 0xC4` in the `sub_0801EC58` call moves id into r4 and msg into r5 (matching ROM), but `CARD_LEVEL` and `CARD_ID` macro expansions differ, because the ROM does not CSE the `gUnk_08621DE0` base load inside the CARD_LEVEL switch.
  - `sub_08051DF4`: Loading `a = *pa` and saving it **before** computing pb/pc (matching ROM instruction order: ldr into r9 first), plus `(u16)*pa` (not `(u16)a`) for the message halfword-load, gives r9=a and r8=b, which is correct. The three pointer registers still come out r6/r7/r4 instead of ROM r4/r6/r7.
  - `sub_08052810`: ROM's message expression `(0xB0000 | (r << 24)) >> 16` generates the correct `lsls/orrs/lsls/lsrs` sequence. The flag byte at offset 0xD68+9 can be expressed as `flag = (u8*)d + 0xD68; flag[9]` to get `[r1,#9]`, but this consumes an extra callee-saved register (r5 push). Writing `((u8*)d)[0xD68+9]` gets constant-folded to offset 0xD71.
  - `sub_08052668`: Variants with single-state-variable `s0`, reloaded `s0 = gUnk_0201AE60.state` in case-0 timer>0xC0 path, and `int t3` for case-1 timer increment reach the correct function size. Remaining diffs: `ldrb r4,[r7]` vs ROM `ldrb r0,[r7]; adds r4,r0,#0`, and case-1 tail constant-folds `s0+1` to `movs r0,#2` vs ROM `adds r0,#1`.
