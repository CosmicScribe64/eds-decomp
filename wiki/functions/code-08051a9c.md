## Matching tricks
- **Invert the layout with an early return:** `if (*s == 0) { ...; return 0; } ...; return 1;` with `struct Duel *d = &gDuel; u8 *s = &d->step;` matched `0x0805232C`/`0x08052560` (the direct `if (step != 0)` form compiled with the branch reversed, and a `&gUnk...step` pointer without the struct local made gcc use a single literal).
- **Solved puzzle (the three key callbacks):** a `local k = gMain.keys;` makes the last `if (k & 1)` come out as `ands r1, r0` (result in k's register) because the and's destination is tied to the first, now-dead operand. **Read the member directly in every test** (`if (gMain.keys & 0x20)`, `& 0x10`, `& 1`) instead: CSE keeps one load and the two earlier tests keep the const as the and's destination (`movs r0,#32; ands r0,r1`) because k is still live, so the last test matches the ROM too. That single change converted `0x080522C0`, `0x0805243C` and `0x080524A8` (checked with a scratch probe, `old_agbcc -da` RTL dumps to confirm the operand roles).

## Wave 1 matches (2026-10-01)

Working notes: `build/wf/DuelPrompt_Tribute/NOTES.md`, `build/wf/TypeMenu_Draw/NOTES.md`, `build/wf/TextBoxHandleChoiceInputCpu/NOTES.md`.

### `DuelPrompt_Tribute` (0xDC, start score 38; ordinary C)

- Read the fields straight off `gDuelScreen` in natural order (`a = w824`, then `b = w828 + w82C`), without the old `pa/pb/pc` pointer locals: score 20, with only the three field-address pseudos in the wrong registers (built r6/r7/r4, ROM r4/r6/r7).
- Then write the packed OR as `(u8)w828 | ((u8)w82C << 8)` instead of `((u8)w82C << 8) | (u8)w828`. The insns after combine are the same, but global-alloc priority (refs / live length, which flow computes **before** combine) now sees the w828 load end before the w82C load. That gives the priority order pa > pb > pc, i.e. r4/r6/r7.
- Diagnosis: compile a cut-down copy with `old_agbcc -dg -dl`; the `.greg` dump prints "Registers to be allocated in sorted order" with refs and live length.

### `TypeMenu_Draw` (0x130, start score 4; FAKEMATCH)

- With `u32 y = (b21 - h) << 3`, combine split the y computation into `y = D<<3` and `D<<19` for the first `y << 16`, keeping D live in r5 and moving the base/timer pointers (score 34). `u16 y` was close (score 4) but added a `lsr #16` narrowing before the spill.
- What matched: `u32 y` plus `asm("" : "+r"(y));` right after the declarations (before `t = &u->timer`). This empty read/write constraint stops combine from folding y into the shift, so y is spilled and reloaded for both rows as in the ROM.
- Failed without the barrier: `(u16)y << 16` at the first use, `* 8`, `(y + 0) << 16` (all 34), `s16 y` (114), a `yh` variable, `y * 0x10000`, `int y`, a one-element `ybuf`, and `y` behind a pointer.

### `TextBoxHandleChoiceInputCpu` (0xAC, ordinary C)

- `int st = *s; switch ((u8)st)`. The `(u8)` cast makes the switch index a separate pseudo, so CSE's jump equivalence never folds case 1's `(*s)++` into a constant 2 (the old `movs r0,#2` difference). Each case keeps its own `(*s)++` in its else branch, and cross-jumping merges them into one tail.
- Failed: `s8`/`u8 st`, `switch (*s)`, a shared `state++` tail after the switch, `*s = *s + 1`, and `{u8 t = *s; *s = t+1;}`.
- This function was byte-identical before `wf.py` could apply it: its table size `0xAC` includes 2 bytes of trailing padding. See [[agent-tooling]].

## Wave 2 matches (2026-10-01)

### `DuelPrompt_SetMonsterFromHand` (0x148, start score 53)

Only the level switch differed: the ROM reloads the stats table base in the default case (`ldr r2`), while the draft's `CARD_LEVEL` macro used the extern symbol `gCardStats` and GCSE/PRE reused the first table load (a copy pseudo in r2), leaving the build 10 bytes short. What matched: the cast literal `((const u32 *)0x08621DE0)[id & 0x7FF]` in both the type and the default-level accesses (the same form as `GetRecipeCardLevel` in [[code-080431e4]]). A cast constant is not a symbol_ref, so PRE does not CSE it, and each access loads its own literal. A `const u32 *stats` local failed in case 1 (r5) and at the function top (r8).

### `DuelPrompt_PickOpponentHandCard` (0xF8, start score 48)

1. Partner message argument: the ROM's `lsl 24; mov 0xB0; lsl 12; orr; lsr 16` comes from `(u8)r << 8 | 0xB` with `int r`. A u16 local adds an extra `lsl/lsr 16` and moves r out of r0; the explicit `(0xB0000 | (r << 24)) >> 16` gives the right instructions but the IOR output lands in the wrong register.
2. Message-8 argument: `(u8)w828 | ((u8)w82C << 8)`, the order of the matched sibling `DuelPrompt_Tribute`, not the reverse.
3. Flag byte `[base+0xD68, #9]`: a block-local pointer `struct Q1 *q = &((struct DuelQ *)d)->q1; q->f0 = ...;` in each case. The direct member access folds to `base+0xD71`; CSE keeps `(plus q 9)` because `base+0xD71` is not a valid Thumb address. Scoping the pointer per case avoids the extra callee-saved register that an earlier function-scope pointer needed.

### `DuelPrompt_BanishRandomFaceDown` (0x11C, start score 66; ordinary C)

The old draft had four separate causes, each fixed in C:
1. **Busy bit as a bitfield.** `gDuelScreen.b808 |= 8` on a plain `u8` became `busy = 1` on a `u16` bitfield (bit 3 of `+0x808`, as in `include/duel_ui.h`), which gives the ROM's `ldr; ldr; add; mov #8; ldrb; orr`.
2. **Cursor byte through a field access.** `*(u8 *)&gDuelScreen.w82C` is an ADDR_EXPR and folds into one `ldr =sym+0x82C` literal. `(u8)scr.cursor << 8` and `(u16)scr.cursor` (ldrb/ldrh at the CSE'd address) give the ROM's `ldr sym; ldr 0x82C; add`.
3. **Prototype.** Both messages go through `(void (*)(u16, u16, int, int))DuelCmd_Push`, the signature of its definition in [[code-0801e260]] (the NOTES name `code_080184D8`, but the definition is in `src/code_0801E260.c`). The unit's all-`u16` prototype adds zero-extensions that lengthen the cursor-address pseudo, so it lost r4 to the count pointer.
4. **Message types.** The first message is a `u16 msg` local: with no extension it lives to the call in r3 (`add r0,r3,#0`), which takes r3 out of the spill set and fixes every reload register. The second is a ternary inside the call (`player != 0 ? 0x80CE : 0xCE`). It has no extension insns, so the cursor pseudo is short enough to beat the count pointer (3/36 vs 8/100).

The screen block is reached through a cast macro (`(*(struct Scr1CD8 *)&gDuelScreen)`), because `wf.py` apply rejects `extern ... asm("gDuelScreen")` labels inside the region.

### `DuelPrompt_BanishRandom` (0x11C, start score 98; ordinary C)

This is a direct port of the matched `DuelPrompt_BanishRandomFaceDown` source (second message `0xC1`/`0x80C1`), and it matched on the first try. The old draft used `*(u8 *)&w82C`, which folds to one literal and comes out 4 bytes short, and it decremented the count before the call.

### `DuelPrompt_DiscardRandom` (0x120, start score 62; ordinary C)

- Porting the `DuelPrompt_BanishRandomFaceDown` shape (bitfield busy, `(u8)` cursor cast, `u16 msg`) left only the old ps/count swap (score 85): ps in r8 and bp/count in r7, where the ROM has ps in r7 and count in r8.
