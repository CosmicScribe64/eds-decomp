## Matching tricks learned

- **`u8 x : 3` bitfield inside a union with a `u16` view** gives both the byte (`ldrb`) and halfword accesses of `0x02015F00+0x1B20`. A standalone one-byte bitfield struct read through a cast pointer gets loaded with `ldr`; padding the struct to 4 bytes (`u8 pad[3]`) restores `ldrb` (`0x08058358`; historical for that function: the wave 2 match reaches `+0x1B20`/`+0x1B21` through `gUnk_02015F00` instead, see below).
- **Address by constant offset**: `(struct DuelZone *)(i * 0x94 + ((u32)gUnk_020192E4 + 0xD8C))` gives the ROM's `mul; ldr sym+off` order (`0x08057F6C`).
- **`switch` for range tests**: two consecutive ranges (`case 1..4` / `case 5,6`) produce the ROM's `cmp #1; blt; cmp #4; ble; cmp #6; bgt` chain; nested `if`s make gcc fold them into `sub; cmp; bls`. A switch with cases 0x777/0x778 next to 0x776 reproduces `cmp; beq; cmp; blt; cmp; bgt` (`0x08058EDC`).
- **Crossjumped tails**: a large `switch` whose cases `return 1` / `return 0` gets the ROM's shared `mov r0,#1` / `mov r0,#0` blocks automatically; a value shared by two cases needs `goto label` into the common test (`0x08058514`).
- **Reusing one local for different roles** changes register assignment: sharing `a` between the counters and the zone scores, and `zone` as the outer player counter, produced r5/r4 exactly like the ROM; separate locals for the `0x49A` loop counter (`zz`) and for the `0x591` result (`r`) were also needed.
- **Operand order of the zone address**: `(p & 1) * 0xD64 + z * 0x94 + base` gives `mul; adds r0,r0,r4`, whereas the `ZB` macro (z first) swaps the add operands.
- A `sub_08058924` return type of `u16` gives the `lsl #16; cmp #0` the callers test.

### `sub_080580C8` (0x290, start score 4; ordinary C)

The parked draft's comment gave score 4 (only the default case's `b & 7 | 8` differed), but the NOTES record 151 when the wave 3 run started. Fixes, in order:
1. **Reach the AI flags through `gUnk_02015F00`, as `sub_08058358` does** (`((struct AiWorkB21x *)&gUnk_02015F00)->d`, `gUnk_02015F00.fl.b.cntB`), not through `gUnk_02017A21.d` / `gUnk_02017A20.b`. The shared symbol gives loop.c's matching movables enough savings * lifetime to hoist `0x02015F00`, `+0x1B21` and the hand-count address. With every callee-saved register taken, those pseudos get no hard register, and reload rematerialises them from REG_EQUIV as the ROM's folded literals (`0x0201A04A` at the loop bottom, `0x02017A21` loaded twice, `0x02017A20` at the end). This took the score from 151 to 62 and later fixed the last reload-register shift (30 -> 4).
2. A `u16 id` (as in `sub_08058358`) instead of `int id`: `id & 0x7FF` is computed once and reused.
3. `switch ((int)CardCost(id))`: the signed switch gives `blt/ble/bgt`.
4. `u16 mask` with `int a, b` declared at loop scope and shared by both cases: a and mask both get r5, -1 gets r4, and the call needs no narrowing. With case-scoped a/b, the registers were swapped.
5. In the default case, `u16 c = (b & 7) | 8; mask = ((u32)a << 20 >> 16) | c;`. With `b &= 7; b |= 8;` or `b = (b & 7) | 8`, regmove moves the AND/IOR onto the constant pseudos. b is a copy of hard register r0, so its replacement_quality is 1, below the constant's 3, which gives `ands r0,r1` instead of `ands r1,r0`. Narrowing the result to `u16`/`u8` stops the swap. An `asm("" : "+r"(b))` barrier also keeps the operation in place, but it hides b's nonzero bits, so mask then needs a full truncation.

Failed: `(u16)(a << 4)` and `(a << 4) | ...` forms of the mask (26-56); `(b & 7) | 8` inlined into the mask expression (34).

### `sub_08058EDC` (0x208, start score 129; ordinary C)

1. Every table (`0x08623DF4`, `0x08621DE0`, `0x08622AB4`) goes through an integer-constant pointer instead of the extern-symbol forms. With the externs, GCSE keeps the table address in a register, while the ROM reloads it at every use (129 -> 40).
2. The deck branch does `deckCount++` before `front = &deck[0]`, as the fusion branch does, so the two tails become identical and cross-jump into `ldr r5,=listoff; add r2,r5; add r3,r2`.
3. The decode is a `static inline u16 CardNumberToId58(u16)` with early returns, the same helper as in [[code-08019554]] and [[code-08011be0]]. Assigning `id` once drops its refs from 9 to 5 (40 -> 30).
4. The r8/r9 player/id swap: `front->unk12 = player;` without `& 1` (the 1-bit field masks it) raises player's refs from 6 to 8, so player wins the global-alloc priority and gets r8 (30 -> 4).
5. The last reload register (r5 vs r1 in the deck-loop setup): the fusion branch stores `front->id = id; front->unk12 = player;` itself and returns instead of using `goto store`. Its extra reloads advance the round-robin reload register, and cross-jumping merges the tails anyway (4 -> 0).

Failed: `id = 0` before the decode, or a `u16 r` local inside the helper (both raise id's refs); pinning player to r8 (+80 bytes) or id to r9 (loses the CSE of `id & 0x7FF`); duplicated tails with `player & 1` (CSE shares `player & 1`, so player's refs drop).

### `sub_080589C8` (0x514, start score 31; FAKEMATCH)

The score went from 212 (first attempt) to 147 (an earlier session), then from 31 at the start of wave 3 to 4 and finally 0.
1. **0x15B and 0x29F loop registers:** reuse `zone` as the 0x29F loop variable (`for (zone = 5; ...)`). In `sub_08058514` the same loop gets r4/r5 because its zone variable crosses calls, and reusing the variable here gives the same callee-saved placement.
2. **0x3F1/0x437 address order:** use a local `ZP(p, z)` macro with the player term first, `p*0xD64 + z*0x94 + base`. EXPAND_SUM puts a MULT operand first, so this expands `h & 1`, then `h >> 8`, then the row multiply. Read the card as a word: `(CARD_WORD(..) << 20) == 0`.
3. **Prologue registers** (mask r1, switch value r2, table r3, with the table loaded after the shift): the integer-constant table form `((const u16 *)0x08622AB4)[c->id & m]`, and the FAKEMATCH `u32 m = 0x7FF`, which case 0x40E reuses for its whole index chain (`m &= c->side; m <<= 1; m += 0x08622AB4; x = *(u16 *)m;` gives `ands r1,r0; lsls r1,r1,#1; adds r1,r1,r3`). `x` is shared by 0x3F1 and 0x40E, and `num` is not reused in 0x3F1. The global-alloc preferences (x prefers r1/r2 and is merged into m) then give the ROM's assignment.
4. **0x3F1 and-operand tie:** the ROM has `adds r3,r1,#0; adds r2,r4,#0; ands r2,r3`, which copies the constant 1 rather than h. The FAKEMATCH `register int pl asm("r3"); pl = h;` makes op1 a hard register, so reload's commutative choice ties the constant instead. Then `p2 = (u8)pl; asm("" : : "r"(pl));` keeps r3 live, so the late `lsl/lsr #24` goes to r0 as in the ROM.

Failed: the symbol table form `gUnk_08622AB4[...]` (loads the table first, in the wrong place); `u16 sid = c->side` in 0x40E (ties the chain to sid in r0); an opaque mask via `asm("" : "+r"(m))` (ties only the and, and the shift goes to r0); an early `pl = (u8)h` (combine folds it into an `ldrb`); QImode or HImode forms such as `(u8)h & 1` and `(u16)pl & 1` (load a fresh `mov r0,#1`); and bitfield player/zone fields (`ldrb` loads).
