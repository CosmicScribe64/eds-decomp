## Matching tricks learned (old_agbcc)

- **`*((id & 0x7FF) + tbl)` versus `tbl[id & 0x7FF]`**: in the pointer-arithmetic form the mask is materialised before the table address (the ROM loads `0x7FF` (or derives it from `0x7C4 + 0x3B`) first, the table last); the array form loads the table first (`0x08059164`).
- **Constant-address tables** (`(const u16 *)0x08622AB4`) are not hoisted out of loops, `extern const u16 gUnk_...[]` symbols are; match the ROM per function (`0x080590E4` constant, `0x08059164` extern).
- **`u16 id0 = CardNumberToId(n);` then `CARD_STATS(id0)`** gives the ROM's `lsls #21; lsrs #19` index extraction; indexing the inline's result directly keeps an `ands` with a loaded `0x7FF`.
- **`gDuelZones[1].zones[z]`** (struct array member) produces the ROM's `mov #0x94; add; mul` zone address in the two `Find...` functions; `(0x0201A070 + 0x94 * z)` as a plain integer flips the `mul` operands.
- **Fields of a hoisted base through a global byte array**: `*(u16 *)(gDuelZonesP1 + 0xDA0) &= 0xFC03;` style raw accesses (not a struct pointer) yield the ROM's `ldr =0xDA0; add r8` per access with the base and `base + 0xD9C` hoisted into r8/sl at the loop pre-header; initialising a `u8 *base` local at the top puts the hoists before the loop counter store. A pointer-to-struct (`SELW.field`) makes gcc derive all accesses from one hoisted `base+0xD9C`.
- **Statement order fixes store evaluation order**: a plain store `*(u16 *)addr = expr` computes the address first; assigning `expr` to a `u16` temp first gives the ROM's "value, then address". A read-modify-write `*p = (*p & M) | V` with a `u16 *p` set first and `V` computed before it reproduces `addr, V, M, load, and, or`.
- **`for (gUnk.b7 = 0; gUnk.b7 <= 3; gUnk.b7++)` over a global byte** gives the ROM's `strb; lsls; lsrs; cmp` (the compare re-reads the just-stored byte through CSE); `++gUnk.b7 <= 3` or `do while` forms give `ands` with a hoisted `0xFF`.
- **A single loop variable for two loops** (`z` in both the five-slot check and the zone scan) decides which of `ok`/`i`/`zone` get r6/r7 (`0x08059408`).
- **`a | (id | C)` needs separate temps** (`a = (z & 0x1F) << 16; t = id | 0x80200000; f(a | t)`); the one-expression form is reassociated to `(a | C) | id`.
- **Uninitialised locals** reproduce `AiIsOpponentThreatening`'s read of r5/r6.
- **Ternary `x = (c) ? 0 : f()`** gives the ROM's shared `mov r0,#0; add r5,r0,#0` tail (`0x08059A78`).
- **Reading `u16 w0` through `gDuelPlayers[1].w0`** (a struct member at offset 0) gives two pool loads (`base`, `0xD64`) and an `add`, as in the ROM; `*(u16 *)&PLAYER(1)` folds them into one literal.
