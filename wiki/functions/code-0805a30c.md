## Matching tricks

- **Constant propagation through switch edges:** in the case-0 body of a switch on a byte, `p->f4 = 0` compiles to `strb r0, [r4, #4]` reusing the switch value register (r0 is known to be 0 on the `beq` edge), so no `mov r0, #0` is needed (`sub_0805A89C`, `sub_0805AB90`).
- A `cmp r, #0; ble/bne <false>` followed by fall-through comes from `if (cond) { ...; return 0; } break;`, because gcc places the merged body block right after the test (`sub_0805B184`).
- Writing the same state increment in two different access forms (pointer `p->f6++` vs direct `gUnk_02015EF0.f6++`) keeps the two tail blocks unmerged, as in the ROM (`sub_0805B184` `B38A`/`B3BA`).
- `sub_08009280(0, num)` inside the number switch needs the switch operand kept in `r1`. Writing the second argument as the same expression (`CARD_NUMBER(id)`) lets gcc reuse it; the ROM does not call with a garbage `r1`.
- The phase-10 chooser mixes `idx >= 0` (`cmp #0; blt`) and `idx > -1` (`cmp r, r(-1); ble`, with `-1` materialized once per group via `mov rX, #1; neg rX, rX`). Reproduce each check with the form the ROM uses.
