# Unit code_0805C508

`0x0805C508`-`0x0805D58C`, Thumb, `old_agbcc -O2`. Source: `src/code_0805C508.c`. Follow-on to [[code-0805b3f4]]: `AiChooseStrategy` (there) picks a scripted strategy index 0..8 and stores `(i << 1) | 1` in `0x02017A24`; `AiStepRunStrategy` dispatches to the matching handler below every frame. Unit status: `unit bytes MATCH`, 9/9 functions in C; no assembly fallbacks remain. All names are proposals (hypotheses).

Every handler is a small sub-step machine on `gAiState.f2` (`+2`), returns 0 while running and 1 for an invalid state; the "commit" idiom (write the chosen hand card `+0xB` into the block at `0x0201AE08`) and the "found flag clear" (`0x02017A24 &= ~1`) recur in every handler.

## Structures and globals

- `gAiState` `AiState`: `+1` step, `+2` sub-step, `+3` round counter, `+6..+9` scratch, `+0xA` phase, `+0xB` chosen hand index.
- `gAiWork` AI work area: `+0x1B24` byte = `bit 0 found` + `bits 1-7 strategy index`, `+0x1B25` candidate index.
- Commit block at `0x020192E0+0x1B28` (`CommitBlk`, 16 bytes): `+0` u16 card id (written with `CARD_ID(hand1[idx])`), `+4` flag byte (bit 1 set = committed; the handlers spin on it), `+8` bit-field halfword (bits 2-9 cleared) + byte `+0xB` (bit 1 set), `+0xC` bit-field halfword (bits 1-8 = hand index). `hand1` (player-1 hand, u32 card words, id = low 12 bits) is at `0x020192E0+0x13EC` == `0x020192E4+0x13E8` == `0x0201A6CC`.
- `gDuelPlayers+0xD66` player-1 hand count, `+0xD6C` flag byte.
- Card tables `gCardIdToNumber` (number by id), `gCardStats` (stats word).

## Matching tricks

- **The commit block's flag byte is a bit-field in a union**: `union { u8 raw; struct { u8 a:1, b:1, c:6; } bf; } f4; ... f4.bf.b = 1;` compiles to the ROM's `mov r3,#2; ldrb; orr r3,r1; strb r3` (the constant `2` register is shared with the earlier `f3 |= 2`, and the OR's destination is the constant's register). A plain `f4 |= 2` gives `orr r0,r4` instead. Keep the union at 4 bytes (`u8 pad` after it would shift the later fields).
- **A local `struct AiState *st = &S;` at the top** gives the ROM's `ldr r5,=0x02015EF0` hoist for sub-step machines that use the pointer after calls (`AiStrategyDoubleMachineAtk`); using the global directly gives the `ldr r1,=...; ldrb r0,[r1,#2]` reload at each use.
- `found.b.flag = 0` (u8 bit-field) gives the `mov r0,#2; neg r0,r0; and` (-2) mask the ROM uses.
- `FindFaceUpMonsterByNumber`'s return must stay `int` (the ROM does not narrow it); `((u32)r << 24) >> 16` is how `(r & 0xFF) << 8` appears.
- Byte-packing of the two extra cards `((((u32)(t\|a) << 24) >> 8) \| ((u32)(t\|b) << 24)) >> 16` with `t = -0x70` reproduces the ROM's shift sequence (the constant is materialised once).

## Near-misses

- Common to `0x0805C938`, `0x0805CB2C`, `0x0805D254` (and `0x0805C0A0` in [[code-0805b3f4]]): the instruction stream is reproduced but the ROM keeps every "clear the found flag" sequence as its own copy with different temp registers (offset reg r0/r2/r3, ldrb temp r2/r3/r6), so GCC's post-allocation cross-jumping only merges the tail `strb; mov r0,#0; b`; the build gets identical registers and merges the whole sequences. Temp registers could not be steered from the source.
- `0x0805C938`: corrected the parked action-queue call to `DuelCmd_Push(0x8008,1,packedIndex,0)`; the older draft had arguments 2/3 reversed. ROM register setup is direct evidence (`r1=1`, packed index in r2). The reset uses direct `S.f2=0`, shortening pointer liveness so the four-register prologue now matches. The range scan has an explicit mask/table, typed offset and input/clobber hint; its 0xFFFFF880 literal remains before the lookup instead of immediately after it. The packed action keeps its card-field OR group separate with an initialized word barrier. Private isolated comparison improved from 144 to 70 changed disassembly lines; three flag-clear prefixes and commit/loop temporary registers remain different. Active assembly is retained. A four-variant explicit raw-clear experiment did not improve the best draft.
- **Resolved `0x0805CEAC` / `0x0805D080`:** both 0x1D4-byte strategies now match as C. The first scan is guarded `i=0; if(i<count){do{...;i++;}while(i<count);}`; the candidate pointer is assigned inside the guard. An initialized `register u32 loadMask asm("r3")=0x7FF` plus an input-only empty-asm constraint before assigning the `r8` candidate base stages the mask literal ahead of the base. Pinning the initialized candidate count to `r6` retains best-value in `r5`; without that count pin, these two registers swap. These three compiler hints are documented FAKEMATCHs, emit no additional operations, and do not alter the selection algorithm. All six pins in the second hand scan were removed independently with whole-unit rechecks.
- **Second scan structure:** initialize `i=0`, load a word `n` from the byte hand count, then inside `if(i<n)` assign `needle`, `bound=n`, offset 0x13E8, hand pointer, mask, and table in that order. Advance the hand pointer and index in a guarded do/while. Keeping the exhausted-loop clear and shared `fail:` clear as distinct source bodies reproduces the target's two address-calculation prefixes and shared byte-mask tail.
- **Failed approaches:** the eight-line literal-order near miss did not improve after a two-minute register-allocation permuter run (~12,200 iterations). Passing a named mask as a new inline-helper argument changed allocation more broadly (91–151 diff lines); forcing mask materialization through an input constraint on the original helper retained the existing calculation. An unpinned mask input was much worse; a read/write mask barrier also worsened allocation.
- **Verification:** `tools/dr python3 tools/check.py code_0805C508` returns 0 and `unit bytes MATCH` (0x1084 bytes), including both simultaneous conversions. The check's 9/9 byte-matching functions includes four assembly fallbacks; the actual C count is 5/9.
