## Matching tricks
- **Bitfield words must be read through their own 4-byte struct** (`*(struct PickBits *)&gUnk_0201D7E4.bits`): a bitfield inside the big struct gives `ldrb`/`ldrh` pieces, a 4-byte struct gives `ldr` + `lsl/lsr`.
- **Symbol-relative constants:** addresses `sym + N` are derived from a literal already in a register (`adds r4, r5, #0; subs r4, #8`); locals like `u8 *step = &gUnk.step;` per access reproduce the ROM's explicit address adds, direct field expressions fold the offset into the load.
- **Expression order for sums matters:** `x += a * 0x78; x += 0x47;` (two statements) and `(a << 14) + 0x06004000 + (c << 5)` as separate `+=` statements reproduced the ROM's add order; a single expression was re-associated by gcc.
- **`u16` parameters used only in a zero test** narrow with a single `lsl 16` (`0x0805DF04`); `u16 t` for a multiplier avoided a spill in `0x0805DA1C`.
- Loops of `dst[i]` with hoisted constants (`0x3F`, `0xFC0`): gcc picks ip/r8 by first use; not reproducible so far (`0x0805DF34`).

## Near-miss register-allocation drafts (attempted, parked under `#if 0`)
All seven still-asm functions listed for this unit were attempted; none matched byte-for-byte. The drafts are logically identical to the ROM and compile, but differ only in which temporaries gcc picked, so they are good permuter seeds.
- `0x0805E100` (`FillTileRect`): identical code and size; the ROM re-materializes `0x2000000` (`movs r0,#128;lsls r0,#18`) for `t +=` in the inner loop while the build reuses the hoisted r6 (16 bytes shorter). Swapping the two increments or the declaration order does not change the CSE.
- `0x0805DC38` (`HBlankAffineWarp`): exact same instruction count; writing the sum as `(h*4 + k*640) + table` reproduces the ROM add order, only the accumulator register (target r1 vs build r2/r0) and the initial IO/table literal load order differ.
- `0x0805DF34` (`LoadPackedPortrait`): hoisted `0x3F`/`0xFC0` land in ip/r8 in the ROM but r8/ip in the build.
- `0x0805D708` (`CardFlipAnimTick`): register assignment (`pl/zone/row/base`) whole-function; the frame index is summed as `(cnt*2 + row*48)` in the ROM but `((row*24 + cnt)*2)` in the build.
- `0x0805DA1C` (`CardSwapAnimTick`): first ~96 instructions and size match; only the tail temporaries after the second `sub_08076714` (r4/r3 vs r0/r1/r2) differ.
- `0x0805D58C` (`CardMoveAnimTick`): logic identical; the ROM keeps `&gUnk_0201CFB0` in r8 (`add r2, r8` for the sel) and spills flag/row/id, the build folds the base into literals and assigns pl/zone/fb to r8/r9/r7.
- `0x0805E3B8` (`DuelSceneInit`): cleaned m2c draft compiles; the prologue already diverges (gcc folds the two clear-bit masks `-3 & -5` into one `0xF9`, reorders the arg-halfword narrowing) and the function comes out smaller, so it needs heavy permuter help.

## Two animation matches (2026-10-01)
