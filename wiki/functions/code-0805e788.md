# Unit code_0805E788

The unit covers `0x0805E788`-`0x0805F96B` (Thumb, `old_agbcc -O2`), and its source is `src/code_0805E788.c`. It sits between the duel UI animation helpers ([[code-0805d58c]]; `sub_0805DEA4`, `sub_0805DF04` and `sub_0805DD3C` are called from here) and the text box UI ([[code-0805f96c]], which calls `sub_0805ECFC` / `sub_0805ED9C` / `sub_0805F64C`). Unit status: `unit bytes MATCH`, **11/14 functions in C**; 3 stay `INCLUDE_ASM` (2 have near-miss attempts under `#if 0`, and the third, the big transition state machine `sub_0805E788`, was not attempted).

The unit has two parts. The first is a fade/transition state machine and a screen-cursor helper. The second is a "text cell buffer" API, a buffer of 64 cells of 0x20 bytes (8x8 4bpp tiles) at `0x0201CFB8`. Strings and numbers are rendered into it (`sub_08072778` draws one char into a cell and `sub_08072808` a 2-byte char) and then copied to VRAM. The card info panels are built on it.

## Structs and globals
- `0x0201CFB0` duel screen block (see [[code-08051a9c]], [[code-0805d58c]]): `+0x808` bits 0-1 dirty flags of the text cells (bit 1 = redraw), `+0x824/828/82C` cursor player/mode/index.
- `0x0201CFB8` text cell buffer: 64 cells x 0x20 bytes; byte `+0x800` (`0x0201D7B8`) low bits cleared by `LoadIconPack`.
- `0x02018450+0x15C..0x15F`: transition state / sub-step / frame counter (`struct Blk18450` in [[code-0805d58c]] has `+0x15D`).
- `0x02011C20+4` bit 7: 2-byte character mode; `& 0x7F` selects the label set (language?).
- Card info block from `sub_0800ABC8` (12 bytes): `u16 id; u8 attr:5; u8 kind:3; u32 atk; u32 def`. Keep `attr`/`kind` in a `u8` storage unit, not `u32`: agbcc then emits `ldrb` + `and #0x1F`/`and #0xE0` for the `!= 0` tests (a `u32` unit gives `lsls`/`lsrs` instead and breaks `sub_0805F728`).
- Card stats table `0x08621DE0`: ATK-like bits 9-17 (x10), DEF-like bits 0-8 (x10), level bits 25-28, type bits 20-24 (0x15-0x17 Magic/Trap/Ritual, 0x18 special).

## Matching tricks
- **Inline helpers with `u16` return type** (`CardAtk/CardDef/CardLevel` = the `switch (CARD_TYPE)` value, 0 / 4000 / (stats field * 10), level 0 / 10 / field) make the call argument a copy (`adds r1, r0, #0`) as in the ROM; `int` results are allocated straight into the argument register.
- **`x = (int)(len * w) >> 1;` into a fresh variable** (not `len *= w; len >>= 1`) gives the ROM register assignment in `sub_0805F00C` (len dies at the multiply and the result reuses r4).
- **Post-increment of the cell index in the argument** (`buf + first++ * 0x20`) puts the `adds r5, #1` before the `bl` (`sub_0805EDE0`, `sub_0805EE30`); `first += digits;` as a statement (not a new `pos = first + digits`) keeps the extra `adds r6, r0, #0` copy in `sub_0805EE78`.
- **Byte swap** `u32 hi = c >> 8; u32 lo = (u8)c << 8; f(lo | hi, ...)` reproduces the shift order; a single expression reloads the halfword.
- **Sibling of `sub_08055EB0`'s lesson**: a `sym + 0x311A` pointer that the ROM adds at run time is written `(u16 *)((u8 *)&gMain + 0x311A)` (a `&gMain.field[n]` folds into one literal); the declaration order `b, i, v, p` reproduces the ROM's load order (`sub_0805ED78`).
- **Bitfield flags** `f808_0 = 1; f808_1 = 1;` give two `orr`s (`mov r1,#1; ldrb; orr; mov r2,#2; orr; strb`).
- **Nested switch for `n == a || n == b || n == c`** in `sub_0805F270` (`switch (n) { case 0x47: case 0x15B: case 0x4CE: ... }`) gives the ROM's binary decision tree; the `||` chain does not.
- **Local register-variable pins** (`register u8 *p asm("r2"); register u32 n asm("r0");`) fix agbcc's operand/schedule choice where it would otherwise differ: in `sub_0805ECFC` pinning the base to r2 and the offset to r0 makes the final add `adds r0, r2, r0` instead of `adds r0, r0, r2`; in `sub_0805F074` pinning the name-string byte offset to r0 makes agbcc emit `lsls` before the table `ldr`. Both are marked `/* FAKEMATCH */` (harmless, because they only steer register allocation).
- **Compare against the memory operand, not a cached local:** in `sub_0805F728` write `CardAtk(id) != info.atk ? 6 : 7` (and `info.def` for DEF) while keeping `atk`/`def` locals for the call argument; this reproduces the ROM's extra copy / stack re-read.
- **Open problems:** broad register allocation in `sub_0805EF00` (ROM: `cnt` r6 / `cell` r5, map base r8, map-entry pointers r5/r4/r3/r1; the draft swaps `cnt`/`cell` and spills the pointers) and in `sub_0805F270` (name-string address and the zone-address products use swapped temporaries). Both have parked drafts as permuter bases; simple register pinning did not converge (the intermediate address temporaries reuse the same registers).
