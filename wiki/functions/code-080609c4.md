# Unit `code_080609C4` (`0x080609C4`-`0x08061A18`)

Thumb, `old_agbcc -O2` ([[compiler-flags]]). Source: `src/code_080609C4.c`. 21 of 25 functions are matching C, 4 stay `INCLUDE_ASM`, each with an attempt under `#if 0`. The unit as a whole matches (`unit bytes MATCH`).
It is the board/screen layer of the duel UI that sits after the prompt helper `sub_080602A4` ([[code-0803fe70]], [[code-08040ebc]]): screen init, fade in/out steps on `gMain` brightness, and the routines that (re)draw zone tile blocks in the IWRAM tilemap buffer `0x03001C5C` and the cursor / card sprites.

## Structures and globals (inferred)

- `gMain` (`0x03000040`): `+0x40E u16 vblankFlags`, `+0x414 vblank callback`, `+0x4832` byte `brightness:6 | flags:2` (fade level 0..0x1F, BLDY = level), `+0x485E u16 frameCounter`.
- `gUnk_0201CFB0` (duel screen view): byte 0 bits 1-2 = overlay enable flags (bit 2 set by `DuelScreenInit`, both cleared by `DuelScreenExit(1)`); `+0x824/+0x828/+0x82C` cursor player / row / column; `+0x85C` optional per-frame callback.
- `gUnk_020192E0` (duel globals): `+4` is also the base of `PlayerState[2]` (`0x020192E4`, stride 0xD64): `+2 u8` hand count, `+3/+4/+5/+6` small counters used by slots 13/14/12/15, `+0x26 u16` per-zone bitmask, `+0x904` and `+0xB84` u32 card-word lists (`& 0xFFF` = card id), `+0xCC4` 2-byte entries. `+0x1ACC & 0xF`, `+0x1B12` bits (bit 1 = player, bits 2-4 = mode), `+0x1B2C` bit 0.
- Zone records `0x0201930C + player*0xD64 + zone*0x94`: `+0` card word (id = low 12 bits), `+6` flags (bit 0/1), `+0xA u16 ids[0x20]`, `+0x4A u16-strided effect types (only the low byte read)`, `+0x8A u16 count` (see [[code-08040ebc]] for `struct DuelZone`).
- `gUnk_081A42A4[2][16]` = `{s32 x, s32 y}` pixel positions of every zone/slot per player (divide by 8 for tile coordinates); `gUnk_081A427C[8]` = animation tile offsets cycled by `frameCounter >> 3`.

## Matching tricks

- **Fade steps with `if (x <= N) return 0; ...; return 1;`** give `bls L0` with the body in the fall-through (and let gcc derive `DISPCNT` from the BLDY pointer with `subs r2,#0x54`); the positive form `if (x > N) { ...; return 1; } return 0;` puts the body out of line. For fade out use `if (b != 0) { BLDY; BLDCNT; return 0; } call; return 1;` (`0x08060C68`).
- **Bitfield byte with 6-bit level** (`u8 brightness : 6;` inside a big `struct Main`) reproduces `ldrb; lsl 26; lsr 26` and the `bic` of the upper bits in `+=` / `-=`.
- **`return sub_08075A6C(4) != 0` shapes**: `if (x != 0) { f(); return 1; } return 0;` matches `0x08060B4C`.
- **`sub_080761F0(0x00400058, 0x40C0, t |= 0x6000)`** (compound assignment inside the argument) loads the constant args first and keeps `t` in r3 (`0x080617F8`).
- **Helpers called through `int` asm-name prototypes** (`void f_i(s32, s32) asm("sub_08060DD8")`) so that callers do not narrow the `u16` parameters of the real definition (`0x08060ECC`, `0x08061004`).
- **Explicit 4x4 block stores** `p[0] = t++; ... p[0x63] = t;` reproduce the unrolled halfword stores; `p = gUnk_03001C5C + (x + (y << 5))` for `u16 x, y`.
- **Explicit coordinate narrowing** (`0x08060E2C`): `u32 x, y` parameters with `(u16)x` and `(u16)y` at index formation reproduce the target's early tile-parameter narrowing. The three-register calling convention and low-half coordinate behaviour are unchanged.
- **2-D table access** `gUnk_081A42A4[player][zone].x / 8` gives the two separate shifts (`zone << 3`, `player << 7`) and the signed-divide fix-up.
- **Sequence the decomposition of packed args at the point of use** (`0x0806120C`): `p2 = b; z2 = b >> 8;` between the two helper-call pairs, and `x |= y << 16` just before the tile computation.

Mid-function declarations are rejected by old_agbcc (syntax error), so the natural fix of declaring `a`/`b` at their use is not available.
- `0x08060ECC`: `id` is kept in r2 with a copy in `ip`, zone-position table in r3; ours puts `id` in r3, table in r2, no `ip`. Tried all declaration orders (pp/z/id/x/y), xy-first/xy-last, `& 0xFFF` mask, `zp` local.
- `0x08061004`: case layout of 12/13 matches with gotos; register allocation differs (table pointer in r6, `idx` stays in r2, x in r5, y in r7, r8 saved). Tried `zp` local, xy swap, `u32` copies, `idx` local.
- `0x08061580`: ROM computes `z*0x94` before `p*0xD64`, saves only r8/r9.
- `0x080616D0`: register allocation (ROM keeps the player index in r7, y in r8, n in r6; ours spills it).
- `0x08061848` is matching. Form the tile-row/column address before adding the intra-tile coordinates, narrow the second byte through `(u16)w >> 8`, and shift the source word cumulatively for bytes 2-3. A temporary stack-buffer pointer before the third byte store retains the ROM's scheduling. Spell the pixel-index mask as separate assignment/AND/shift operations. The tile-column/address register constraint to `r4` is documented `FAKEMATCH`; a `r3` constraint and an empty scheduling barrier were both removed after exact whole-unit checks. The color argument is word-sized and narrowed by the byte store; the blitter explicitly casts its color argument to `u8` before the call, preserving its original instruction sequence and the three-register ABI.
- `0x080618C4` is matching. Constrain the initialized source-pointer copy to `r5` (documented `FAKEMATCH`), then explicitly narrow the word-sized palette argument to `u16`. This preserves the four-register ABI and the ROM's low-half palette behavior while letting the source-pointer move precede narrowing. Load the row halfword before initializing `k` and advancing `src` in the inner-loop initializer. Removing the pointer constraint was tested and failed the unit comparison, so it is retained. Both this function and `0x08061848` were verified with `tools/check.py`: 25/25 functions match and unit bytes MATCH (0x1024 bytes).

## Screen-init loop match (2026-10-01)

`sub_080609C4` matches all 0xE8 bytes with one initialized r3 binding for the u16 base tile 0x4280 and no empty constraints. Initialize i, the first destination, tile, then the second destination. Stage the first halfword as `*a = i; *a += tile;`, leaving `*b = tile + i;`. The compiler forwards the value and emits exactly one store to each destination, with the target's operand order. For the two iterations, i is 0/1 and both destinations receive 0x4280/0x4281; pointers address distinct halfword arrays. Removing the tile binding or replacing it with a wide integer changes scheduling.

The bounded one-worker permuter found this defined rewrite at iteration 855 (17 compile errors), from a one-byte miss. No uninitialized values, dead branches, invented ABI or extra runtime stores are used. The final whole-unit check and full-ROM checkpoint 24 pass. Evidence: `build/bigguns-lead2/screen_init_*.py`, `enable_screen.py`, `screen-permuter.log`, `sub_080609C4/solo-clean/`. Earlier scheduling limitations above are superseded.

## `sub_08060ECC` matched (2026-10-01)

The permuter (a 10-minute queue run) found the fix. The card ID local is **`u16 id = (*(u32 *)z << 20) >> 20`**, not `u32`, which keeps `id` in r2 with its `ip` copy, as in the ROM. This is ordinary C with no hints. Changing the card ID from `u32` to `u16` also improved about a dozen other drafts in the automated type sweep ([[decomp-permuter]]).
