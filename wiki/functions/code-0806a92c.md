## State and matching notes

State at 0x0201DB20 shares `col[3]` at +0x620, `count[2][3]` at +0x1494, row bytes +0x14A0, cursor +0x1C1C with [[code-08068180]]. Signed exchange byte +0x1866 is 1 when armed, zero when ready, -1 after applying. Menu word +0x1C3C holds choice bits 15–17; its second byte +0x1C3D holds phase bits 0–2. Selector +0x1C5A occupies bits 2–4. A union models the overlapping word and byte bitfields and matches the read/modify/write operations exactly.

Direct struct accesses reproduce the runner's base-plus-offset literals. `sub_08068D1C` must be declared with a full-width result in this unit. The search compares directly, while calls to copy-count mutators narrow to u16. The large handler remained assembly without an accepted C implementation until wave 3 (historical; see below).

`sub_0806A9AC` is ordinary matching C with no register bindings or empty assembly. Inline integer getters extract the complete two-bit main/side counts before a nonzero test, reproducing the paired shifts instead of a direct bit mask. A `const u16 *` ROM view at 0x08622AB4 keeps mask construction before loading the table base; a separately initialized trunk base pointer keeps the base load before the four-byte card index. The side count is re-read after the main-list append call, and each list count is postincremented before its append call. The original `int(void)` ABI and overlapping object-bitfield updates are unchanged. Full live validation: `build/bigguns-card-ui/code_0806A92C-accepted.txt`, 10/10 functions and all 0x1BB8 unit bytes match; private exact snapshot: `build/bigguns-card-ui/sub_0806A9AC/base-local/`.

`sub_0806AFA4` is verified matching with `tools/check.py code_0806A92C` (10/10 functions and unit bytes MATCH). Cursor clamping keeps the loaded count for `count - 1` and a separate copy for comparison and the zero store. An empty read/write register barrier on the copy prevents coalescing the two values and emits the ROM's `adds r3,r0,#0`; it emits no instruction itself. This compiler constraint is marked `FAKEMATCH` in the source.

## Wave 3 matches (2026-10-01/02)

Working notes: `build/wf/sub_0806B3B0/NOTES.md` (with RTL dumps in `dump/` and twin assembly comparisons `twin_asm.txt`, `f934_vs_b3b0.txt`).

### `sub_0806B3B0` (0x1134, start score 587; FAKEMATCH)

At 4.4 KB this was the largest function of wave 3. It is the transfer scene's frame handler:
- When the redraw bit is set and a horizontal page slide crosses its midpoint (`tween.value` 4/3 with direction 3/4), it clears `0x0600D000` (`CpuFastSet` of a zero word) and redraws the neighbouring rows and the selected card's detail panel (or calls `sub_08065384` when the list is empty).
- After `sub_08066260` (called with the tween state and the sprite/slot records), directions 1/2 (vertical) and 3/4 (horizontal, with BLDCNT `0x3F43` and a blend value for `sub_0807B4A8`) ease the BG offset registers through `sub_0807B4D0` and the curve `gUnk_080875D2`, and commit the new scroll when the tween ends.
- List input (`menuOpen == 0`): B calls `sub_080787F4(0, 0x180, 0, ...)` (a fade, hypothesis) with exit mode 0, Up/Down scroll through `sub_080679E0`/`sub_08067DA4` ([[code-0806704c]]), Left/Right page the list by five cards (redraw the card panel, reinitialise the five slots), and A sets the menu phase (`+0x1C3D` bits 0-2) to 1; otherwise `sub_0806ADBC` handles the shoulder keys.
- Menu input (`menuOpen == 1`): Left/Right cycle the 3-bit choice (`+0x1C3C` bits 15-17), skipping entries by cursor and current choice. A runs choice 0/4/5/6 (the same `sub_080787F4` call with exit mode 2/1/3/0) or, for choices 2/3, arms the exchange selector when `sub_08068434()` allows it; B with selector 2 cancels (`sub_0806B2F8`).
- Shared tail: `sub_0806B190`, two sprite groups (`sub_08077EF4`), the slide indicator, `sub_0806704C`/`sub_08067908`/`sub_08067660`, `sub_08068180` and the panel helpers, then either returns 1 (byte `tail[-0x1602] == 2`) or sets BLDCNT/BLDY from the signed value at `tail - 0x374`.

It is a twin of `sub_08070F18` ([[code-0807093c]], matched in wave 2); the agent measured about 91% similarity. Score 587 -> 770 -> 168 -> 60 -> 12 -> 0:
1. **Rewrite from the twin.** The function was rewritten from `sub_08070F18`'s C, reusing its frame/state/count views, the `u16 menuSelected : 3` field in a u32 container, `volatile u32 clear` and the `tail` pointer epilogue. This replaced the older private draft (structurally close, different style). The score rose to 770 because the diff lines aligned differently, although the code was closer.
2. **GCSE copy priority (FAKEMATCH).** The ROM keeps two copies of `&gUnk_0201DB20` (r3 and r6). The r6 copy is a GCSE reaching register that lives through the whole input section: 15 refs over a live length of 652 (doubled by its REG_EQUAL), priority 0.069, below the menu-arm constants (7 at 0.091, `0x38000` at 0.087, the mask at 0.086). Those constants took r6 and the copy fell to ip. One no-code use, `asm("" : : "r"(&gUnk_0201DB20));` in the right-key arm, is rewritten by GCSE to the copy and gives 16 refs, 4*16/652 = 0.098 (770 -> 168).
3. **Separate confirm sounds.** The ROM keeps the choice 2 and choice 3 selector bodies separate. Each A-menu case calls `sub_08077AEC(1)` itself, and so does the `menuOpen == 0` A path, instead of a shared `goto confirm_sound`; cross-jumping then merges only the sound tail (168 -> 60).
4. **Three-quantity sort (FAKEMATCH).** The left-key phase-store block had exactly three local quantities (the address, -8 and 3), and agbcc's buggy sort for three quantities allocated them in birth order, giving the address r0. A fourth quantity, `u32 extra; asm volatile("" : "=r"(extra));`, restores the priority sort: -8 in r0, 3 in r1, the address in r2 (60 -> 12).
5. **Reload rotation (FAKEMATCH).** The ROM needs one more spill step before that store, so `0x1C3D` reloads into r0 and the byte into r1. Holding r5 busy around the store (`register u32 busy asm("r5")` with an empty output/input `asm` pair) does this (12 -> 0).
- Two further FAKEMATCH forms come from the twin: `volatile u32 clear` keeps the original fill slot and its stack-store scheduling, and the `B3_FADE_INT`/`B3_FADE_U16` casts call `sub_080787F4` under other return types, so the menu transition calls are not cross-jumped.
- Failed: plain `sub_080787F4` calls instead of the int/u16 casts (972, the fade calls cross-jump); `selector += 1` in case 3 (same RTL); separate `sound(0)` calls in the right and left arms (no change); binding the left phase pointer to r2 with `register u8 *pp asm("r2")` (the address became a direct literal and the `&D` copy died early, 135); removing the fourth-quantity dummy while keeping the r5 pin (160).
- Lesson: for a large function with a matched twin, porting the twin's C beat continuing a separate, structurally close draft; the remaining work was a handful of allocation-priority, local-alloc and cross-jump fixes, diagnosed from the RTL dumps in `dump/` (`.flow`, `.greg`, `.lreg`; see [[matching-tricks]], register allocation priority).
