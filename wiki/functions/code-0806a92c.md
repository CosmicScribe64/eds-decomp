## State and matching notes

State at 0x0201DB20 shares `col[3]` at +0x620, `count[2][3]` at +0x1494, row bytes +0x14A0, cursor +0x1C1C with [[code-08068180]]. Signed exchange byte +0x1866 is 1 when armed, zero when ready, -1 after applying. Menu word +0x1C3C holds choice bits 15–17; its second byte +0x1C3D holds phase bits 0–2. Selector +0x1C5A occupies bits 2–4. A union models the overlapping word and byte bitfields and matches the read/modify/write operations exactly.

Direct struct accesses reproduce the runner's base-plus-offset literals. `sub_08068D1C` must be declared with a full-width result in this unit. The search compares directly, while calls to copy-count mutators narrow to u16. The large handler remains assembly without an accepted C implementation.

`sub_0806A9AC` is ordinary matching C with no register bindings or empty assembly. Inline integer getters extract the complete two-bit main/side counts before a nonzero test, reproducing the paired shifts instead of a direct bit mask. A `const u16 *` ROM view at 0x08622AB4 keeps mask construction before loading the table base; a separately initialized trunk base pointer keeps the base load before the four-byte card index. The side count is re-read after the main-list append call, and each list count is postincremented before its append call. The original `int(void)` ABI and overlapping object-bitfield updates are unchanged. Full live validation: `build/bigguns-card-ui/code_0806A92C-accepted.txt`, 10/10 functions and all 0x1BB8 unit bytes match; private exact snapshot: `build/bigguns-card-ui/sub_0806A9AC/base-local/`.

`sub_0806AFA4` is verified matching with `tools/check.py code_0806A92C` (10/10 functions and unit bytes MATCH). Cursor clamping keeps the loaded count for `count - 1` and a separate copy for comparison and the zero store. An empty read/write register barrier on the copy prevents coalescing the two values and emits the ROM's `adds r3,r0,#0`; it emits no instruction itself. This compiler constraint is marked `FAKEMATCH` in the source.

## Private large-handler frontier

The complete `sub_0806B3B0` reconstruction is parked at `build/bigguns-card-ui/sub_0806B3B0/reviewed-frontier/source.c`. It is ordinary C with no register bindings or empty assembly. The original no-argument/full-width return convention remains `int(void)`. The compiled body is 0x111C against the ROM's 0x1134; the first difference is +0x66A (0x0806BA1A), so the redraw and scrolling prefix is byte-identical through +0x669. The complete private unit check keeps all nine active C functions exact, but the large function and whole unit still differ. The active source therefore retains its assembly fallback. See `reviewed-frontier/check.txt` and `diff.txt` in that directory.

The reconstruction models the ramp at +0x628 (signed current value +0x62A), animation byte +0x61E, sprite records +0x18B0, and six 16-byte slot records following the four-byte header at +0x1BB8. Slot visibility is at +0x1BC4 + 16*i; the last visibility byte is +0x1C14. It also exposes the overlapping menu word/byte views and the +0x1C58 selection timer. Private compile-time offset assertions cover these views and the previously known fields. A local scratch view holds the initialized fill word and the row output used by navigation, reproducing the 0x2C frame and original stack offsets without extra storage.

The movement-mode switch, distinct confirmation paths, and the original right-page sound label placement matter, because common labels introduced too early merge instruction tails that are separate in the ROM. Whole-word menu tests preserve the mask comparisons and avoid replacing later increments with constants. The remaining mismatches concern the input/menu base lifetime, preserving the pre-mask choice value, two decrement/phase tails, the row pointer within the typed scratch view, and scratch-register choices. Binding the complete input view to r6 makes the body worse and is not a useful continuation. An initialized read/write constraint on the pre-mask choice values gives a separate 0x1124 candidate at `sub_0806B3B0/next-readwrite/`; it also remains nonmatching and is not active.

`tools/dr python3 build/bigguns-card-ui/verify_transfer_handler.py reviewed-frontier mutating` passes 2,048 finite states. The harness compares return values, ordered call arguments, EWRAM, live IWRAM, display registers and video memory, while clobbering caller-save registers after calls. Synthetic helpers include the fill operation and changes to scroll fields, cursor/phase, and slide outputs, exercising repeated reads after calls. The log is `build/bigguns-card-ui/handler-frontier-behavior.txt`. This is bounded evidence using synthetic helpers, not proof of equivalence or a substitute for exact matching.
