## Matching tricks
- `ProhibitCardSelect_SwitchScreen` compiles from a `switch (mode)` with an explicit `case 0` exactly like its sibling; only the destination struct differs (local `struct MenuState` at `0x02017A40`, step `+0x3E6`, substep `+0x3E7`).
- Loops `for (i = 1; i <= 0x334 && CARD_NUMBER(i) != 0xFFFF; i++)` reproduce the ROM's bottom-tested loop with the `i > 0x334` check before the table re-check; the `while`/`break` spelling used in the sibling near-miss produces a different constant-load order.
- A two-case `switch` must list `case 1` before `case 0` to get the ROM's block order (mode 1 code first, `cmp #0; bne; b <mode 0>`).
- Trunk entry as `struct { u16 owned:10; u8 f1:2; u8 f2:2; u8 f3:2; }` gives `ldrh; lsl #22` for the count test and `ldrb [+9]` tests for the others.

## Near-misses
- `0x08070A1C`: only the mode-1 loop differs (ROM: `0xFFFFFB46` in r3, `0x03150000` and `0xFFFFF894` in r1, hoisted counter addresses through r1/r0/r1; build: r1 / r1 / r3 and r0/r1/r0). ~12 spellings of the range test (casts, local `n`, `continue`, nested ifs) did not change it.
- A later s16/u16/s32/u32 mask-local grid, with and without an input constraint, also worsened the initial 50-line comparison to 278–308 changed lines. It was private and never enabled; avoid repeating it unchanged.

## Twin input-handler repair pass (2026-10-01)

Historical (matched in wave 2, see below): the parked `TradeCardSelect_Update` draft was reduced from **2249 to 920 changed normalized disassembly lines**, measured with the current `check.py --diff TradeCardSelect_Update --norm` comparison. These are diff lines, not differing bytes. The handler remains assembly; the active unit still reports **unit bytes MATCH**, 0x1604 bytes, **3/4 functions in C**.

- Corrected a real translation error. The packed selector temporary was `u16`, truncating bits 16–31 of the word at state+0x1C3C. The increment is expressed through the existing three-bit `W84.b` field instead. The animation byte, row byte and five-row loop counter use unsigned byte types matching the ROM.
- Named animation fields at +0x628 (`u8 b628`) and +0x62A (`s16 h62A`) preserve the target's state-base addressing; raw `DIN16(0x62A)` had encouraged an unrelated cached base. Existing matching functions and struct offsets remain unchanged.
- Source block order matters substantially: browse case 0 precedes panel case 1, key 16 precedes key 32, and animation cases 1/2 precede 3/4. Together with the corrected field types, these restore large portions of the ROM's block order.
- Row-coordinate expressions use signed integer `0xFF & (halfword + offset)` masks. Marked word caller views avoid extra caller narrowing and preserve the target `ands #255; asrs #3` sequences. The aliases refer to the original helper symbols and keep their original argument order.
- A local `{ s32 fill; u16 scroll; }` frame restores the ROM's stack slots +0x20/+0x24. Staging the next-row value before row/count loads, with marked `r2` bindings, and staging count-address additions separately reproduces the first 225 normalized instructions. The next remaining difference is one commutative `adds` operand order.
- Tested and rejected: early animation reordering before field repair, byte bitfields for `b635` (identical output), fixed `r1` count-address locals (unnecessary), empty constraints on those locals (unnecessary), and binding the final count index to `r2` (worse).

Scratch evidence: `build/codex-scratch/codex-code_0807093C/checkpoint.log`, `best920.c`, and `survey.py`. The normalized match prefix excludes pool offsets and branch destinations; it is not a byte-match claim. The earlier notes saying hints were absent describe the previous draft and are superseded by the explicitly marked, behaviour-neutral hints permitted by the 2026-10-01 policy.

The same pass subsequently reached **539 normalized changed lines**. Direct `REG_BG3*`, `REG_BG1*`, and `REG_BG0*` assignments restore the original register-pointer increments; staging the alpha value as a shifted word and chaining the upper-phase BG write restore the animation allocation. A separate count-offset temporary fixes the lone commuted `adds` in the initial drawing block. Panel case 2 follows the action cases, shared sound tails follow the action switch, and ordinary `DeckState`/`B7C` pointers restore much of the panel allocation. The paging guards test the signed row directly and compare its unsigned halfword after the nonnegative guard. The cursor subtraction temporary is a marked signed-width FAKEMATCH. The unsigned guard still sends values outside 0–4 to the subtract-five arm, and the final halfword store preserves the result modulo 65536.

Rejected follow-up experiments include typed counter-array addressing, volatile cursor scratch, constrained count-pointer reloads, replacing the frame with individual scalar/aggregate scratch objects, and fully reconstructed paging loops with fixed register roles. The remaining differences center on paging-loop stack addressing and allocation, input-state pointer allocation, and the final fade path. The handler remains disabled; no partial assembly replacement was enabled.

## Card-list frame handler matched (wave 2, 2026-10-01)

`TradeCardSelect_Update` (0x1028) matches, from start score 433 (257 lines, 44 bytes short). It is the twin of `DeckEdit_Update` ([[code-0806d51c]], wave 1); the third sibling `ProhibitCardSelect_Update` ([[code-0806ed44]]) was then ported from this one. Working notes: `build/wf/TradeCardSelect_Update/NOTES.md`.

Steps (score after each):
1. Menu DPAD_RIGHT/LEFT: replace the shared `menuPhase` pointer and `menu_moved:` label with a plain phase write in each arm, through a local `struct DeckPhaseFields` (`phase:3` at +0x1C3D), so the address is `base + 0x1C3D` rather than one folded pool constant (167). This also fixed the browse `default:` block (+0x716), which was only a global-allocation knock-on.
2. Browse A button `phase = 1` through the same struct (196, a longer matching prefix).
3. One function-scope pointer `u8 *pp` set in both arms (`pp = (u8 *)&gDeckEdit; pp += 0x1C3D;`). Used in two blocks, it is allocated by global-alloc (r2), and the tail block keeps only two local quantities, which get r0/r1. With a block-local pointer there are three, and **local-alloc's three-element sort bug** (it compares quantity numbers 0/1/2 rather than `qty_order` entries) gives the pointer r0 (182).
4. Reload register choice: RIGHT's offset must be r0 (r5 busy), LEFT's r5 (r4 busy). An empty asm pair around `pp += 0x1C3D` with `register u32 busy asm("r5")` / `asm("r4")` (FAKEMATCH) keeps those registers occupied (70).
5. A-button cases 0/4/5: the three identical `FadeStart(0, 0x180, 0, ...)` tails were cross-jumped. `asm("")` after the call (the `DeckEdit_Update` trick) fixed that, but its length estimate turned case 0's `beq error_sound` into a long branch (4). Calling the same function through casts to different return types (`((int (*)(u32, u32, u32, void *))FadeStart)(...)`, `u16` likewise) makes the call RTL differ (`call` versus `call_value`) with identical code, which stops the cross-jump (0).

`__asm__("sym")` alias declarations inside the workflow markers are rejected by `wf.py apply`; the function-pointer cast form is plain C and folds to a direct `bl`.
