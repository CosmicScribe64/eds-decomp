## Matching tricks

- Text canvas access: keep it as `extern u8 gUnk_02000000[]` and index `[0x10000..0x10004]` for the header; `agbcc` then emits base + separate offset literal like the ROM. A struct view for the header would fold to one literal.
- `switch (size)` on a `s32` (from `sc >> 8` with a `u16 sc` parameter) gives the ROM's signed `bgt` in the compare tree; `u8 size` gives the same; `u32` gives `bhi`.
- Renderers: compute `p = (const u16 *)(idx * 8 + (u32)font)` (offset first, then the literal base) to get `lsl; ldr; add`; for the Latin renderer write `off`/`base` variables and add after the `switch` so the `add` is shared.
- Loops with a copy of the counter (`adds r7, r4, #0` after the zero test): in `TextDrawLatinGlyph` `n = size >> 1; if (n != 0) { cnt = n; do {...} while (--cnt != 0); }` reproduces it. The same trick fails for `TextDrawSjisGlyph` (the counter is merged with `size`).
- `(w >> 8) | ((w & 0xFF) << 8)` with a `u16 w` gives the ROM's byte-swap (`lsr; lsl 24; lsr 16; orr`); the `lsl 17; lsr 16` is `(u16)(sw << 1)`.
- Word-wrap renderers: use `s32 x0, y0` parameters copied to locals `x`, `y` (this orders the prologue moves like the ROM), do not use temporaries for `x + size` in the max-extent update (address is computed first in the ROM), and read the 7-bit gap as `(u32)b << 25 >> 25`.
- `size >> 1` used in a signed add must be `(s32)((u32)size >> 1)` to get `lsr` with a signed compare.
- `if (x <= 0x5E) return tbl[x]; return 0;` (not `> 0x5E` first) gives the ROM's block order for `AsciiToFullwidthSjis`.
- For `sub_08074868` and the cursor code `gUnk_081A73A0[idx].cb` written naturally reproduces the ROM (hoisting `table + 0x40` as a loop invariant); in the one non-loop use (`0x080749E8`) write `off = idx * 0x44; items += 0x40;` to get the separate `adds #0x40`.
- `struct Main *m = &gUnk_03000040; u8 *step = &m->unk4859;` (base and offset as two literals) again as in [[code-0807717c]].
- Direct `gUnk_03005B60.field` access gives `ldr base; ldr off; adds`, same as a pointer for a single access. Across blocks a pointer local is not equivalent: in `0x080740BC` it gave a base copy that PRE merged (see the wave 2 section).
- `0x08074A34`: the ROM's null-callback path falls straight into the epilogue with `r0` still holding the (zero) callback, so the source must *not* end with `return cb;`. Drop the trailing return and let the function fall off the end. An explicit final `return (u32)cb;` makes agbcc merge it with the shared `mov r0,#0` epilogue.
- `0x08074B74`/`0x08074BF8`: the ROM keeps `y & 7` and shifts it inside the loop; agbcc hoists the shifted value out. The permuter broke the tie with two source-level "register anchors": `s32 xl = ((short)x) & 7;` and a dummy `s32 *new_var;` used as `(*(new_var = &xt) + ...)` in the index (address-taking `xt` stops the allocator from folding it into the shifted temporary). Both `0x08074BF8` and the 16-px twin matched with the exact same two edits.
- `0x08074C80` (solved): the byte-swap is `u16 w = *p++; u16 sw = (w >> 8) | ((u8)w << 8);`. The `(u8)w << 8` form reproduces the ROM's `lsr; lsl 24; lsr 16; orr` and keeps `w` in r0, while the equivalent `(u8)(w >> 8) | (u16)(w << 8)` puts `w` in r1. The row counter copy comes from `n = size; if (n != 0) { i = n; do {...} while (--i != 0); }`, reusing the declared `s32 i`. A fresh `u32 cnt` gets merged back into `size`.

## Link receive and debug-menu input matched (wave 1, 2026-10-01)

Both match in ordinary C. Working notes: `build/wf/sub_08074260/NOTES.md`, `build/wf/sub_08074868/NOTES.md`.

### `sub_08074260` (0x144, start score 24)

- The old draft's buffer rotation was semantically wrong (`A34 = B08; B08 = A38; A38 = A34`); the target does `B08 = A38; A38 = A34; A34 = B08`. Fixing it raised the score (78), because `&A38` became a local pseudo.
- The loop's `0x03006598` literal is really `gUnk_03005B60 + 0xA38`, i.e. the original reads the struct member `unkA38` in the loop. That keeps the `&A38` pseudo live across blocks (global alloc puts it in r6, pushing `&B08` to r8), and reload rematerializes it from its REG_EQUIV constant in the loop (`ldr r3, =0x03006598`). Writing `(u8 *)gUnk_03005B60.unkA38 + AFC * 24` matched. All loop counters stay struct members (AFC, B00, B12, B08).
- An `asm("" :: "r"(&gUnk_03005B60.unkA38))` at the start of the if-block also matched and was what revealed the cause. Swap temporaries, an IME pointer local, and a u8/u32 flag local made no difference.

### `sub_08074868` (0x180, start score 30)

- Parts 1 (0x80/0x40 blocks), the 0x20 block and the L/R blocks use direct `gUnk_03000040.field` accesses; only the middle uses a local, `m = &gUnk_03000040; step = &m->unk4859;`. GCSE PRE treats the middle `&gUnk_03000040` pool load as redundant: it inserts a reaching register at the end of the first block (r4, used by part 1 and the 0x20 block) and turns the middle load into `m = reaching` (the `add r5, r4, #0` copy). Calls kill the pool-load availability, so the L/R part reloads (`ldr r4`).
- Test `m->newKeys & 1/2/0x10` directly instead of through a `u16 keys` local: CSE reuses one load, but the AND result lands in r0 (`and r0, r1`) as in the ROM; a keys local gives `and r1, r0`.
- 0x200 block: `if (x > 0x1E) x -= 0x1E; else x = 0;` on the field directly (a `u16 *p` local folded base+0x2150 into one pool constant).
- Failed: `m2 = m` copies (CSE always merges them), register pins r4/r5/r6 (70), `asm("" : "+r"(m2))` (46), u32/s32 keys (26). The old draft also read `*step` before assigning it.
- Debug with `old_agbcc -O2 -da`: the `*.gcse` dump shows "PRE: redundant insn ... reaching reg". See [[matching-tricks#Literal pools, symbols and address construction]].

## Wave 2 matches (2026-10-01)

Working notes: `build/wf/sub_080740BC/NOTES.md`.

### `sub_080740BC` (`LinkStep`, 0x11C, start score 56; ordinary C)

- The old draft used a local `s = &gUnk_03005B60` and hand-written masks (`byte & 0x88`, `u8 t = byte & 4`, `v & (u16)~0x40`). That gave a base copy (r1 to r5), PRE merged the post-if base load into r5, and the `~0x40` constant came from the pool.
- What matched: write it like the SDK source, with a `SioMultiCnt` bitfield struct (`baudRate:2, si:1, sd:1, id:2, error:1, enable:1, ..., ifEnable:1`, then `u16 data`) overlaid on `+0xB0C`:
  - `*(u32 *)&bak = *(vu32 *)&REG_SIOCNT; if (bak.sd == 1 && bak.enable == 0)`: fold_truthop merges the two bitfield tests into the ROM's `ldrb; and #0x88; cmp #8`, and `bak.si == 0` gives `and #4; lsl 24; lsr 24`.
  - `((volatile struct SioMultiCnt *)&REG_SIOCNT)->ifEnable = 0` gives `ldrb [r6,#1]; movs #0x41; negs; ands; strb` (a QImode bitfield store; the constant 0xBF sign-extends to -65).
  - Direct `gUnk_03005B60.field` accesses everywhere, and `unkA1E = 8` as a constant: after the `== 8` test CSE reuses the `& 0x88` result register (r4) for the store.
  - `B14 |= (A1E == 8) << 7; return B14;`: the separate return re-reads with `ldrh`; `return B14 |= ...` does not.
- Score went 56, 2, 0 in three compiles once the bitfield form was in. Failed: a const-int base `(struct LinkSio *)0x03005B60` (65; the `+0xB0C` address folds to one literal).
