## Matching tricks (old_agbcc)

- **Bitfield flags**: `flags->newline = 0` compiles to the `mov r7,#2; neg r7,r7; and` pattern (int -2 mask) seen in the target; a plain `u8 &= ~1` gives `movs r0,#254`. The `OamList.count:7` field likewise reproduces `lsl 25 / lsr 25` and the `& 0x7F` increment.
- **Struct copy with pointer post-increment**: `*d++ = *s++; *(u16 *)d = *(u16 *)s;` matches the `ldmia/stmia` + `ldrh` copy in `OamListFlush`, while assigning struct fields makes gcc hoist a `+0x14` base.
- **Local copy of a bitfield to block CSE**: `u32 n, m = l->count; if (m > 0x7F) return 0; n = l->count;` reproduces the target's separate unsigned compare (a bitfield compared with 0x7F is otherwise folded to a signed test).
- **`<< 5` instead of `* 32`** in `dst[(x + j & 0x1F) + ((y + i & 0x1F) << 5)]` fixes operand order of the final add (`FillTilemapRectWrap`).
- **Shadow text**: `(t1 = (t = n * (c >> 1)) + 1) + x` in the first call and `t + x` in the second stops gcc from reassociating `(1 + x)` and reproduces the exact registers of `DrawStringShadow` / `...JIS`.
- **Fields typed `u16` for compares**: `Line.acc` is `u16` and `dx/dy` `s16`; the compare `acc >= dy` then produces `ldrh` versus `ldsh` exactly as in the target.
- **Pass-through wrappers** (`DrawStringShadowAuto`) need the callee prototypes with the same narrow types, so caller-side narrowing matches.
- **A digit/character range check must be a `switch` with dense cases** (`case '0': ... case '9':`), which old_agbcc emits as the two-compare range test `cmp #hi; bgt; cmp #lo; blt` on the int value. A `||` of two compares folds into an unsigned `(c - lo) > hi-lo` test (`sub #lo; cmp #9; bhi`), and separate `if`s canonicalise the second bound to `cmp #lo-1; ble`. Same rule as `case 2: case 3:` in [[code-0806704c]].
- **Permuter register tricks** (`/* FAKEMATCH */`): a dead assignment keeps a computed value in the register the ROM used (`r = (t = v - '0') + s[1]` in `ParseDecimal2`); a dead `int addr = <first dst offset>` plus a `row2 = row` copy pins the address/value split in `PlotGlyphRow16`. Same idea as the `ret = zone = 1;` pattern in [[decomp-permuter]].
- **`*(volatile u8 *)s`** on a repeated byte read forces the ROM's extra `ldrb` when agbcc would otherwise CSE it (`TextFits`).
- **OAM list clear** (`0x0807A2EC`): initialise the byte loop counter before the `0xFF` fill value, then use an empty input barrier on each loaded head byte before the OR. Clearing the `count:7` bitfield supplies the target's negated mask instead of a folded `& 0x80`.
- **Signed field reloads** (`0x0807A398`): empty memory barriers after the direction stores and before subsequent comparisons force the target's field reloads. Passing each `s16` delta through an `int` temporary and an empty input barrier retains `ldrsh` for the negation. These barriers emit no instructions.

## `LZSSDecompress` (LZSS) matched (2026-10-01)

Three changes, all ordinary C ([[lzss-decompress]]):
1. The ring index `r`, match position `p` and byte `b` are `u16` locals (lossless: `r`/`p` are masked to 12 bits, and `b` holds a byte or the masked high nibble). The climber found these.
2. The declaration order is `r`, `i`, `p`, `b` (also from the climber).
3. The match length lives in the inner loop condition, `for (i = 0; i < b + 3; i++)`, with no `len` local. Loop-invariant hoisting then places `b + 3` after `i = 0`, as in the ROM (`movs r2,#0; adds r1,#3; mov ip,r1`).

## Ascending tile fill matched (wave 1, 2026-10-01)

`FillScreenblockRectAscending32` (0xD8, start score 38) and its sibling `FillVramMapRect32` in [[code-0807a6ac]] match in ordinary C with the same shape, each on the first try. Working notes: `build/wf/FillScreenblockRectAscending32/NOTES.md`.

- The target computes `(w<<24)>>25`, narrows it to u8 again, keeps `half<<24` spilled in `[sp]` and recomputes the inner bound per row. Earlier drafts used a `half` local, which agbcc kept in a register.
- What matched: **no `half` local**. Write `w / 2` inline in both the inner loop bound (`j < w / 2`) and the stride (`p += 0x10 - w / 2`), with `u8 i, j`. c-typeck shortens `u8 / 2` to an unsigned-char division, which is the redundant u8 narrowing. The rotated loop's two condition copies are hoisted differently, which produces the `[sp]` spill and the per-row reload.
- Failed earlier: `u8`/`s16` `half` locals, the explicit double-narrowing expression, explicit stride/next locals.
- This overturns the "explicit spills are difficult" entry for these two functions in [[matching-tricks]]: the spill came from the compiler's own loop-condition copies, not from register pressure.

## Wave 2 matches (2026-10-01)

Working notes: `build/wf/PutMapString/NOTES.md`, `build/wf/BitmapPlotRow8/NOTES.md`, `build/wf/OverlayBoldGlyphTile/NOTES.md`.

### `PutMapString` (`DrawTextLine`, 0xF4, start score 99; ordinary C)

- `u8 count` with `count < max`; the draft's u16 count lacked the ROM's `lsl 24; lsr 24`.
- Call `PutMapChar` through a cast with its real prototype (x is `u16`, as defined in [[code-080784e4]]). With the unit's u8 x, the `x & 0x1F` constants are QImode and the y ones HImode, so loop.c sees separate life-2/savings-2 constant movables that are "not desirable". With u16 x the constants merge into one movable that is hoisted, and the `y & 0x1F` chain follows it; `y - 1` stays in the loop (life 2, 13*2*2 < insn count). x then loses r7 to reload and is spilled, as in the ROM.
- `switch (*str) { case '\r': ...; case '\n': ... }` instead of the nested if. The switch index load is not the QImode `(set reg:QI (mem:QI))` form that cse_set_around_loop looks up, so the body reloads `*str` as the ROM does instead of reusing the duplicated exit test's load. Case order `\r` then `\n` gives the ROM's block order (`\n` first scored 13).
- Failed: `(u16)(y-1)`, `(y+0xFFFF)`, `% 32`, `31u`; an `int ty = y & 0x1F` temp (still gated by the constant movable); a function-level `int mask = 0x1F` (right hoist and x spill, but mask took r8, 94); a do/while plus `if` guard (36, the `count < max` test moves to the loop top).

### `BitmapPlotRow8` (`PlotGlyphRow8`, 0x104, start score 99; FAKEMATCH)

- The draft had `int buf[0xC]`; the ROM frame is 12 bytes with byte stores, so `u8 buf[0xC]`.
- The ROM keeps three separate values: `half` (r4, tied to the mul output), a per-case `row` that lives only until the loop, and `row2 = row` (a global pseudo in r4, evicted to sl by reload). It also copies `stride` into r0 before the switch and uses that copy only in mode 4; mode 8 multiplies by r2 directly.
- What matched: (1) the `row2 = row` copy in the for-init, `for (i = 0, row2 = row; ...)`, so it lands after `i = 0`; (2) a block-scoped `u32 row` in each case, a local-alloc pseudo in r4, which gives `half` a hard-register preference for r4 (84 to 15); (3) FAKEMATCH `st = ((u32)stride << 16) >> 16;` before `half = w >> 1`. GCSE cprop cannot see through the no-op shift pair, and combine later folds it into a plain copy (nonzero_bits), so the stride copy survives with only 2 refs (15 to 0).
- Failed: `asm("" : "+r"(st))` (the copy survives but gains refs, so st outranks half and takes r4, 15); plain `st = stride` or `stride & 0xFFFF` (propagated away, 11); an asm barrier on `stride` (22, stride moves to ip); one variable for half and row (84).

### `OverlayBoldGlyphTile` (`ExpandGlyph1bpp`, 0x1A0, start score 60; ordinary C)

- `u8 ix`: the draft's `s8 ix` gave `lsl/asr`, the ROM a plain `lsl #3`.
- Loop bound in sl: a plain `u16 n = 8;` declared before `ix = *idx`, with do/while loops ending `while (i < n)`. Once the other changes are in, it no longer folds to 8.
- `src = (u8 *)0x0822BB00 + ix * 8` (literal address) instead of `gFontLatin8x8Bold + ix * 8`: the shift lands in r0 and the table address in r1, which shifts the reload rotation for the r8/r9/ip constants (extern form: 10).
- Test `*src & mask` directly in every `if` instead of through a `b = *src` local. The ROM's `ands r0,r3` on the last test of each word needs the load to come from GCSE; with a local, the last test becomes `ands r3,r0`. Same mechanism as the key-callback tests in [[code-08051a9c]].

## Wave 3 matches (2026-10-01/02)

Working notes: `build/wf/PutMapNumber/NOTES.md`, `build/wf/BitmapDrawLatinGlyph/NOTES.md`.

### `PutMapNumber` (`DrawNumber`, 0x134, start score 130; ordinary C)

Each step measured:
1. Use the parameters directly (no `xx`/`yy` locals): 130 to 94.
2. `return` instead of `break` in the mode-1 loop (`if (d == 0 && num == 0) return;`): 94 to 59. With `break` the second loop was not rotated (no duplicated `cmp r5,r9; bcs` entry test).
3. Call `PutMapChar` through its real prototype (u16 x, as in `PutMapString` above): 59 to 52. With u8, `x & 0x1F` is narrowed in QImode and its 0x1F constant is a QI pseudo that CSE cannot share with `y & 0x1F` (SImode); the ROM loads 0x1F once for both.
4. The `num == 0` call written like the sibling `DrawNumberTiles` ([[code-080784e4]]): `x-- & 0x1F` then `return;`, with the loop after it rather than in an else: 52 to 0. The dead post-decrement keeps a copy of x (the ROM's `mov r2, r8` in the prologue).

### `BitmapDrawLatinGlyph` (`DrawGlyphASCII`, 0x140, start score 164; FAKEMATCH)

1. A block-local `u32 t` in each loop instead of one function-scope `t` (a global pseudo in r5): local-alloc gives `t` r4, and the `y++` copy is spilled to `[sp+0x1C]`/`[sp+0x20]` (164 to 78).
2. Loop forms `for (i = 0; i < 4; i++)` and `mode >>= 1; for (i = 0; i < mode; i++)`: loop.c reverses both into the ROM's `i = 3 .. bge` and `i = n .. bne` (78 to 74; e moves to r8).
3. Global-alloc order: the ROM has e = r8, w = r9, i = sl, but the measured priorities were e 0.2596, i 0.2593, w 0.2547, so i came before w. FAKEMATCH `asm("" : : "r"(e), "r"(w));` adds one ref to each and puts e and w ahead of i (74 to 58).
4. Integer font bases, `(u16 *)(0x08228D00 + ch * 8)` and so on, instead of the `gUnk_` symbols: the const_int stays inside the add, so reload loads each base into the rotating spill register (r1 in the 8 path, r1 in case 10, r5 in case 12). This also stops the case 10/12 `add r6,r0,r1` tails from cross-jumping (4 bytes) and aligns the later reload rotation (58 to 0).
- Failed: without the asm every loop-form combination scored 22 or more; per-loop `j` (32); u32/u8/u16 counters; `register int i asm("r10")` (worse, it disables loop reversal); `i < mode >> 1`; `mode / 2`; `i = 0` before the switch; entry-initialised base-pointer locals (102).
- Tooling: on macOS, Docker sometimes compiled a stale or truncated `unit.c` right after a rewrite, which gave wrong scores and false "does not compile" results. The work directory's `try.sh` waits until the container's md5 of `unit.c` matches the host's. See [[agent-tooling]].
