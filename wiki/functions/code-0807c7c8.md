# code_0807C7C8: Password scene steps and Card Trading scene (`0x0807C7C8`-`0x0807D3D0`)

`src/code_0807C7C8.c` (21 functions, 0xC08 bytes). **19 / 21 are C and byte-matching** (`0xA38` bytes); 2 stay `INCLUDE_ASM` (`sub_0807CCAC`, `sub_0807D1F4`, `0x1D0` bytes total), each with its best attempt under `#if 0 /* NONMATCHING */` (register-allocation-only). The unit links to the exact target bytes. Compiler `old_agbcc -O2`. Follows [[code-0807b6b8]] (link menu, `FindCardByPassword`); this is the last game-code unit before the sound driver ([[sound-engine]]). Names are proposals; the code keeps `sub_08XXXXXX`.

Both scenes are *step machines*. The scene callback (`0x0807CC28` Password, `0x0807D348` Card Trading) reads `gMain.step` (`0x03004899`, byte at `0x03000040 + 0x4859`), calls `table[step]()`, and when the step returns non-zero does `step++; sub = 0; sub2 = 0`. A null table entry ends the scene (callback returns 1). See [[program-flow]].

## Structures

- `PwState @0x0201F780` (size 0x28, cleared by `0x0807CDA0`): `u16 code` (+0, card trade id / password index), a `u16` at +2 with bitfields `a:1`, `b:1` (selected row / side, used as a 2-bit value `ab` in `CFA8`), `c:7` (bits 2-8, animation frame), `d:4` (bits 9-12, tab slide counter); +0x10 link sync block (`LinkSync` of [[code-0807b6b8]], rx entry at +0x14, peer data `u16` at +0x16), `u16 timer` (+0x1E), `u16 card` (+0x20), `u8 unk22` (player id, set to 0x50 by `CB_CardTrading`).
- `LinkState @0x0201F7B0` (size 0x18): `u8 digits[8]` (+0), `u8 pw[8]` (+8), then a bit-packed `u32` at +0x10: `slot:4, cursor:4, a:6, b:6` and `u16 c:12` at +0x12 (bits 4-15), `u16 card` (+0x14 the matched card id from `FindCardByPassword`). This refines the `LinkState` of [[code-0807b6b8]] (its `cur` byte is `slot|cursor<<4`).
- `gMain` (`0x03000040`) fields used: `+0x06 keyNew`, `+0x40E u16`, `+0x414 u32`, `+0x85C u16[0x60]` (tilemap copy), `+0x442C u16` (BG scroll shadow), `+0x4859 step`, `+0x485A sub`, `+0x485B sub2`, `+0x4872 u16`, `+0x4874` low 2 bits.
- Save mirror `0x02011C20`: per-card 4-byte records starting at `+0x8`; byte `+0xA` bit 1 = card owned/unlocked flag (`flag1`), set by the password reveal step.
- Tables: `gUnk_08622AB4` (u16[0x800], maps card id to trade code), `gUnk_08623DF4` (u16, maps peer code to card), `gUnk_0822C720` (card names, 64 bytes each), `gUnk_08087E88` (u32 scroll values), `gUnk_08087F08` (4-byte sprite attr entries).

## Matching tricks learned (old_agbcc)

- **Reference the global directly, not through a local pointer.** `struct LinkState *s = &gUnk_0201F7B0; ... s->c` produces a hoisted pointer register that never matches; writing `gUnk_0201F7B0.c` everywhere lets gcc/GCSE choose the same copies and reloads as the target (`0x0807C924`, `0x0807CAA0`, `0x0807CB74`, `0x0807C7C8` second half).
- **Nested-if form for a range test with early return 1.** `if (c <= 0x12B) { ... if (!(keyNew & 8)) { c++; return 0; } } return 1;` matched where `if (c > 0x12B) return 1;` did not (copy `adds r0,r1,#0` vs reload).
- **Pointer operand order.** In `base[i]` address arithmetic gcc puts a *pointer* register first in `add`; the target's `adds r4, r5(i), r6(base)` is reproduced by `u32 base; *(u8 *)(i + base) = ...`.
- **`x % 10` stays as a `bl __modsi3`** but the address of the store is computed between `rand()` and the libcall only when written with `%`, not with an explicit `__modsi3(...)` call.
- **Two bitfields as one value.** The single `and #3; cmp #3` in `CFA8` needs a second struct view (`struct PwPair {u16 pad; u16 ab:2;}`) cast from the same local pointer; a second `extern ... asm("sym")` view loads a separate literal.
- **u16 bitfield `+1` with a 7-bit mask** (`c`, bits 2-8 of a halfword) compiles to `lsr/add/and 0x7F/lsl 2/and 0xFFFFFE03/orr`; it needs `struct` fields declared `u16 x:n`, and byte-aligned fields inside the same struct are read with `ldrb`.
- `if (fn) { if (fn()) {...} return 0; } return 1;` (table callback) matches; the inverted `if (!fn) return 1;` does not.
- `for (i = 0; i < rows; i++)` with `i` unused in the body gives the count-down `sub; cmp #0; bne` loop of `LoadTileBlock`.

## Nonmatching notes

- `0x0807CCAC`: the two loops and every constant match; target uses `r3`/`r5` temps for `limit = 1` / `a = 0` and keeps `0x100`/`0x2000` in registers before `orr` (13 variants tried).
- Historical `0x0807CDB4` blocker (resolved): len/font-width/half-width used r6/r4/r5 instead of target r4/r5/r6. A new horizontal extent and explicit first X coordinate now match in ordinary C; see below.
- `0x0807D1F4`: target loads the table base after the index math (`ldr r3` vs built `r2`) and copies the peer value into a second register for the `- 0x7D0` arm; built copies the other way round.

## Trading-video initializer accepted

`sub_0807CDB4` (**`0x1B8` bytes**) is accepted in ordinary C, with **no register bindings or empty assembly constraints**. The whole `0xC08`-byte unit is **MATCH**, actual **19/21 C (`0xA38` bytes)** and two assembly fallbacks (`0x1D0`). Logs: `build/decomp_large/trade-accepted-check.log`; private exact source `build/decomp_large/game-batch/sub_0807CDB4/coord-x-first/source.c`.

The first scout draft misses 19 operand and scheduling bytes at the correct size. Retain the string length for the font-choice comparison and derive a new initialized **`extent = (len * w) >> 1`** instead of mutating len. This restores len/width/half-width's target allocation and reduces the miss to six bytes. See [[matching-tricks]] for the earlier `sub_0805F00C` derived-extent example. Then compute the real first text-coordinate local **`x = 0x78 - extent` before `half = w >> 1`**, and pass x to the first draw. That places the half-width shift after the X subtraction, matching the final scheduling difference.

An explicit initialized first Y coordinate also matches, as does assigning the half-width inside the first call's Y argument; the simpler x-first form was accepted. Width/half signedness and declaration-order variants alone do not fix the routine. Initialized register/dependency hints were worse and were rejected. Every new local is assigned before use; the IRQ/MMIO sequence, both fresh card-name reads, text drawing ABI, tilemap stores and return value are unchanged. ROM review and strict whole-unit byte checks cover the accepted body; no finite behavioral test was used as a substitute for those checks.

Bounded scripts: `build/decomp_large/trade_shapes.py` and `trade_coordinates.py`. Four ordinary variants independently produced complete-unit MATCH. The old `0xB4+` size in the table was a placeholder; ROM range `0x0807CDB4`–`0x0807CF6C` proves the exact `0x1B8` size.
