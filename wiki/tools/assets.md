# Asset extraction and the data build

The repository holds no game data. `make setup` (`tools/setup.py`) finds the user's ROM in `roms/`, checks its SHA-1 and extracts every non-code byte into `assets/`, which is gitignored. The build then reads `assets/` instead of the ROM.

## Pieces
- `config/assets.tsv` lists 54 assets: start and end address, type, output path and options. Every byte of both data units (`0x08080A20`–`0x08087FB4` and `0x08087FD0`–`0x08800000`) belongs to exactly one asset, and the cartridge header (`0x08000004`–`0x080000C0`) is one more. `tools/assets.py check` verifies the coverage.
- `tools/assets.py extract` converts each range. Before writing a converted file it builds the bytes back and compares them with the ROM, and writes a raw `.bin` instead if they differ (listed in `assets/fallback.txt`). After a normal extraction that list is empty.
- `tools/assets.py build` (run by the Makefile when any file in `assets/` changes) writes `build/assets/<path>.bin`. `data/rodata_*.s` are generated by `tools/assets.py gen-data` and `.incbin` those files, split at the labels the code refers to. `asm/crt0.s` takes the header from `build/assets/header.bin`.
- `tools/assets.py verify` builds every asset and compares it with the ROM.

## Formats
| Type | Output | Notes |
|---|---|---|
| `strings` | JSON list | Card names (821 × 0x40) and descriptions (821 × 0x1E0). A record whose bytes after the NUL aren't zero is kept as `{"text", "raw_tail"}` |
| `dialogue`, `duelists` | JSON list | [[text-system]], [[duelist-table]] |
| `card_stats` | CSV | Raw bitfields `def atk kind type level attr`, as in [[card-table]]. The name column is for reading only |
| `card_art` | 821 PNGs | 72×80, 64-colour indexed. The unpacking follows [[card-art]] |
| `font1bpp` | PNG sheet | [[font]]. Kanji sheets have one Shift-JIS lead byte (192 glyphs) per row |
| `palette` | JASC-PAL | |
| `tiles4bpp` | PNG sheet | Viewed with the palette named in the manifest |
| `u16` | JSON list | Card ID maps ([[card-id-map]]) |
| `zero` | none | Padding, checked to be zero |
| `bin` | `.bin` | Sound, scene graphics, image packs and tables whose formats aren't documented yet |

Text uses Windows-1252, with Latin-1 for the five undefined bytes, so every byte value maps to one character and back.

**Palette bit 15.** The hardware ignores bit 15 of a BGR555 colour, but 820 of the 821 card palettes and the system palette set it on some entries, with no visible pattern. PNG and JASC palettes can't hold it, so it goes into sidecar files (`cards/art/palette_bit15.json`, `gfx/system.pal.bit15.json`) that list the affected indices.

## Verification (2026-10-01)
- `verify`: 54/54 assets build back to the ROM bytes, with no fallbacks.
- A fresh copy of the repository with only a zipped ROM in `roms/` ran `make setup` and then `make compare` (`eds.gba: OK`, about 14 s). With the ROM deleted afterwards, a clean build still matched.
- Renaming card 1 in `names.json` changed the built ROM, so edits reach the build.
- Card art rendered correctly for slots 1 (7 Colored Fish) and 100 (Castle of Dark Illusions).

## Next formats
Sound (PCM samples to WAV, songs and SE tracks), image packs and LZSS scene sets ([[graphics-formats]], [[lzss-decompress]]) and the remaining tables. Each new converter has to round-trip exactly; extraction falls back to `.bin` automatically if it doesn't.
